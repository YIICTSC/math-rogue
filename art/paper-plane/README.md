# 紙飛行機バトル：Blender製の機体・換装パーツ

## 組み込み

- `src/components/PaperPlaneFleet3D.tsx` が戦闘背景と格納庫プレビューを描画。
- `public/models/paper-plane/fleet.glb` は約1 MBの共有メッシュライブラリー。
- 自機はチラシ号・テスト用紙号・画用紙号の3種。敵機は偵察・爆撃・迎撃・要塞の4シルエットを、既存36種類の敵名に応じた形状・色で使用する。
- 砲台3種、ミサイル2種、シールド3種、エンジン3種、増幅器3種の14メッシュを共有する。既存207種類のモジュールと初期装備は、種類・名前・スロット数・必要エネルギー・特殊効果に応じて形状と配色を決める。207個の専用形状を個別制作したものではない。
- 3×3のスロット順を保持する。敵機は左向きなので、モデルのローカル座標の列と行を反転してから配置する。画面左列が機首側、右列が尾部側になる。
- `+`の強化装備は金色のアクセントと少し大きい形状。空きスロットは部品を描画しない。
- カード装填やHP変更ではメッシュを再生成せず、装備の構成変更だけで差し替える。
- セーブの `player.airframe` と `enemy.airframe` に外観の識別子を保持。既存セーブでは識別子が省略可能で、標準機体で表示する。装備配列、戦闘計算、学習問題の処理は維持。
- WebGL初期化失敗、モデル読込失敗、コンテキスト喪失時は矢印表示へフォールバック。操作UIは継続して利用できる。

## 編集・再生成

リポジトリのルートで実行する。

```powershell
node scripts/export-paper-plane-catalog.mjs
& '..\tools\blender\blender-4.5.11-windows-x64\blender.exe' --background --python scripts/blender/build-paper-plane.py
node scripts/test-paper-plane-models.mjs
pnpm run build
```

`paper-plane.blend` は編集用のモデル一覧。生成スクリプトは折り紙の独自メッシュ、厚み、面取り、部品、材質、照明、GLB出力を再現する。GLBでは全機体・部品の原点を揃え、Three.jsで組み立てる。

`perspective.png`、`front.png`、`back.png`、`top.png` は組み立てた自機のBlender確認用画像。ゲーム配信先の `public` には入れない。

## 検証

- 全カタログおよび強化装備がGLB内の有効なメッシュを参照すること、頂点範囲、容量、カード装填時のモデル構成維持を自動チェック。
- 敵機の前後・上下について、180度回転後も戦闘盤面の列・行と対応することを回帰テスト。
- Chromium / SwiftShaderでPC（1280×800）・スマホ相当（390×844）の戦闘と格納庫を表示し、画像で確認。格納庫の実際のクリックによる装備交換・保存・コンテキスト喪失時の代替表示を検証。
- 英語UI監査を含むプロダクションビルドを実行。
- プロジェクト全体の型チェックは既存の467件のエラーが残る。新設した3D表示コードの型エラーはない。

実機スマートフォンでのGPU性能評価は未実施。描画は最大30fps、DPR上限1.5、画面が非表示の間は停止する。
