## 設計の結論

小3〜中3を中心に、既存教科を到達目標ごとに分ける75単元、生活場面へ再設計する15単元、教科融合の10単元を設計する。高1への接続を含むものは問題文に必要な関係式を示す。

すでに基本教科・高校分野・実生活分野が広く実装されているため、これら100件を「未収録の知識100分野」とは数えない。選びやすく、つまずきを特定しやすい100の学習スキル・応用演習の候補である。既存問題の移設と新規作問による問題数の純増は別に集計する。

## 重複を増やさないための分類

| 種別 | 件数 | 採用条件 | 集計方法 |
| --- | ---: | --- | --- |
| 細分化 | 75 | 既存の大単元から、1つの誤解を診断できる学習目標を分離する | 親の問題をコピーして別単元の新規問題数に加算しない |
| 生活場面への再設計 | 15 | 年齢・前提知識・生活の制約が元の高校向け内容等と異なる | 知識の再掲だけなら既存単元の演習に統合する |
| 教科融合 | 10 | 2つ以上の技能を使わないと解けない | 教科別問題の単なるランダム混合は融合として数えない |

同じ数値・表現の問題を複数単元から参照する場合は、問題の正本を1つにし、参照先を複数持たせる。既存の子単元で同じ学習目標を十分に扱っていた場合は、そちらを拡充し、候補を独立追加しない。独立追加数はこのレビュー後に確定する。

特に注意する境界：

- M01とM02は計算が同じでも、余りを切り上げるか残すかという場面判断が違う。
- M11・M12・M13は順方向の割合、逆算、基準が変わる連続変化を分ける。
- S01とS07は同じ条件制御の原理を使う。別単元としての価値が薄い場合は、共通スキル＋植物／電磁石の場面タグへ統合する。
- L09とL10は認証情報の保護と通知の真偽確認を分ける。一般的な「気を付けよう」の問題は両方へ水増し登録しない。
- C08とX08は最多票と過半数を共有する。X08は数値だけでなく「主張と根拠の組合せ」まで正しく選ぶ設問にする。
- 英語圏カリキュラムの既存単元を日本式英語へ機械翻訳して新規計上しない。今回の英語15候補は日本語話者向けの学習目標として設計した。

## 学習体験と一覧の構造

表示は「教科 → 親単元 → 学習スキル → 難易度」を基本とする。例は「算数 → 割合 → もとの値段を求める → 基礎／標準／応用」。難易度と出題形式ごとに単元名を増やさない。

生活場面・教科融合は、主教科の技能単元に接続し、「買い物」「防災」「旅行」等の場面タグで横断検索できるようにする。`units.json` の `primaryCategory` は既存カテゴリを使う配置案で、現行UIへ登録済みという意味ではない。複数の入口から選んでも同じ設計IDを参照する。

- 基礎：見るべき条件を明示し、1つの判断・計算を問う。
- 標準：必要な条件を自分で選び、1〜2段階で解く。
- 応用：不要情報・例外・誤った主張を含め、理由も選ぶ。
- 復習：誤答の理由に応じて、前提となる技能へ戻す。

正誤だけでなく、誤答に付けた「基準量を逆にした」「条件を落とした」等を診断タグとして蓄積する設計とする。単元完了は単純な問題数だけで決めず、複数の問題型・別セッションでの安定を確認する。具体的なしきい値は試行データで調整する。

## 作問・単元ノートの受入条件

各候補の問題例1問は、出題の方向と誤答理由を示す設計原稿である。この1問の数値だけを変えて50問にしない。

| 項目 | 基準 |
| --- | --- |
| 目標問題数 | 1単元50問。基礎20・標準20・応用10を目安にする |
| 内容の広さ | 少なくとも10種類の設問骨格。場面・表現・問う向きを変え、同じ答えの暗記に依存させない |
| 既存問の再利用 | 学習目標が一致し、権利・正確さ・学年表記を確認した問題のみ。再利用数と新規数を分ける |
| 問題の形式 | 初期は現行の選択式に合わせ、正解1つ・意味のある誤答3つ。自由記述の自動採点は別課題とする |
| 誤答の品質 | 3つの選択肢に異なる誤解を割り当てる。表記だけ違う同値選択肢、意味のない語、正解と同じ内容を避ける |
| 正解の一意性 | 別解・別の自然な英語表現・与件不足がないか、人のレビューを通す |
| 解説 | 使う条件、根拠、計算・判断の手順、典型的な誤りとの違いを説明する |
| 単元ノート | 専用のめあて、2〜3点の板書、よくあるミス、短い例を作り、既存の板書仕様へ接続する |
| 学年と表記 | 学習指導要領・既習事項・漢字／語彙・文量を確認する。設計文をそのまま低学年へ表示しない |
| 情報の鮮度 | 料金・換算率・統計・契約条件は与件か出典日を明示。現実の最新値と混同させない |
| 重複 | 問題文だけでなく、正答・条件・解法・誤答理由の同一性も照合する |

理科の実験操作は学校の指導下を前提にし、問題を家庭で実施する手順書にしない。防災・健康・法律分野は架空の条件読解を中心とし、個人の診断・投薬量計算・状況を問わない避難指示を問題化しない。確実な一般原則と個別条件を分ける。

## 図表・音声・入力への対応

現行 `GeneralProblem` にある `question`、`answer`、`options`、`passage`、`unitLabel`、`hint`、`visual`、`audioPrompt`、`speechPrompt` を確認した。設計例はまず選択式に対応させる。

- M07・M08：図形の寸法図。計算に必要な寸法を全て示す。
- M19：縦軸を省略した棒グラフと元の数値を同時に提示。
- E01：音の違いが学習目標なので、発音資料または明示的な発音注記を用意する。例のhourはhを発音しないことをノートでも説明する。
- E03・S06・S08・S09・S12・S14：位置図・回路図・模式図・記録図を用意する。本文だけの原稿を図表問題の実装完了と見なさない。
- C01・C02・C03・X02：縮尺・凡例・単位・通行条件を欠かさない地図／表を用意する。
- L07・L13・L14・L15・X05・X09・X10：表示や要項を `passage` として提示し、条件の引用箇所を説明できるようにする。

既存 `visual` の型で表せない図は、実装時に対応する型・描画処理・代替説明を追加する必要がある。新しい図表がすべて現状のまま表示できるという前提は置かない。音声が使えない環境では同じ技能を評価できる代替を用意し、発音の評価と読解の評価を混ぜない。

自由入力は、分数・単位・全角半角・同値表現・許容される英作文等の採点仕様を別途設計してから追加する。最初の25単元に必須の新機能にはしない。

## 実装への引き渡し

`EXP_M01` 等は設計上の安定IDで、現在の `GameMode` や本番モードIDではない。今回のJSONをゲームへそのまま読み込ませる変更はしていない。

実装時は、単元の正本となるメタデータを一か所に置くことを推奨する。現在、算数・国語の単元定義が `ModeSelectionScreen.tsx` と `ProblemChallengeScreen.tsx` に分散しているため、新規100件を両画面へ別々に手入力する運用は避けたい。新レジストリは例えば `src/data/problemUnits.ts` とし、配置案・親子関係・前提・学年・難易度・対応問題の参照を持たせる。このパスは提案であり未作成。

移行時の順序：

1. 設計IDを確定し、既存モードと学習目標・既存問題を照合する。
2. 本番ID／互換マッピングと問題の正本IDを定義する。既存の `sourceMode` や単元モードの仕組みを踏まえてルーティングを確認する。
3. 問題・誤答理由・専用ノートを作成し、教育内容レビューを実施する。
4. 単元選択、出題画面、問題ミックス、日課、週間学習、ミニゲームの問題選択へ同じ定義を接続する。
5. 日本語・ひらがな・英語UIの扱いを確認する。既存の単元名表示方針を維持し、英語圏版は別のカリキュラムとして判断する。
6. 保存済みの親単元ID・モードIDを引き続き読めることを確認する。過去の親の正解数を根拠なく子へ按分しない。
7. 各期の25件が正しく選択・出題・採点・復習・保存されることを確認して公開する。

親単元を分解しても、親からの総合練習は残す。既存の学習履歴は保持し、新しい子単元の到達度は対応する回答がある場合のみ更新する。50問補充処理があるため、不足を自動生成だけで埋めて合格にするのではなく、実際に表示される問題の品質を確認する。

## 今回の確認と残る判断

今回確認したもの：100件のID一意性、領域別・期別件数、登録名の正規化完全一致、参照モードの存在、設計内の前提IDの存在と実装期、各例の4選択肢の文字列上の一意性、相互リンク。これは教育内容の正しさや意味重複を自動で保証するものではない。

実装前に確定するもの：既存問題との全件照合、候補を独立させるか演習タグに統合するか、正式な学年配当、図表の仕様、各単元50問の原稿、保存と集計の互換マッピング。最初の作業単位は第1期の25候補とする。
