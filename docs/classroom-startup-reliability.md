# 教室での同時起動対策（2026-10-20）

対象は `https://learning-rogue.yishigeict.chatgpt.site/`、Windows / Edge。
指定サイトのHTTP応答には `x-learning-rogue-host: chatgpt-sites` とGitHub Pagesの配信ヘッダーがあり、本体の配信元を中継している。今回の変更対象は本リポジトリのゲーム本体。

## 起動進捗と自動継続（2026-10-20追補）

- HTMLだけで表示できるシンプルな起動画面を最初から表示する。ゲーム本体やCSSの取得が遅くても画面を維持する。
- ビルド時に、起動用エントリーとAppの静的依存JS/CSSだけを収集し、各ファイルのバイト数をHTMLへ埋め込む。未選択の問題集・ミニゲーム・大量の追加素材は起動待ちの対象にしない。
- 同時取得は最大3ファイル。実際に受信した展開後バイト数と完了ファイル数を表示する。ゲージの0〜95%は受信量、残りはスタイル適用・ゲーム初期化で、初期描画が完了してから100%にする。
- ネットワーク・HTTP取得エラーと通信停止は、待機時間をずらして自動再試行する。取得済みの正常なファイル、セーブ、招待URLを維持し、文書の再読み込みは行わない。エラー応答がHTTPキャッシュに残った場合も、次の試行で再取得する。
- 公開更新で古いJS/CSSが404になった場合、最新HTMLの起動構成を読み直して新しいファイルへ切り替える。ページ遷移やセーブ削除は行わない。
- 起動中の「読み込み失敗」「再読み込み」画面・ボタンを廃止。Reactの待機用要素が出ただけではロード完了と扱わず、Appの初期描画完了通知で閉じる。
- 完了済みファイルは起動用キャッシュへ保存する。保存容量がない端末でもHTTP取得を継続し、キャッシュAPIの応答待ちは2秒で切り上げる。起動に永続ストレージを必須としない。Electronのfile URLはXMLHttpRequestで読み込む。
- 初回起動に必要なファイルが未保存のまま完全にオフラインの場合は、接続回復を待って続行する。実装上の恒久的な実行エラーが通信再試行で直ることを保証するものではなく、原因は開発者コンソールへ残す。

下記「実装」の最大3回という制限はService Worker内部の1回の取得要求に対する制限。起動ローダーはそれで打ち切らず、読み込みを続行する。起動画面・手動再読み込みに関する旧記述は本追補を優先する。

## 実装

- 20秒経過は通信失敗ではなく待機表示にする。エラーで文書全体を自動再読み込みしない。
- 手動再読み込みでもキャッシュ・セーブ・招待URLを保持する。
- 約65 KB（gzip）の小さな起動用JavaScriptで待機画面を先に表示する。
- 問題画面、問題データ、ミニゲーム、デバッグ画面は必要になってから読み込む。汎用問題集内部の単元別分割までは今回行っていない。
- Service Workerは一時的なJS/CSS取得エラーだけを最大3回まで、待ち時間をずらして再試行する。404や永続エラーを無限再試行しない。
- 同じ端末内の同一URLへの取得をまとめる。異なる30台のブラウザ間でキャッシュを共有する仕組みではない。
- 保存済みHTMLがある場合、ネットワーク待ちが3秒を超えたら保存済み画面を利用し、更新は裏で続ける。
- 初回の起動用JS/CSSも保存し、直前のランタイムキャッシュと現在のテーマ素材キャッシュv3を保持する。旧Workerのv4指定により、実際のv3素材保存が削除される不整合も修正。
- ゴルフの回答後の「次へ」ボタンを削除。既存の850ms後の自動進行、一時停止、重複送信防止を維持する。

## 通信量の計測

以前の公開版の起動JavaScriptは24,521,564 bytes、ローカルgzip換算で5,999,150 bytes。
修正後の起動からタイトルまでに必要なJavaScript合計は10,869,068 bytes、gzip換算で3,153,663 bytes（約47.4%削減）。
初期の待機画面だけなら203,233 bytes、gzip換算65,206 bytes。
数値はJavaScriptのみ。HTML、CSS、画像、音声、通信ヘッダーなどを含む総転送量ではない。

## 検証

- `pnpm run build`：型検査・英語UI・表示文言監査・本番ビルド。
- `node scripts/verify-web-startup-budget.mjs`：初期読み込みの依存関係と容量制限。
- `node scripts/test-startup-service-worker.mjs`：キャッシュ無効/満杯、キャッシュ保持、再試行上限、30件の重複取得、保存済みHTMLへの切り替え。
- `node scripts/test-startup-recovery-browser.mjs`：20秒以上の待機と本当の失敗の区別、セーブ・キャッシュ・招待URL保持、30個の独立したブラウザコンテキストで再読み込み連鎖が起きないこと。
- `node scripts/test-classroom-web-build.mjs`：配信側を合計5Mbpsに制限した本番ビルドの起動、JSの一時的503からの復旧、オフライン再起動、算数/汎用問題画面の後読み込み。
- `node scripts/test-golf-quiz-autoadvance.mjs`：正誤回答後の自動進行、次ボタンなし、重複防止、一時停止/再開。
- `pnpm run test:golf`、`node scripts/test-session-results.mjs`：既存ゲーム処理、オンライン結果、キーボード操作の回帰確認。

ブラウザテストはMac上のChromium系ブラウザ。Windows / Edge実機30台と学校アクセスポイントの検証を置き換えるものではない。
5Mbpsは150Mbpsを30台で均等に分けた条件の近似で、実際の無線品質や他の校内通信は再現していない。

## 学校での確認手順

1. 同じEdgeプロファイルで新しい版を一度開き、使用する問題画面を表示しておく。
2. 授業では30台で起動し、失敗表示の人数・起動までの時間・自動的に再読み込みする端末が残るかを確認する。
3. 初回と2回目を比較する。教科・単元、時刻、端末、失敗時の文言を記録する。
4. 必要な場合だけ設定の「通信」から対象編の素材を事前保存する。授業開始時に全員が大量の素材を保存し始めないようにする。
