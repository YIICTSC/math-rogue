# スポーツモード追加4競技

スポーツクラブに、野球・サッカー・バレーボール・大運動会を追加した。
新4競技は1人対CPU、CPU観戦から試合終了・成績保存・再挑戦まで進められる。野球には用途別の打撃・投球・守備・本塁打ドリルもある。
依頼書の全細目を実装済みとするものではない。残っている項目は末尾に記載する。
通常モード・デバッグモードとも全8競技を選択・起動できる。

## 流用した既存機能

- SportsHubの入口、既存4競技のタイトル・招待機能を維持。新4競技は遅延ロードする独立ルート。
- `ProtagonistModel`、主人公カタログ、スポーツ衣装と既存のスケルトン・基本クリップ。既存GLBは上書きしていない。
- `useGameplayGamepad`、学習範囲・配信課題の選択、問題生成、QuizPanel、正解ポイントと学習記録。
- audioServiceの音量・ミュート・音声解放・iOSオーディオ復帰処理。

## オンライン対戦

既存競技と同じ「タイトル → 部屋を作る／招待に参加 → 学習範囲 → 集合 → 準備完了 → 試合」の流れで遊べる。
スポーツ総合の招待入口からも競技・参加名・6桁コードで参加でき、招待URLも発行する。
新4競技のオンラインも通常モードで利用できる。ホストが部屋作成時に単元を選び、集合画面に共通の学習範囲を表示する。集合中には出題しない。

| 競技 | 人数と担当 |
| --- | --- |
| 野球 | 2〜18人、各チーム最大9人。打席ごとにチーム内の担当者を交代し、相手側の担当者が投球・守備を操作。4人以上のチーム対戦も可能。待機中は手番を表示する。 |
| サッカー | 2〜22人、最大11対11。参加者ごとに別の選手を操作。空いた選手はCPUが担当し、他人の選手を奪わずに操作対象を切り替えられる。 |
| バレーボール | 2〜12人、最大6対6。個別の移動・サーブ・レシーブ・トス・スパイク・ブロック入力。空き枠はCPU。 |
| 大運動会 | 2〜8人、4チーム各2人。全種目で8選手が参加し、空き枠はCPU。走る種目は両選手の完走を待ってチーム順位を決め、屋上バトルはチーム単位で勝敗を判定する。 |

ホストは募集人数・試合設定を変更でき、参加者はチームを選べる。2チーム以上、2人以上、全員準備完了で開始する。
試合開始後とイニング・前後半・セット・種目の区切りに各自3問を出題する。ホストが選択単元から各参加者の問題を生成・採点し、本人の現在の1問だけを送る。回答後にのみ正解を公開する。全員が終了するまで試合時間を止め、回答履歴・正解ポイントは各端末へ一度だけ記録する。単元変更は集合中のホストのみ可能で、全員の準備状態を解除する。通信プロトコルはv2。

通信は既存テニス等のホスト方式と同じPeerJS／WebRTC。ホストが60Hzで試合を進め、全参加者へ状態を配信し、各端末で描画を補間する。
既存の `VITE_RPG_PEER_*` と `VITE_TENNIS_ICE_SERVERS`（未指定時 `VITE_GOLF_ICE_SERVERS`）設定を使う。
ホストの接続が必要で、専用サーバー方式のボタンは設けていない。
各端末は読み込み完了がホストに確認されるまで通知を再送し、全員の3D読み込み完了を待って時間を進める。初回モデル読込中は通信の応答待ちを90秒、プレイ中は15秒とし、ホストのバックグラウンド移行・一時停止を共有する。
入力の期限切れ・切断で移動を止め、退出した参加者の枠はCPUに戻す。途中参加は受け付けず、再戦は集合画面から準備し直す。
ホスト退出時は切断を案内する。ホスト移譲・試合途中への再接続は未対応。

## 新規素材・構成

Blenderで独自制作したGLBを `public/models/academy-sports/` に配置した。
球場、サッカースタジアム、体育館、街中コース、障害物8部屋、ターゲット会場、屋上、表彰会場、用具バンクの9ファイル。
用具には3種のボール、バット、グローブ、ヘルメット、捕手防具、競技別ジャージ、膝当て、障害物、アイテム、トロフィーを含む。
競技場には立体的な設備・観客席・看板・照明・建物を配置。スコアボード、ネット変形、軌跡、選手マーカー、紙吹雪は実行時に描画する。

専用動作は既存リグへの競技別ボーン姿勢として追加した。投球・打撃・捕球・送球、キック・タックル、サーブ・レシーブ・トス・スパイク・ブロック、パンチ・キック・ガード・リアクションに対応する。
参考作品のキャラクター・音源・名称・モデルは使用していない。

32種類のオリジナル合成効果音をMP3とOpusの2形式で制作した。GLBと合わせて約11.6 MiB。
出典・ハッシュ・サイズは `assets/academy-sports/{asset-build,sound-build}.json`。
Web/Androidのアセット一覧に登録済み。ボイスの新規生成は行っていない。

再生成コマンド：

```sh
blender -b -t 2 --python scripts/academy-sports/build-venues.py
node scripts/academy-sports/optimize-assets.mjs
python3 scripts/academy-sports/build-sounds.py
node scripts/generate-web-asset-manifest.mjs
node scripts/generate-android-asset-manifest.mjs --update-prefix models/academy-sports/
node scripts/generate-android-asset-manifest.mjs --update-prefix sfx/academy-sports/
```

設定・ポーズ画面の操作説明、操作補助、4段階の難易度を用意した。

## CPU・特殊プレー

選手には速度、パワー、制御、守備、スタミナ、ジャンプ、連携、投球の個性を設定。
野球は打撃反応・ミート誤差・球種/コース・落下予測・送球先を判断する。
サッカーは保持者の前進、受け手の支援、2人での追跡、陣形維持、パス/シュート判断、GKの到達予測を行う。
バレーは到達点への移動、レシーブ担当、トス先、空きコース、ブロックを判断。長いラリーは疲労と判断失敗につながる。
大運動会は障害物へのジャンプ時機、扉の操作、足場登り、アイテム使用、相手への攻撃を行う。上位難易度はショートカット・転がる障害物の回避・ガードへのつかみも選択する。

全35主人公に競技別の固有名・色・速度・威力・回転・浮きの特性を設定。サッカーの必殺シュートは35スピリットを消費し、GKに防がれる。野球の必殺投球/打球、バレーの必殺サーブ/スパイクは40を消費して次の対象プレーに予約する。連打による二重消費はない。
守備時の星盾セーブは25消費してGKを補強する。チーム覚醒は12秒。
大運動会のチーム別必殺技は45ゲージを消費し、実際の攻撃範囲・ダメージ・吹き飛ばしを変更する。

## 記録・互換性

成績は試合終了時のみ `pixel_spire_academy_sports_records_v1` に最大100件を保存する。
同じ試合の二重記録を防ぎ、保存領域不足・破損データは競技進行を止めずに扱う。
チーム得点・競技別成績・大運動会の各順位と記録を保持する。既存競技のセーブキーは変更していない。
1人用は全設定後の「学習して試合へ」の直後に単元を選ぶ。試合前とイニング/前後半/セット/種目の区切りに3問を出題し、既存の正解ポイント・課題履歴へ反映する。
新4競技は1人対CPU・CPU観戦・オンライン対戦に対応。通常モードのオンライン招待先も全8競技から選べる。

ルールテストは4競技×4難易度×4シードの64試合の終了・有限座標・実在モデルを確認。
得点・アウト・反則・セット/種目遷移・物理接触・保存保護の個別ケースも検証する。
ブラウザテストはソフトウェアWebGLで実描画し、CPU戦の結果、学習ポイント、キーボード/標準パッド/タッチ入力、320×568・390×844・844×390の操作領域、ポーズ、退出を確認する。
WebGL復旧、8競技の入口、既存招待の互換性も確認対象。スクリーンショットと結果JSONは `tmp/academy-sports-qa/`（環境変数 `ACADEMY_QA_OUTPUT` で変更可）。
既存の4競技のルールテストも通過している。
今回の確認結果は `assets/academy-sports/validation.json` に記録した。ブラウザ確認は競技操作・会場・復旧・入口・音声に分けて実行している。
作業環境の空き容量制約により、ビルド時の静的メディアは同じ内容のハードリンクでdistへ出力した。JS/CSSは通常のViteビルドで生成している。

未対応・簡略化した部分：

- 野球：高度な中継・挟殺、打順/選手交代の編集、詳細な個人投手成績、すべての野球細則と公式記録。長引く守備は18秒でプレーを整理する。
- サッカー：選手交代、カード、専用の連携必殺シュート判定、細かな身体接触やGKの全モーション。必殺時は3Dカメラと個別の2Dカットイン静止画を併用する。
- バレー：全公式反則の網羅、専用カメラ付きの複雑なフェイント連携、個人別成績の充実。
- 大運動会：独立した2対2トーナメント形式のターゲット戦（現状は4チーム各2人の同時戦）、全障害物の精密な剛体物理、対戦格闘相当の連続技・空中投げ。
- 新4競技の同一端末でのローカル複数人対戦、フル実況ボイス、試合途中のセーブ再開、全状況の英語/ひらがな実況文。
- 実機iPhone/Android、実物ゲームパッド、長時間連続プレイ、全主人公・全競技の全組み合わせは未検証。ブラウザのタッチ/パッドエミュレーションによる確認と区別する。

オンラインのロジック検証は最大18／22／12／8席の割り当て、権限制限、同時入力、野球の手番、切断・開始待ち・再戦と、通信コマンド経由の4競技の完走を対象にする。ブラウザ間テストはローカルの実PeerServerと2つのChromiumコンテキストで競技ごとの招待・学習・準備・3D読み込み・操作同期・結果共有・再戦を確認した。各競技の上限18／22／12／8セッションの実WebRTC入室と、切断後の枠解放も確認した。上限試験の追加参加者は描画を行わない通信セッションであり、同時描画は各競技2端末相当。最大22台の実機同時接続や外部NAT越え・外部TURNサービス経由の通信は未検証。ローカルTURNのTCP中継で、検証環境のChromiumのUDP制限を変更せずに通信確認する。

次の改善は実機でのプレイフィール・カメラ・CPUバランス確認を優先し、野球の細則、サッカーの連携技、バレーの戦術、運動会の足場と格闘の深さを順に拡張する。

## ImageGenによる画面素材

各競技とスポーツ総合の縦横タイトル10点、選択用2×2アイコン1シート、各競技の操作用3×2アイコン4シートを新規生成。既存のテニスのタイトル・操作アイコンとスポーツ選択アイコンを参照し、WebPで登録した。元の構図を保ち、CSSのセル指定で各イラストを表示する。ハッシュと寸法は `assets/academy-sports/imagegen-art.json`。専用タイトルからプレイ設定へ進む。通常モードでも入口・ゲーム本体・招待が利用できる。

オンラインブラウザ試験は `CHROMIUM_PATH` でブラウザ実行ファイルを指定できる。
直接WebRTCを使えない環境では、試験専用の `turn-server@0.8.0` をユーザー所有の一時ディレクトリへインストールし、`ACADEMY_TEST_TURN_MODULE` にその `index.js` の絶対パスを指定する。
試験スクリプトがループバックだけでTCP中継を起動・終了する。製品の依存関係や本番TURN設定は変更しない。

## 主人公別の必殺球・音声

小学生9人・高校9人・マジック17人の全35主人公について、既存の本人イラストを参照し、ImageGenで野球・サッカー・バレー各1点、計105点のカットインを生成した。9枚のアトラスで配信し、ボール用エフェクトは各競技4フレーム、計12フレームを透過シートにした。出典・寸法・ハッシュは `assets/academy-sports/special-art.json`。カットインは操作領域を避け、動きを減らす設定に対応する。

ボイスは同じ主人公の既存スポーツ/継界戦記の短い掛け声を、競技ごとの通常アクション・必殺球へ計280枠割り当てた。新規音声の生成は行っていない。`voiceCatalog.ts` に本人・出典・セリフ・長さを記録し、既存の音量・ミュート・iOS復帰処理と優先度付きキューで再生する。

野球の投手視点では左右照準をカメラ方向に合わせる。サッカーは横長画面ではサイドカメラの横向きコート、縦長画面では奥行きコートに切り替え、キーボード・タッチ・パッドを同じ画面座標変換へ通す。オンラインでも変換は送信前に一度だけ行う。操作選手が自動で切り替わっても移動の長押しを保ち、ため操作だけを解除する。サッカーではシュート直後に自分でボールを拾い直さないようにする。

追加検証は全35人の必殺投球・打球・シュート・サーブ・スパイクの実際の速度/軌道/消費、105セル、280枠の本人ボイス、効果シートの透明余白を確認する。ブラウザでは通常起動、設定後の単元選択、実際の投球照準、縦横カメラ、カットイン・4フレーム・音声再生と復号を確認する。再生成用のアトラス登録は `node scripts/academy-sports/package-special-art.mjs <ImageGen結果JSON>`、カタログ生成は `node scripts/academy-sports/build-special-catalog.mjs`。

## 野球・サッカーの放送風HUDとアクション

野球は得点・イニング・B/S/Oランプ・実際の走者ダイヤ、投手/打者の本人イラストと能力評価、球種・球速・スピリットを表示。球速はkm/hで表示する。サッカーはチーム色を統一した中央スコア・前後半時計、操作選手・相手GKのゲージ、22選手とボールが移動するミニマップを表示する。時計は選択した短時間の試合を45分/90分相当に換算し、追加時間をATで示す。スマホはカードをコンパクト化し、操作ボタンと重ならない位置へ移動する。

1人プレイでは味方の保持者へ常に操作を同期する。パス受領・タックル奪取・リスタート・GKのキャッチも対象で、味方が保持している間の手動切替は行わない。GKを操作している間はCPUが勝手にパスや移動を行わない。オンラインの席・操作ユニット割り当てとCPU観戦はこの同期の対象外。

サッカーのB/Xは保持中に切り返し、守備中にタックル。切り返しは18スピリットを消費し、相手との距離1.9m未満でPERFECT、3.2m未満でGOOD、それ以外は移動のみ。成功とパスで最大5段階のLINKを積み、1段階ごとにシュート速度3.5%、チャージ速度7%を強化する。10秒経過または保持を奪われると失効する。最寄りの相手を短く硬直させ、同じフレーム内でボール位置も移す。成功トースト、チャージ方向の点線、操作選手の頭上マーカー、必殺の寄りカメラとゴールリプレイで状態を示す。

野球は投球の脚上げ/体幹の捻り/リリース/フォロースルー、打撃の腰先行と振り抜き、捕球・送球・走塁。サッカーは速度に合う歩幅の走行・ドリブル、ため・キックの軸足とフォロースルー、スライディング、GKのハイキャッチを既存スケルトンに適用する。物理・当たり判定・投球のリリース時刻は変更せず、打撃・送球・キックは物理イベントの発生時点をインパクトとして描画し、残りをフォロースルーに使う。アニメーション終了時に全関節を戻す。ポーズ関数に後方互換のY軸回転引数を追加し、髪モデルにも同じ回転を反映する。カメラ切替は視点ごとにカットし、追従は描画頻度に依存しない補間とする。動きを減らす設定では装飾的な上下動・回転・カメラ演出を抑える。

追加検証：`pnpm run test:academy-sports:broadcast`、`pnpm run test:academy-sports:broadcast:browser`。実パス・GKキャッチからの操作引継ぎ、オンライン/観戦の維持、切り返しの距離・コスト・連携の威力、各モーション段階、実ボーンの四元数変化、4画面サイズ、日英ひらがなの表示を検証する。新しい試合の描画ID、モデル・用具の読み込み完了、バット・ボールの実体も待ってから画像を取得する。画像と結果は `tmp/academy-broadcast-qa/`。

## CPUと野球守備の調整（2026-11-13）

野球のCPU打撃は投球ごとにタイミング・照準・見送りを決め、毎フレームのボール追従を廃止。プレイヤー向けの打撃補助をCPUに適用しない。難度ごとに誤差と打球の強さを分け、ゴロ・ライナーを中心にする。CPUの自動必殺投球は上位難度のみ。人間の打撃・必殺打の威力は保持する。

試合中（オンラインを含む）の打球後は全野手が自動で追球・捕球・送球し、手動入力が守備を止めない。守備側のボタンは「守備オート」と表示し、次の投球では投手操作に戻る。専用の守備練習は手動で操作できる。

サッカーはCPU独自の狙いを使い、プレイヤーのスティック方向を参照しない。難度別の判断間隔・追従速度・シュート誤差と威力・タックル頻度を適用。下位難度では遠距離シュートや必殺シュートの連発を抑える。キーパーも毎フレームの完全予測ではなく間隔を置いて追従する。

バレーはCPUの追従速度・返球判断・スパイクとサーブの飛行時間・コースの読み・ブロック頻度を調整。ソロの味方の移動支援を保ち、相手を弱くした設定が味方の追球を妨げない。人間の入力と専用練習は維持する。

`node scripts/academy-sports/test-cpu-balance.mjs` は4難度×160球、オンラインを含む無操作の自動守備、CPUの狙いの独立、球速差を検査する。標準難度の固定試験160球では打撃成功66回、ホームラン2本。これは試験条件下の結果で、全投球の発生率を保証する値ではない。
