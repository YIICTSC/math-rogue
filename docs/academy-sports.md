# スポーツモード追加4競技

スポーツクラブに、野球・サッカー・バレーボール・大運動会を追加した。
新4競技は1人対CPU、練習、CPU観戦から試合終了・成績保存・再挑戦まで進められる。
依頼書の全細目を実装済みとするものではない。残っている項目は末尾に記載する。
新4競技は有効なデバッグモードでのみ表示・起動する。通常モードは既存4競技を選択できる。

## 流用した既存機能

- SportsHubの入口、既存4競技のタイトル・招待機能を維持。新4競技は遅延ロードする独立ルート。
- `ProtagonistModel`、主人公カタログ、スポーツ衣装と既存のスケルトン・基本クリップ。既存GLBは上書きしていない。
- `useGameplayGamepad`、学習範囲・配信課題の選択、問題生成、QuizPanel、正解ポイントと学習記録。
- audioServiceの音量・ミュート・音声解放・iOSオーディオ復帰処理。

## 新規素材・構成

Blenderで独自制作したGLBを `public/models/academy-sports/` に配置した。
球場、サッカースタジアム、体育館、街中コース、障害物8部屋、ターゲット会場、屋上、表彰会場、用具バンクの9ファイル。
用具には3種のボール、バット、グローブ、ヘルメット、捕手防具、競技別ジャージ、膝当て、障害物、アイテム、トロフィーを含む。
競技場には立体的な設備・観客席・看板・照明・建物を配置。スコアボード、ネット変形、軌跡、選手マーカー、紙吹雪は実行時に描画する。

専用動作は既存リグへの競技別ボーン姿勢として追加した。投球・打撃・捕球・送球、キック・タックル、サーブ・レシーブ・トス・スパイク・ブロック、パンチ・キック・ガード・リアクションに対応する。
参考作品のキャラクター・音源・名称・モデルは使用していない。

32種類のオリジナル合成効果音をMP3とOpusの2形式で制作した。GLBと合わせて約11.6 MiB。
出典・ハッシュ・サイズは `assets/academy-sports/{asset-build,sound-build}.json`。
Web/Androidのアセット一覧に登録済み。ボイスの新規生成は行っていない。

再生成コマンド：

```sh
blender -b -t 2 --python scripts/academy-sports/build-venues.py
node scripts/academy-sports/optimize-assets.mjs
python3 scripts/academy-sports/build-sounds.py
node scripts/generate-web-asset-manifest.mjs
node scripts/generate-android-asset-manifest.mjs --update-prefix models/academy-sports/
node scripts/generate-android-asset-manifest.mjs --update-prefix sfx/academy-sports/
```

## 操作方法

| 操作 | キーボード | 標準ゲームパッド |
| --- | --- | --- |
| 移動・照準 | 方向キー / WASD | 左スティック / 十字キー |
| 打撃・投球・シュート・バレーの接触・攻撃 | Z（サッカーは長押し→離す） | A |
| 捕球・タックル・ブロック・ガード | X | B |
| パス・アイテム | C | X |
| ジャンプ | R | Y |
| 操作選手変更 | Q | LB |
| 必殺技・連携 | V | RB |
| ダッシュ | Space | RT |
| ロングパス・攻撃種別 | F | LT |
| 切り返し・球種/打ち方・つかみ | T | 右スティック押込み |
| ポーズ | Esc / P | Menu |

スマートフォンは左の仮想スティックと右のアイコンを使用する。
野球の攻撃中は、打球後の主ボタンが進塁、守備ボタンが帰塁になる。走者がいれば盗塁ボタンを表示。
旗ボタンから球種・打ち方・送球先・トス先・攻撃種別などを選ぶ。パッドの左スティック押込みでパス/トス先選択、野球の送球は方向入力＋Aでも塁を指定できる。戦術選択中は競技時間を止める。
設定・ポーズ画面の操作説明、操作補助、4段階の難易度を用意した。

## CPU・特殊プレー

選手には速度、パワー、制御、守備、スタミナ、ジャンプ、連携、投球の個性を設定。
野球は打撃反応・ミート誤差・球種/コース・落下予測・送球先を判断する。
サッカーは保持者の前進、受け手の支援、2人での追跡、陣形維持、パス/シュート判断、GKの到達予測を行う。
バレーは到達点への移動、レシーブ担当、トス先、空きコース、ブロックを判断。長いラリーは疲労と判断失敗につながる。
大運動会は障害物へのジャンプ時機、扉の操作、足場登り、アイテム使用、相手への攻撃を行う。上位難易度はショートカット・転がる障害物の回避・ガードへのつかみも選択する。

サッカーの独自必殺シュート6種は速度・浮き・回転を変更し、GKに防がれる。35スピリットを消費。
守備時の星盾セーブは25消費してGKを補強する。チーム覚醒は12秒。
バレーの連携は45ゲージを消費して次の攻撃を強化。大運動会のチーム別必殺技も45ゲージを消費し、実際の攻撃範囲・ダメージ・吹き飛ばしを変更する。

## 記録・互換性

成績は試合終了時のみ `pixel_spire_academy_sports_records_v1` に最大100件を保存する。
同じ試合の二重記録を防ぎ、保存領域不足・破損データは競技進行を止めずに扱う。
チーム得点・競技別成績・大運動会の各順位と記録を保持する。既存競技のセーブキーは変更していない。
試合前とイニング/前後半/セット/種目の区切りに3問出題し、既存の正解ポイント・課題履歴へ反映する。
新4競技は1人対CPUとCPU観戦に対応。既存のオンライン招待先は従来の4競技のまま。

## 検証と残る項目

```sh
pnpm run test:academy-sports
pnpm run verify:academy-sports:assets
pnpm run test:academy-sports:browser
pnpm run test:academy-sports:audio
pnpm run build
pnpm run server:build
```

ルールテストは4競技×4難易度×4シードの64試合の終了・有限座標・実在モデルを確認。
得点・アウト・反則・セット/種目遷移・物理接触・保存保護の個別ケースも検証する。
ブラウザテストはソフトウェアWebGLで実描画し、CPU戦の結果、学習ポイント、キーボード/標準パッド/タッチ入力、320×568・390×844・844×390の操作領域、ポーズ、退出を確認する。
WebGL復旧、8競技の入口、既存招待の互換性も確認対象。スクリーンショットと結果JSONは `tmp/academy-sports-qa/`（環境変数 `ACADEMY_QA_OUTPUT` で変更可）。
既存の4競技のルールテストも通過している。
今回の確認結果は `assets/academy-sports/validation.json` に記録した。ブラウザ確認は競技操作・会場・復旧・入口・音声に分けて実行している。
作業環境の空き容量制約により、ビルド時の静的メディアは同じ内容のハードリンクでdistへ出力した。JS/CSSは通常のViteビルドで生成している。

未対応・簡略化した部分：

- 野球：高度な中継・挟殺、打順/選手交代の編集、詳細な個人投手成績、すべての野球細則と公式記録。長引く守備は18秒でプレーを整理する。
- サッカー：選手交代、カード、専用の連携必殺シュート判定、細かな身体接触やGKの全モーション。カットインは3Dカメラ演出で、個別の2Dアニメ映像ではない。
- バレー：全公式反則の網羅、専用カメラ付きの複雑なフェイント連携、個人別成績の充実。
- 大運動会：独立した2対2トーナメント形式のターゲット戦（現状は4チーム各2人の同時戦）、全障害物の精密な剛体物理、対戦格闘相当の連続技・空中投げ。
- 新4競技のローカル複数人/オンライン対戦、フル実況ボイス、試合途中のセーブ再開、全状況の英語/ひらがな実況文。
- 実機iPhone/Android、実物ゲームパッド、長時間連続プレイ、全主人公・全競技の全組み合わせは未検証。ブラウザのタッチ/パッドエミュレーションによる確認と区別する。

次の改善は実機でのプレイフィール・カメラ・CPUバランス確認を優先し、野球の細則、サッカーの連携技、バレーの戦術、運動会の足場と格闘の深さを順に拡張する。

## ImageGenによる画面素材

各競技とスポーツ総合の縦横タイトル10点、選択用2×2アイコン1シート、各競技の操作用3×2アイコン4シートを新規生成。既存のテニスのタイトル・操作アイコンとスポーツ選択アイコンを参照し、WebPで登録した。元の構図を保ち、CSSのセル指定で各イラストを表示する。ハッシュと寸法は `assets/academy-sports/imagegen-art.json`。専用タイトルからプレイ設定へ進む。Appの `isDebugModeActive` を入口とゲーム本体の両方で要求する。
