# 翻訳完結契約

更新日: 2026-07-21

## 目的

英語・ひらがなモードの翻訳漏れを、目視巡回の記憶や個別画面のチェックリストに依存せず、表示元データと描画経路の両方から継続的に検出する。

この文書は翻訳作業の完了条件と、今後文字列を追加するときの実装規則を定義する。過去の画面別計画より本書の検証条件を優先する。

## 翻訳対象

- タイトルからエンディングまでの全共通UI
- 小学生編、高校編、マジック編の画面、イベント、戦闘、報酬、結果
- デバッグメニューと、デバッグから開く確認画面
- カード、レリック、ポーション、敵、エンディング、BGMを含む図鑑データ
- タイピングモードの共通UI、レッスン名、説明、段階名
- オンラインランキング、記録画面、設定、確認、エラー、通知
- ミニゲームの選択、解放通知、削除確認、終了後の共通UI
- `title`、`aria-label`、`placeholder`、`alt` など視覚外の表示文字
- 数値や名称を埋め込む動的文章

## 明示的な対象外

- `src/mini-games/` と、旧実装の `SchoolDungeonRPG.tsx`、`SchoolDungeonRPG2.tsx`、`PokerGameScreen.tsx`、`PaperPlaneBattle.tsx` 内のゲーム固有HUD、問題、チュートリアル、演出文
- `src/data/subjects/` 内の学習問題本文と教材上の正式表記
- 課題モーダルの単元名と板書教材本文
- 日本語の読み取り自体をルールとする問題
- つかぽん英語問題の日本語回答
- クレジットに掲載する人名・支援者名
- 画像に焼き込まれた文字、数式、URL、保存キー、操作キー名

対象外は上記のフィールドだけであり、ファイル名に `MiniGame`、`Debug`、`data` が含まれることを理由にファイル全体を除外しない。

## 実装規則

1. JSXの固定表示文、UI属性、通知文は `trans` を通す。
2. イベント本文は `transEventText` を通す。
3. 問題の教科・単元表示には用途に応じて `transProblemSubjectName` を使う。
4. 文脈依存の文章は短語の部分置換で補わず、完全一致辞書へ原文単位で登録する。
5. 動的文章は表示時と同じテンプレートを監査でも組み立てる。
6. 固有名を原文維持する場合は、名前フィールドだけを例外とし、周辺の役割名や説明を例外に含めない。
7. 新しい表示データ集合を追加した場合、その全フィールドを監査スクリプトへ列挙する。
8. 監査の除外を追加する場合、本書の「明示的な対象外」に理由と境界を先に記載する。

## 自動監査の責務

### 英語

- 翻訳後にひらがな、カタカナ、漢字が残っていないこと
- 汎用フォールバック文へ潰れていないこと
- JSX本文、JSX式、UI属性に日本語直書きがないこと
- 図鑑、エンディング、ランキング、タイピング、ミニゲーム共通UIを全件検査すること

### ひらがな

- 翻訳後に未許可の漢字が残っていないこと
- 既知の誤読・誤分割が再発していないこと
- JSX本文、JSX式、UI属性に漢字直書きがないこと
- 図鑑、エンディング、ランキング、タイピング、ミニゲーム共通UIを全件検査すること

### 描画経路

- `src/mini-games/`、列挙した旧ミニゲーム本体、`src/data/subjects/` 以外の全TS/TSXを静的走査する
- `DebugMenuScreen`、`MiniGameSelectScreen`、`MiniGameProblemChallenge`、表示用の `src/data` を一括除外しない
- 日本語・英語の明示的な言語分岐内だけは、反対言語の監査で直書きを許可する

## 完了ゲート

以下がすべて同一コミット候補上で成功したときだけ翻訳作業を完了扱いにする。

1. `npm run audit:english`
2. `npm run audit:hiragana`
3. `npm run audit:display-copy`
   - 通常は3監査をまとめた `npm run audit:translations` を使う。
4. 上記3監査を3巡連続で実行
5. `npm run build`
6. `git diff --check`
7. 監査対象外パスが本書の例外境界と一致することを差分レビュー
8. 実画面で英語・ひらがなの代表的な動的モーダルを確認

監査失敗を辞書追加だけで解消した場合も、表示元の全レコードを再監査する。単一の発見箇所だけを修正して完了とはしない。
