# エンドレスモード ギミック説明・難度改訂仕様

更新日：2026-09-04

## 1. 目的

エンドレスモードのギミックは、現在のマップ画面に「弱点」「ギミック」「備え」を表示している。しかし、プレイヤーが次の内容を一度に判断できない。

- どの範囲で数えるのか
- 何を何回すれば達成なのか
- 失敗したとき、何がリセットされるのか
- 達成すると何が起こるのか
- 「S01」「3問全部正解」「同じ単元」「カードタイプ」などの用語が何を指すのか
- 現在の進捗がどこで確認できるのか

本資料では、50章・1章15F・5章ごとにボスという現行仕様を維持したうえで、ギミックの説明文と達成条件がプレイヤーに伝わる形へ整理する。あわせて、750F相当という全体の長さに対して、ギミックの条件が適切かを評価する。

## 2. 現行エンドレスモードの長さ

### 2.1 全体構造

エンドレスモードは通常モードのAct番号を引き継がず、エンドレス第1章（C01）から始まる。

| 項目 | 現行仕様 |
|---|---|
| 章数 | 50章（C01〜C50） |
| 1章の長さ | 15F。通常モードの1章と同じ長さ |
| 全体の長さ | 50章 × 15F ＝ 750F相当 |
| ボス章 | C05、C10、C15、C20、C25、C30、C35、C40、C45、C50 |
| ボス間隔 | 5章ごと。4章を進み、5章目の終端でボス戦 |
| 大ボス | C10、C20、C30、C40、C50 |
| 最終処理 | C50ボス、最終報酬、各編の真エンディング |
| 真エンドレス | C51以降。5章ごとに自動生成ボスが出現 |

ゲーム開始直後に画面へ表示される `0F` は、C01のマップへ入る前の表示である。C01の15Fを進み、C02〜C04を経て、C05の終端で最初のボスに到達する。

### 2.2 5章区間の定義

`S01` は専門的な内部IDではなく、プレイヤーにとっては「次のボスまでの5章分の範囲」を表す。

| 区間 | 対象章 | 累計Fの目安 | 区間の終わり |
|---:|---|---:|---|
| S01 | C01〜C05 | 1〜75F | C05ボス |
| S02 | C06〜C10 | 76〜150F | C10ボス |
| S03 | C11〜C15 | 151〜225F | C15ボス |
| S04 | C16〜C20 | 226〜300F | C20ボス |
| S05 | C21〜C25 | 301〜375F | C25ボス |
| S06 | C26〜C30 | 376〜450F | C30ボス |
| S07 | C31〜C35 | 451〜525F | C35ボス |
| S08 | C36〜C40 | 526〜600F | C40ボス |
| S09 | C41〜C45 | 601〜675F | C45ボス |
| S10 | C46〜C50 | 676〜750F | C50最終ボス |

`S01区間内` と表示する場合は、必ず次のように展開して表示する。

```text
S01（C01〜C05／1〜75F）
```

「S01」だけを表示してはいけない。マップ上では、内部IDではなく次のプレイヤー向け表記を基本とする。

```text
次のボスまで：S01・あと4章
数える範囲：C01〜C05（1〜75F）
```

### 2.3 50章は長すぎるか

50章・750F相当は、1回の短時間プレイで完了する長さではない。一方、1章15Fは通常モードと同じため、1章ごとのプレイ感覚は既存仕様から大きく変わらない。

| 観点 | 判定 | 理由・改訂方針 |
|---|---|---|
| 1章15F | 適切 | 通常モードと同じで、マップを理解しやすい。 |
| 5章ごとのボス | 条件付きで適切 | 節目としては分かりやすい。ただし75Fを何も起こらずに進ませない。各章で進捗を表示する。 |
| 1区間75F | 条件付きで適切 | 1回・2回条件は短すぎる。最低5回の「戦闘後3問セット」を前提に、3問全部正解4回・3セット連続・6回のカード解決を基準にする。 |
| 50章・10区間 | 長いが許容 | 章結果、回復、カード解禁、区間表示、セーブ継続が必要。 |
| C50到達 | 高い目標として適切 | 真エンディングに相当するため、最後の3問・4フェーズの役割を明示する。 |
| C51以降 | 無限に継続可能 | 新しい隠し条件を増やさず、既存10種の条件を明示的に再利用する。 |

### 2.4 長さに対する結論

- 50章・750F相当そのものは変更しない。
- 75Fの区間内で達成するギミックは、プレイヤーが途中経過を見られることを必須にする。
- 1回成功、2回成功、カード3種類を1回ずつは、75Fの区間条件として簡単すぎるため廃止する。
- 区間内の「戦闘後3問にすべて正解したセット」は4回、連続条件は3セット連続、カード条件は合計6回の解決を基準にする。
- 「同じ単元」「異なるカードタイプ」など、プレイヤーが出題や報酬を完全には操作できない条件は、必須条件から外すか、達成手段を必ず用意する。
- C50のボス戦後3問は、戦闘中の条件と混同しやすいため、専用の画面見出しで知らせる。

### 2.5 75Fを基準にした約70％達成レベリング

「約70％達成」は、全プレイヤーの70％が必ず達成するという意味ではなく、通常のデッキ・通常の3問セット成功率・区間内の標準的なプレイを30周程度テストしたとき、各ボスギミックの達成率が60〜80％、目標値が約70％になることを意味する。

区間内の「戦闘後3問セット」は最低5回保証されるため、初期の基準値は次のようにする。3問のうち1問でも不正解・途中離脱になったセットは、3問全部正解1回には数えない。

| 条件種別 | 現行の問題 | 改訂基準 | 75Fでの狙い |
|---|---|---|---|
| 3問全部正解の累計 | 1回または3回 | 3問全部正解を4回 | 5回の最低機会に対して、1セットの失敗を許容しつつ簡単すぎない。 |
| 3問全部正解の連続 | 2回または3回 | 3セット連続 | 5〜6セットの機会で、セット成功率80％前後なら約70％を狙える。 |
| 3カードタイプ | ATTACK・SKILL・POWERを各1回 | 3種類を各2回、合計6回 | 75Fの自然なカード使用だけでは即達成しない。 |
| 2カードタイプ | 異なる2種類を各1回 | 選んだ2種類を各3回、合計6回 | 2種類条件でも回数を必要にし、偏ったデッキを放置しない。 |
| 同一戦闘の攻撃 | ATTACKを2枚連続 | ATTACKを3枚連続 | 手札・エネルギー・敵の行動を見て準備する必要がある。 |
| ボス戦序盤 | 3ターン以内にATTACKを1枚 | 3ターン以内にATTACKを2枚 | 早期の手札準備を要求するが、初期ドローで達成手段を保証する。 |
| 均衡条件 | 攻撃・ブロック・3問全部正解を各1回 | 攻撃・ブロック・3問全部正解を各2回、最大差1以内 | 3つの行動を区間全体で計画する。 |

目標値はコード上の数値だけで決定しない。小学生編・高校編・マジック編、通常デッキ・マジック開始デッキ、各難度でプレイテストを行い、次の範囲から外れた場合に調整する。

- 達成率50％未満：条件を1段階下げるか、達成機会を増やす。
- 達成率60〜80％：採用範囲。説明と進捗表示を優先して維持する。
- 達成率80％超：条件を1段階上げるか、達成後の効果を弱める。
- 達成率90％超：ギミックとして機能していないと判断する。
- 達成率20％未満、または特定の初期デッキだけ達成不能：即時に救済を追加する。

### 2.6 深い章でのレベリング

S01〜S10で必要回数を無制限に増やすと、最低5回の戦闘後3問セットでは達成不能になる。深い章の難化は、回数の水増しではなく、次の順で行う。

1. S01〜S03：3問全部正解4回・3セット連続・合計6カードを基本値にする。
2. S04〜S07：同じ数値を保ち、敵の防壁・制限ターン・失敗時の反撃を強める。
3. S08〜S10：同じ数値を保ち、複数段階の効果やボス行動で判断量を増やす。ただし、達成条件そのものは増やさない。
4. C50：75F区間の条件とは分離し、ボス戦後3問を最終確認として表示する。
5. C51以降：既存条件を再利用し、ボス強度と報酬でレベリングする。新しい隠し回数条件を追加しない。

### 2.7 「1回」の数え方

ギミックでいう「1回」は、問題1問の正解ではなく、次の1セットを指す。

```text
1回の戦闘が終了
  ↓
戦闘後の3問を表示
  ↓
3問すべてに正解して結果を確定
  ↓
ギミックの「3問全部正解」が +1
```

- 3問のうち1問でも不正解、時間切れ、途中離脱があった場合、そのセットは`+0`とする。
- 累計条件では、それまでの達成数を減らさない。連続条件では連続数を0へ戻す。
- 再提出で同じ3問セットをやり直し、3問すべてに正解した場合は、その再提出を1回として数える。最初の失敗と再提出成功を二重に数えない。
- C50の真エンディング確認も、ボス撃破後の最終3問をすべて正解して`3問全部正解 0/1`から`1/1`にする。3問を`0/3`で数えない。
- マップ、詳細パネル、章結果、再開画面では、旧来の判定名を使わず、「戦闘後の3問」「3問全部正解」「3問全部正解をN回」と表示する。

## 3. ギミック説明の基本方針

### 3.1 画面に必ず表示する6項目

現在の「弱点」「ギミック」「備え」に加えて、次の情報を表示する。

| 表示項目 | プレイヤーが知る内容 |
|---|---|
| 目的 | 戦闘後の3問にすべて正解するセットを、何回達成すればよいか |
| 数える範囲 | 区間全体、同じ戦闘、ボス戦の最初の3ターン、戦闘後の3問セットなど |
| 進捗 | `0/4`、`連続0/3`、`ATTACK 1/3`、`ATTACK 1/2・SKILL 0/2・POWER 0/2` などの現在値 |
| 失敗時 | 進捗が維持されるか、連続数だけ戻るか |
| 達成すると | ボスの装甲、防壁、反射、強化などに起こる変化 |
| 次にすること | 次の戦闘後の3問へ進む、カードを使う、最終3問に答えるなど |

### 3.2 マップ上の短縮表示

画面の高さが限られるため、マップ上は次の4行を基本とする。

```text
次の節目：エンドレス第5章　墨核端末ピポ（あと4章）
目的：S01（C01〜C05／1〜75F）で、戦闘後の3問にすべて正解することを4回達成
進捗：0/4　失敗しても累計は減りません
達成：未処理データが消え、ボスの装甲が下がる
```

「備え」は必要な場合だけ5行目に置く。

```text
備え：区間内の戦闘後3問セットの機会を見逃さない
```

### 3.3 詳細表示

短縮表示をタップまたはクリックすると、詳細パネルを開く。用語だけでなく、ギミック全体を確認できるようにする。

```text
ギミック詳細

何をする？
S01のあいだに、戦闘後の3問へすべて正解するセットを4回達成します。

どこで数える？
C01〜C05のマップと戦闘をまたいで数えます。

現在の進捗
0/4

失敗したら？
この条件の累計は減りません。3問のうち1問でも不正解だった場合は、次の戦闘後の3問セットへ進みます。

達成すると？
未処理データが消え、墨核端末ピポの装甲が下がります。

次にすること
次の戦闘後に表示される3問へ、すべて正解してください。
```

詳細パネルは、現在の `EndlessGimmickGlossaryText` の用語タップ機能と併用する。用語をタップしなくても、ギミックの達成方法が分かる状態にする。

### 3.4 達成済み表示

達成後に「達成済み」だけを表示してはいけない。条件と結果を残す。

```text
達成済み：4/4
S01で、戦闘後の3問にすべて正解することを4回達成しました。
効果：未処理データを消去済み。ボスの装甲低下が有効です。
```

区間をまたいで次のボスを表示する場合は、現在のボスの条件と過去の達成記録を分ける。

```text
現在のギミック：S02（C06〜C10）
達成記録：S01・墨核端末ピポ　達成済み
```

## 4. 用語の扱い

### 4.1 プレイヤー向けの定義

| 用語 | 画面に表示する説明 |
|---|---|
| 3問全部正解 | 1回の戦闘後チャレンジに含まれる3問へ、すべて正解した状態です。1問でも不正解・途中離脱なら、そのセットは1回に数えません。 |
| 3問全部正解を1回達成 | 戦闘後の3問セットを最後まで解き、3問すべての正解を確定した状態です。 |
| 再提出 | 3問全部正解できなかったセットを、もう一度解き直す操作です。再提出でも3問全部正解できたときだけ1回に数えます。 |
| 同じ単元 | 同じ分野・単元の3問セットです。プレイヤーが問題単元を選べない場合、必須条件にはしません。 |
| カードタイプ | カードの分類です。ATTACK、SKILL、POWERがあります。 |
| 同一戦闘 | 1回のバトル中だけを指します。別の敵との戦闘へ移ると数え直します。 |
| 区間 | 次のボスまでの5章分の範囲です。例：S01はC01〜C05、1〜75Fです。戦闘後の3問セットをこの範囲で数えます。 |
| フェーズ | ボスのHPや行動を区切った段階です。戦闘の段階と、学習問題の必要回数は別に表示します。 |
| ターン | プレイヤーまたは敵が1回行動する単位です。 |
| ブロック | 次のターン開始まで受けるダメージを防ぐ数値です。 |
| 再演 | 直前に解決したカード効果を、もう一度発生させることです。 |
| 反照片 | 反射の力を保つボス固有の鏡像です。 |
| 属性 | マジック編のカードや能力が持つ分類です。ギミックの必須条件にする場合は、カードタイプと区別して説明します。 |
| 強化効果 | 敵を有利にする一時的な効果です。 |

### 4.2 内部名を表示しない

次の文字列は内部実装・監査用であり、通常のマップ説明へそのまま出さない。

```text
mechanicKey / subjectId / attributeId / battleId / segment / phaseCount
```

`S01`、`subjectId`、`attributeId`、`phaseCount`を出す必要がある場合は、必ず人間向けの説明を併記する。

### 4.3 黄色ハイライトの使い方

- タップ・クリックできる用語は黄色背景＋下線で表示する。
- 初めて表示されるギミックには「黄色の用語をタップすると説明を確認できます」を1回表示する。
- 色だけに依存せず、下線、`aria-label`、キーボードのEnter・Space操作を用意する。
- 黄色ハイライトを押さなくても、目的・範囲・進捗・失敗時・達成後は読めるようにする。

## 5. 進捗の共通ルール

### 5.1 範囲ごとのリセット

| 条件 | 数える範囲 | リセットされるタイミング |
|---|---|---|
| 区間内の「3問全部正解」回数 | S01〜S10などの5章区間 | ボス報酬を確定したとき |
| 「3問全部正解」の連続 | 指定された区間内 | 3問セットで1問でも不正解・途中離脱になったとき。単元の変更は必須失敗にしない |
| 同一戦闘のカード連続 | 1回のボス・通常戦闘 | 戦闘終了、別カードを挟んだとき |
| 異なるカードタイプ | 指定された区間または戦闘 | 指定範囲が終わったとき。重複タイプは進捗を増やさない |
| ボス戦後の3問セット | そのボス撃破後の3問 | 3問を終了したとき |
| フェーズ | ボス戦のHP・行動演出 | 戦闘終了時。3問セットの必要回数とは別管理 |

### 5.2 連続条件の公平性

現行の「同じ単元の3問セットへ2回／3回連続で正解」は、プレイヤーが問題単元を直接選べない場合に隠し条件になる。回数も、75Fに対して2セットでは短すぎる。改訂後は次のようにする。

- 連続条件は、原則として「戦闘後の3問にすべて正解することをNセット連続」とする。
- Nは原則3とし、2回連続は採用しない。
- 同じ単元でも別の単元でも、3問全部正解を連続達成すれば数える。
- 「同じ単元」は演出または任意ボーナスとして表示し、未達成の原因にしない。
- 失敗で連続数を0へ戻すことは、表示上明記する。
- 3問セットを途中離脱した場合も、連続条件では失敗として扱うか、数えないかをギミックごとに明記する。無言で判定しない。

この変更により、同一サイクル内の単元が固定されていても、異なる分野を引く必要はなく、同一単元を引き続ける必要もなくなる。

### 5.3 カードタイプ条件の公平性

通常の開始デッキはATTACKとSKILLを含むが、POWERが開始時から保証されるとは限らない。よって、ATTACK・SKILL・POWERの3種類を合計6回（各2回）要求するギミックには、次のいずれかを必ず適用する。

1. 区間開始時またはボス前に、不足しているカードタイプの一時カードを、必要回数分提示する。
2. 区間内のカード報酬に、不足タイプを必要回数分保証する。
3. POWERを要求せず、プレイヤーが所持しているカードタイプから2種類を選び、それぞれ3回解決する条件へ下げる。

推奨は1と2の併用である。達成条件を知らないままカードを取れなかった場合でも、後から詰まらないようにする。救済カードは達成後にデッキから除外でき、通常報酬の選択肢を圧迫しないようにする。

### 5.4 再提出条件の公平性

「失敗した3問セットを再提出して3問全部正解」は、全問正解したプレイヤーには発生しない。そのままでは、上手にプレイしたことが未達成の原因になる。

改訂後は、C05高校編の再提出ギミックに限り、75Fの間に4回の復習セット（各3問）を提示し、そのうち3セットで3問全部正解する条件へ変更する。

- 過去に失敗したセットがない場合も、ボス前に「復習として再提出する4セット（各3問）」を明示的に提示する。
- 各セットは誤答を意図的に作らなくても再提出として記録し、4セット中3セットで3問全部正解すると達成とする。

誤答を意図的に作らせず、復習行動として自然に達成できる。進捗は`復習セット 0/3（全4セット）`のように表示し、未達成時の再開方法も明記する。

## 6. 30ボスのプレイヤー向けギミック仕様

以下の表は、現在の30ボスのギミックを、マップ画面でそのまま使える文章へ変換した案である。内部の `mechanicKey` は表示しない。

### 6.1 小学生編

| ボス | プレイヤー向け達成条件 | 範囲・進捗表示 | 失敗時 | 達成時の表示 |

## 7. 真エンドレス（C51以降）の説明

### 7.1 長さと区間

真エンドレスはC51から始まり、5章ごとにボスが出現する。

| 例 | 区間 | 累計Fの目安 | ボス |
|---|---|---:|---|
| C51〜C55 | S11 | 751〜825F | C55ボス |
| C56〜C60 | S12 | 826〜900F | C60ボス |
| C61〜C65 | S13 | 901〜975F | C65ボス |

以後も `S = ceil(章番号 / 5)` として計算する。画面には次のように表示する。

```text
真エンドレス S11（C51〜C55／751〜825F）
```

### 7.2 自動生成ギミックのルール

真エンドレスでは、既存の10種類のギミックを再利用する。新しい内部名を増やして説明不足を悪化させない。

- `REPEAT_RECORD`、`WAVEFORM`、`STAR_KEY`、`ORBITAL_ORDER`：戦闘後の3問にすべて正解するセットを3回連続。単元は問わない。
- `ATTRIBUTE_SEAL`、`MORPH_AFTERIMAGE`：選んだ2種類のカードを各3回、区間内で合計6回解決する。
- `NOISE`、`CONTRACT`：区間内に戦闘後の3問にすべて正解するセットを4回達成。
- `TIME_PHASE`：ボス戦の1〜3ターン目にATTACKを2枚解決する。
- `CATALYST`：同一戦闘でATTACKを3枚連続解決する。
- 生成ボスの画面にも、固定30ボスと同じ6項目を表示する。

生成時に条件値を毎回変えてはいけない。真エンドレスの標準値は、区間内の「戦闘後3問全部正解」4回、連続3セット、カード合計6回、同一戦闘ATTACK3枚、序盤ATTACK2枚とする。敵の強さや報酬を上げても、説明のない回数条件を追加しない。

`真エンドレス第55章の深層ギミック` のような抽象文だけを出してはいけない。必ず「目的」「範囲」「進捗」「失敗時」「達成時」へ分解する。

## 8. 実装時のデータ構造案

既存の `mechanicSummary`、`weakness`、`recommendedPrep` だけでは説明を構造化できないため、ボス定義へプレイヤー向け説明を追加する。

```ts
type EndlessGimmickExplanation = {
  objective: string;
  scope: string;
  progressLabel: string;
  failure: string;
  achievement: string;
  nextAction: string;
  progressKind: 'THREE_CORRECT_SET_COUNT' | 'THREE_CORRECT_SET_STREAK' | 'CARD_TYPES' | 'BALANCE' | 'FINAL_THREE_CORRECT';
  target: number;
  minimumOpportunities?: number;
  targetByType?: Partial<Record<'ATTACK' | 'SKILL' | 'POWER', number>>;
  targetByAction?: Partial<Record<'attack' | 'block' | 'learning', number>>;
  requiresPlayerChoice: boolean;
};

interface EndlessBossDefinition {
  // 既存フィールド
  mechanicSummary: string;
  weakness: string;
  recommendedPrep: string;

  // 追加する表示用フィールド
  playerExplanation: EndlessGimmickExplanation;
};
```

条件ロジックのIDと表示文は分離する。既存セーブの `bossId` と `mechanicKey` は維持するが、回数条件を変更するため、進捗データには `tuningVersion` を持たせる。旧バージョンの進捗を新条件の達成済みとして引き継がず、区間開始時または次回ロード時に新基準へリセット・再計算する。これにより、旧条件の`1/1`や`種類3/3`が残って新条件をスキップすることを防ぐ。

```ts
type EndlessGimmickTuning = {
  tuningVersion: number;
  minimumOpportunities?: number;
  target: number;
  targetByType?: Partial<Record<'ATTACK' | 'SKILL' | 'POWER', number>>;
  targetByAction?: Partial<Record<'attack' | 'block' | 'learning', number>>;
};

type ThreeQuestionSetResult = {
  setId: string;
  totalQuestions: 3;
  answeredQuestions: number;
  correctQuestions: number;
  allCorrect: boolean;
  completed: boolean;
};
```

新条件へ移行した後は、区間内の戦闘後3問セットの機会数・カード報酬・救済カードの有無を監査ログへ記録し、プレイテストの達成率と照合する。
ギミックの累計・連続カウンターは、このセット結果の`allCorrect`が`true`になったときだけ1回進める。3問それぞれの回答イベントを、そのまま累計や連続数へ加算してはいけない。

## 10. 受け入れ条件

- [ ] C01〜C50のすべてのボスで、マップ画面だけを見て達成条件が分かる。
- [ ] `S01`〜`S10`は、章範囲・F範囲・次のボスが併記される。
- [ ] C51以降も、`S11`以降の範囲が自動展開される。
- [ ] 標準ギミックの進捗が`0/4`、`連続0/3`、カードタイプ別の`0/2`または選択タイプ別の`0/3`、3カウンター別で表示される。
- [ ] 各5章区間には最低5回の戦闘後3問セットがあり、3問全部正解4回の条件を成立させられる。
- [ ] 75Fの標準ギミックに、3問全部正解1回・2回、連続2セット、カード3種類を各1回だけという条件が残っていない。
- [ ] 失敗時に何がリセットされるかが表示される。
- [ ] 達成後に、条件だけでなくゲーム内効果が表示される。
- [ ] 学習連続条件は、同じ単元を引けないことを理由に未達成にならない。
- [ ] 3種類のカード条件は、プレイヤーのデッキ状況に応じた達成手段が保証される。
- [ ] 3種類のカード条件は各2回、2種類のカード条件は各3回、合計6回として表示される。
- [ ] 同一戦闘のATTACK条件は原則3枚連続、序盤条件は3ターン以内に2枚として表示される。
- [ ] 30周以上のプレイテストで、各標準ギミックの達成率が60〜80％に収まり、目標値約70％を確認できる。
- [ ] 再提出条件は、全問正解したプレイヤーにも達成手段がある。
- [ ] 黄色ハイライトの用語は、タップ・クリック・Enter・Spaceで説明を開ける。

- [ ] 小学生編、高校編、マジック編、真エンドレスで説明の項目構成が一致する。
- [ ] 日本語、ひらがな、英語の各表示で、内部IDがそのまま露出しない。
