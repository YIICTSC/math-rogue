# 雑学内ミニゲーム改善計画（将棋／配置型TCG）

作成日: 2026-08-20
対象: 雑学・教養カテゴリ内の「ミニ将棋」と「学習ローグTCG」
状態: 初回導入済み（標準将棋／アドバンス将棋／配置型TCG）

## 1. 目的

雑学内の2つのミニゲームを、学習ローグ本編と異なる遊びとして繰り返し楽しめる内容へ改善する。

- ミニ将棋
  - 選択した駒の移動可能範囲を盤上に表示する。
  - 龍を含む標準駒の動きを正しい将棋ルールに統一する。
  - プレイごとに駒の種類と初期配置が変わる。
  - ユニーク駒50種と全100ステージのアドバンスモードを追加する。
  - 駒の長押しから、いつでも動きと特殊ルールを確認できるようにする。
- 学習ローグTCG
  - 本編と同系統の「手札から効果を即時使用する戦闘」を廃止する。
  - ユニットや設備をマスに配置する1人用TCGへ作り直す。
  - 学習ローグ本編から流用するものはカード名とイラストだけとし、コスト、種別、数値、効果はミニゲーム専用にする。
  - CPUを順番に倒し、勝利するたびに3枚から1枚を選んでデッキに追加できる構成にする。

## 2. 文言の解釈と今回の決定

依頼文の「リプレイ度」は「リプレイごと」、「カード校」は「カード効果」の意図として仕様化する。

- 「もう一度遊ぶ」と敗北後の再挑戦は、いずれも新しいランダム配置を生成する。
- アドバンスモードのステージ1〜50では、そのステージの新駒を1種類登場させる。クリア後、その駒をフリー対局の抽選対象として永続解禁する。
- ステージ51以降は、同じユニーク駒を2枚置くだけではなく、異なるユニーク駒を2種類以上登場させる。
- ミニ将棋は5×5盤を維持する。アドバンスモードも同じ盤サイズとし、駒の種類と盤面の組み合わせで難易度を上げる。
- 配置型TCGの1ランはCPU戦10戦とする。敗北するとそのランは終了し、初期デッキから再開する。
- CPU戦1〜9の対戦相手は、放課後ポーカーのライバルからランごとに重複なしで9人をランダム抽選する。10戦目は必ず「校長ゲンダ」とする。

## 3. 現行実装の確認結果

### 3.1 共通構成

- 実装本体は `src/components/TriviaMiniGameScreen.tsx` 内にある。
- `src/miniGameCategoryConfig.ts` で雑学カテゴリとミニゲーム画面を紐付けている。
- `src/miniGameConfig.ts` にミニゲーム一覧用の名称、説明、画面IDがある。
- 日本語、英語、ひらがな表示と、タッチ、マウス、キーボード、コントローラー操作の維持が必要である。

### 3.2 ミニ将棋

- 現在の登場駒は王/玉、飛、角、金、銀、歩の6種類で、初期配置は毎回固定である。
- 駒を選ぶと選択中の駒だけが青系で表示され、合法手のマスは表示されない。
- 成りは相手陣へ移動した時の強制自動成りである。
- 玉を実際に取ると勝利する実装で、王手放置や王手がかかる着手を禁止していない。
- 龍の動きは「金の動き＋斜め1マス」となっており、本来の「飛車の縦横スライド＋斜め1マス」と異なる。
- 馬も後方へ1マスの直交移動が欠けている。
- CPUは「取れる駒がある手」を優先し、候補先頭を選ぶ簡易実装である。

### 3.3 学習ローグTCG

- `CARDS_LIBRARY` から本編のカード定義を複製し、本編と同じダメージ、ブロック、弱体、びくびく、ドロー等のフィールドを使っている。
- 手札5枚、エナジー3、プレイヤー/CPU HP45の1戦だけで、盤面配置や勝利後のデッキ構築はない。
- CPUには手札、デッキ、配置判断がなく、ターン終了時に予告数値のダメージを与えるだけである。

## 4. ミニ将棋 改善仕様

### 4.1 モード構成

ミニ将棋開始時に次の2モードを選択する。

| モード | 内容 | 進行保存 |
| --- | --- | --- |
| スタンダード | 標準駒だけの5×5将棋。毎回ランダム配置 | 勝数、最高連勝、遊んだ配置シード数 |
| アドバンス | ユニーク駒50種が段階登場する全100ステージ | 最高到達、各ステージのクリア、解禁駒、最少手数 |

初回はスタンダードを初期選択とし、アドバンスは常時選択可能とする。モード自体の解禁条件は設けない。

### 4.2 駒選択時の移動範囲表示

自分の盤上駒を選択した直後に、合法手を同期計算して盤上へ表示する。

| 表示 | 意味 |
| --- | --- |
| シアンの太枠 | 選択中の駒 |
| 青の円点 | 空いている移動可能マス |
| 赤の角マーク | 相手駒を取れるマス |
| 紫の点線 | 特殊移動、跳越、入れ替えなどの候補 |
| 黄の下向き矢印 | 持ち駒を打てるマス |
| 半透明の禁止記号 | 動き自体は合うが、王手放置、二歩、行き所のない駒等で不可のマス |

- 色だけに依存せず、形状と `aria-label` で意味を区別する。
- 合法手が0の駒を選んだ場合は「この駒は現在動かせません」と表示する。
- 持ち駒選択時も同じ表示系を使い、二歩等の禁止理由を確認できるようにする。
- 候補のないマスを押しても選択を解除せず、短いエラー表示と音で理由を伝える。

### 4.3 駒の長押し説明

- タッチ/マウス: 駒を450ms長押しすると駒詳細モーダルを開く。10px以上移動した場合は長押しをキャンセルする。
- キーボード: 駒へフォーカスを合わせ、`I` または `?` で開く。
- コントローラー: 駒へフォーカスを合わせ、`Y` で開く。画面下部に操作案内を表示する。
- フォーカス/カーソルが使えない場合に備え、盤面の「駒の動き一覧」ボタンからも同じ説明を開けるようにする。
- 長押しが成功した時は通常の駒選択を発火させない。

駒詳細モーダルには次を表示する。

- 駒名、駒文字、標準/ユニークの区分
- 相手側から見た場合も含む移動図
- スライド、跳越、捕獲、特殊能力の文章説明
- 成り先と成り条件、または「この駒は成らない」
- 打ち駒時の制限
- 現在の盤面で移動できるマス数

モーダル表示中は手番を進めず、閉じた時に元の駒へフォーカスを戻す。

### 4.4 標準駒の正しい動き

「前」は駒の所有者から見た相手陣方向を表す。スライド駒は、味方駒を通過できず、最初の相手駒を取った位置で停止する。

| 駒 | 未成 | 成駒 |
| --- | --- | --- |
| 王/玉 | 縦横斜めへ1マス | 成らない |
| 飛車 | 縦横へ任意距離 | 龍: 飛車の動き＋斜めへ1マス |
| 角行 | 斜めへ任意距離 | 馬: 角行の動き＋縦横へ1マス |
| 金将 | 前、左右、後ろ、前方斜めへ1マス | 成らない |
| 銀将 | 前と3つの斜めへ1マス | 成銀: 金将と同じ |
| 桂馬 | 前方2マス＋左右1マスの2か所へ跳越 | 成桂: 金将と同じ |
| 香車 | 前方へ任意距離 | 成香: 金将と同じ |
| 歩兵 | 前方へ1マス | と金: 金将と同じ |

スタンダードのランダム配置では、従来の6種に桂馬と香車を加えた標準8種を候補とする。

### 4.5 標準ルールの補正

- 自分の王が取られる状態のままになる着手は不可とする。
- 玉を実際に取る処理ではなく、王手を回避できる合法手が0になった時点で詰みとする。
- 成りは「移動元または移動先が相手陣」の時に選択可能とする。
- 歩、香が最終段へ進む場合と、桂が最終から2段目へ進む場合は強制成りとする。
- 持ち駒は取った時に未成へ戻す。
- 二歩と行き所のない駒を禁止する。打ち歩詰めは初期実装でも禁止する。
- 同一盤面の無限反復を防ぐため、連続王手の千日手は王手側の負け、それ以外の千日手は引き分けとする。

### 4.6 初期配置のランダム生成

プレイ開始ごとにシードを生成し、同じシードなら同じ配置とCPU判断を再現できるようにする。`Math.random()` を盤面ロジックから直接呼び出さない。

生成後は次の条件をすべて検証し、満たさなければ別シードで再生成する。

- 両陣営に王/玉が必ず1枚ずつある。
- 初期状態でどちらの王にも王手がかかっていない。
- 両者に最低1手以上の合法手がある。
- 片側の盤上駒は王を含む6〜9枚とする。
- 標準駒のみの場合、駒価値差を歩2枚相当以内にする。
- 先手が1手で玉を詰ませる配置を除外する。
- アドバンス駒の必須種類数と、ステージ別の駒価値上限を満たす。
- 後手側は単純な左右反転に固定せず、価値条件内で別抽選する。
- 直前に遊んだ盤面と「両陣営の駒種別ごとの枚数」または「全駒の配置」が同一な候補は破棄する。これにより、通常のリプレイで駒種と配置の両方に変化を保証する。

結果画面にシードと「この盤面を再現」を用意するが、通常の「もう一度遊ぶ」は必ず新しいシードを使う。

#### ユニーク駒の実装制約

- 特殊能力でも王手放置はできない。
- 強制移動、押し出し、引き寄せの移動先が盤外または占有済みなら、その能力は使えない。
- 「もう1手」の効果は重複しない。1手番の着手数は最大2回とする。
- 「獅」の2段階移動の途中で王手状態を作っても、最終位置で王手放置でないことを検証する。
- 価値、CPU評価、ステージ配置上限はデータに分離し、プレイテストで変更可能にする。
- 長押し説明には「移動」「取る時」「取られた時」「周囲への効果」を分けて表示する。

### 4.8 100ステージ構成

| ステージ | ユニーク駒の種類数 | 主な内容 |
| --- | ---: | --- |
| 1〜10 | 1 | 移動のみが異なる入門駒を1種ずつ紹介 |
| 11〜20 | 1 | スライドと跳越の複合駒を1種ずつ紹介 |
| 21〜30 | 1 | 捕獲や入れ替えの特殊駒を1種ずつ紹介 |
| 31〜40 | 1 | 他駒に干渉する駒を1種ずつ紹介 |
| 41〜50 | 1 | 複合能力の上位駒を1種ずつ紹介 |
| 51〜60 | 2 | 異なる解禁済み駒2種を必ず登場 |
| 61〜70 | 3 | 3種の組み合わせと相互作用 |
| 71〜80 | 4 | 4種と強化CPU |
| 81〜90 | 5 | 5種、持ち駒ありで開始する変則局 |
| 91〜99 | 6 | 6種、高評価CPU、厳しい駒価値配分 |
| 100 | 8 | Stage 50の「宿」を含む8種。クリア後に全駒フリー対局を解禁 |

- ステージ1〜50では新駒を紹介するルールカードを初回のみ表示する。
- 各ステージの盤面は条件内でランダム生成し、再プレイしても同じ配置に固定しない。
- 未クリアの次ステージまで選択可能とし、クリア済みステージはいつでも再挑戦可能とする。
- ステージクリア時に新駒図鑑、最少手数、クリア回数を更新する。

### 4.9 CPU

- CPUはすべての標準駒とユニーク駒に対し、プレイヤーと同じ合法手生成関数を使う。
- 難易度は先読み深度、候補数、評価のゆらぎで調整し、CPUだけに例外ルールを与えない。
- 評価要素は詰み、王の安全、駒得、動けるマス数、成り、ユニーク能力の発動価値とする。
- 思考中は表示を出し、メインスレッドを長時間占有しない。

## 5. 配置型TCG 新ルール

### 5.1 ゲームの基本構成

- 1人用、プレイヤー対CPUのターン制カードゲームとする。
- 1ランはCPU10人との連戦で、10人目を倒すとランクリアとする。
- 戦闘ごとにHP、手札、山札は初期化する。勝利時に選んだカードはラン中のデッキに永続追加される。
- 初期デッキは20枚、初期手札は5枚、手札上限は9枚、初期ライフは20とする。
- 先攻はプレイヤーとし、先攻1ターン目だけ通常ドローを行わない。
- 資源は「スクールポイント（SP）」とし、毎ターン全回復する。上限は1から始まり、自分ターン開始時に1ずつ増え、最大8とする。

### 5.2 盤面

両プレイヤは3レーンを持ち、各レーンにユニット1枚とサポート1枚を置ける。

```text
CPU:       [サポート][サポート][サポート]
           [ユニット][ユニット][ユニット]
                 左        中        右
           [ユニット][ユニット][ユニット]
プレイヤー: [サポート][サポート][サポート]
```

- ユニットは正面の相手ユニットを攻撃する。正面が空なら相手ライフを攻撃する。
- 配置したターンのユニットは攻撃できない。「速攻」を持つ場合だけ即座攻撃できる。
- 各ユニットは1ターンに1回攻撃できる。攻撃時は両ユニットが同時に攻撃力分のダメージを与え合う。
- ユニットのダメージは盤面にいる間継続し、残り体力が0以下になったら捨て札へ送る。
- ユニットは自分ターンに1回、空いている隣のレーンへ移動できる。移動したターンは攻撃できない。
- 同じレーンのサポートは、特記がない限りそのレーンのユニットだけを強化する。

### 5.3 カード種別

| 種別 | 使い方 | 主な専用フィールド |
| --- | --- | --- |
| ユニット | 空きユニットマスに配置 | `spCost`, `attack`, `health`, `traits`, `deployEffect`, `attackEffect`, `defeatEffect` |
| サポート | 空きサポートマスに配置し、継続効果を持つ | `spCost`, `durability`, `auraEffect`, `breakEffect` |
| イベント | 対象のマスまたはカードを選んで即時解決し、捨て札へ送る | `spCost`, `targets`, `eventEffect` |

カードの表示名とイラストパスは `CARDS_LIBRARY` の対応カードから参照する。それ以外のフィールドは `MiniTcgCardDefinition` として完全に分離する。

```ts
type MiniTcgCardDefinition = {
  id: string;
  sourceCardId: string; // 名称とイラストの参照だけに使う
  kind: 'UNIT' | 'SUPPORT' | 'EVENT';
  spCost: number;
  attack?: number;
  health?: number;
  durability?: number;
  rulesText: LocalizedText;
  effects: MiniTcgEffect[];
  rewardTier: 'STARTER' | 'COMMON' | 'UNCOMMON' | 'RARE';
};
```

本編の `damage`, `block`, `weak`, `vulnerable`, `energy`, `draw`, `playCopies` 等をミニTCGのルールとして直接読み込んではならない。

初期カードプール200種の `Mini ID`、`sourceCardId`、コスト、数値、専用効果、流用イラストは、[配置型TCG カードカタログ200](trivia-placement-tcg-card-catalog-200.md) を正とする。

### 5.4 ターン進行

1. ターン開始: SP上限を1増やして全回復し、カードを1枚引く。
2. メイン: カード使用、ユニット配置、移動、攻撃を好きな順で行う。
3. ターン終了: 「ターン終了」を押し、終了時効果を解決する。
4. CPUターン: CPUも同じコストと配置ルールで行動する。処理途中は行動対象と効果を短いアニメーションで示す。

同時発動は「ターンプレイヤーの効果 → 非ターンプレイヤーの効果 → 左レーンから右レーン」の順で解決する。ランダム対象が必要な時は、ランシード由来の擬似乱数を使う。

### 5.5 勝敗

- 相手ライフを0にすると勝利する。
- 自分ライフが0になると敗北する。
- 山札がない状態でドローすると、その回数に等しい疲労ダメージ（1、2、3…）を受ける。捨て札は山札に戻さない。
- 同時に両者のライフが0以下になった場合は、現在のターンプレイヤーの敗北とする。

### 5.6 CPU連戦

| 戦闘 | 対戦相手 | デッキ・思考テーマ |
| ---: | --- | --- |
| 1 | 抽選ライバル1 | 配置、ユニット攻撃 |
| 2 | 抽選ライバル2 | サポートと耐久値 |
| 3 | 抽選ライバル3 | 速攻と空きレーンの防衛 |
| 4 | 抽選ライバル4 | イベントと交換 |
| 5 | 抽選ライバル5 | サポート横断強化と対処 |
| 6 | 抽選ライバル6 | 登場時・退場時効果 |
| 7 | 抽選ライバル7 | 配置制限とSP増減 |
| 8 | 抽選ライバル8 | 複数レーンの連携 |
| 9 | 抽選ライバル9 | 高度な配置交換 |
| 10 | 校長ゲンダ（固定） | それまでの全ルール |

#### 対戦相手とイラストの流用

- ラン開始時に `POKER_RIVALS` 24人と `POKER_ENDLESS_RIVALS` 36人を統合した60人を候補にする。
- `endless_rival_principal_genda` はランダム候補から除外し、残り59人から異なる9人をランシードで抽選する。
- 10戦目は `endless_rival_principal_genda` / 「校長ゲンダ」へ固定する。
- CPUの表示名は放課後ポーカー側のライバル名をそのまま使い、TCG用の別名に変更しない。
- 立ち絵は `public/sprites/after-school-poker-rivals-{01..08}.webp` と `public/sprites/after-school-poker-endless-rivals-{01..12}.webp` を新規複製せず直接流用する。
- ポーカーと同じ `getPokerRivalPortraitStyle` 相当の切り出し共通関数を使い、3×3シートの行でライバル、列で表情3種を選ぶ。
- TCGでは表情0=通常、1=ライフ10以下または不利盤面、2=敗北決定とする。
- ライバルIDの9人分の配列はラン開始時に確定・保存し、アプリ再起動や同じランの戦闘再開で再抽選しない。

- CPUは戦闘別の固有デッキと思考重みを持つが、プレイヤーと異なる隠し資源は持たない。
- 戦闘1〜3は直近の高得点手に大きめのランダム幅を入れ、4〜7は1ターン、8〜10は2ターンの候補を評価する。
- CPUの手札は枚数だけ表示し、カード内容は使用まで非公開とする。山札と捨て札の枚数は公開する。

### 5.7 勝利後の3枚選択

1. CPU撃破演出の後、現在の戦闘数に合わせたレアリティ重みで3枚を生成する。
2. 3枚はすべて異なるカードとし、同一の `MiniTcgCardDefinition.id` を重複表示しない。
3. 選択中は名前、イラスト、種別、SP、数値、ミニTCG専用効果文、現在のデッキとの相性タグを表示する。
4. 1枚選ぶと即座デッキに追加し、ラン状態を保存して次のCPU戦へ進む。
5. 選択のスキップはできない。カード一覧は選択前に確認できる。

カードプールは初期実装で200種とする。そのうちNo.1〜20の20種を初期デッキへ各1枚入れ、No.21〜200の180種を勝利報酬プールにする。個別定義は[配置型TCG カードカタログ200](trivia-placement-tcg-card-catalog-200.md) を参照する。

### 5.8 ラン保存と再開

次の状態をローカル保存する。

- 仕様バージョン
- ランシード
- 抽選済みのCPUライバルID 9人分と、最終戦の校長ID
- 次のCPU番号
- 現在のデッキのカードID一覧
- 獲得済み報酬履歴
- 勝数、最高連勝、10戦クリア回数
- 戦闘中か、報酬選択中か、次戦開始前かのフェーズ

アプリ終了が戦闘中だった場合は、不整合な中間状態を復元せず、そのCPU戦の開始時から同じデッキとシードで再開する。報酬選択中なら同じ3枚を再表示する。

## 6. UI・操作・アクセシビリティ

### 6.1 ミニ将棋

- 縦画面と横画面の両方で盤の各1マスを最低44×44 CSS pxの操作領域にする。
- ステージ番号、登場中のユニーク駒、手番、王手状態、持ち駒を常時確認できる。
- 相手駒全体をCSSで回転する場合も、長押しモーダルの文字と移動図はプレイヤー向きで表示する。
- 「元に戻す」は搭載しない。合法手確定後にだけ手番を進める。

### 6.2 配置型TCG

- 手札のカードを選ぶと、配置/使用可能なマスを強調表示する。
- ドラッグ＆ドロップと「カード選択 → マス選択」を両方実装し、ドラッグ専用にしない。
- カード長押しまたは詳細ボタンで、拡大イラストとミニTCG専用効果を表示する。本編の効果文を表示しない。
- 盤面の変化はアニメーションだけに依存せず、攻撃値、残り体力、攻撃済み、新着、対象中を静的表示でも区別する。
- コントローラーは方向キーで手札/盤面を移動、`A` で決定、`B` でキャンセル、`X` でターン終了、`Y` で詳細を開く。

### 6.3 共通

- 新しい表示文は日本語、英語、ひらがなの対象とする。
- 初回ルールモーダルだけでなく、ヘッダーのヘルプから再表示できる。
- `prefers-reduced-motion` 時は駒移動、カード配置、CPU操作の演出を短縮し、点滅を使わない。
- 効果音を出せない状態でも、不正操作、王手、カード発動、勝敗が視覚的に分かるようにする。

## 7. データと保存

既存セーブへの後方互換性を保ち、次の独立したバージョン付きキーを追加する。実際のキー名は `storageService` の命名規則に合わせる。

- 将棋進行: `learning_rogue_trivia_shogi_progress_v1`
- 将棋統計: `learning_rogue_trivia_shogi_stats_v1`
- 配置型TCGラン: `learning_rogue_placement_tcg_run_v1`
- 配置型TCG統計: `learning_rogue_placement_tcg_stats_v1`

保存データは読み込み時にスキーマ検証し、不正な駒ID、カードID、ステージ番号がある場合は安全な初期値へフォールバックする。ひとつの破損で他方のミニゲームデータを削除しない。

## 10. 検証計画

### 10.1 将棋ユニットテスト

- 標準8種と全成駒について、盤中央、端、角、味方駒に遮られた状態、相手駒がある状態の合法手をテーブルテストする。
- 龍が縦横の盤端まで動け、斜めは1マスだけ動けることを固定テストする。
- 馬が斜めの盤端まで動け、前後左右へ1マス動けることを固定テストする。
- 王手放置、二歩、打ち歩詰め、行き所のない駒、強制成りをテストする。
- ユニーク駒50種につき、最低1件の正常系と1件の境界/禁止系を用意する。
- 1,000シード以上の初期配置を生成し、不正配置、即詰み、生成無限ループがないことを確認する。
- ステージ51〜100の全生成結果に異なるユニーク駒が2種類以上含まれることを確認する。

### 10.2 配置型TCGユニットテスト

- SP増加/回復、ドロー、配置、新着、移動、攻撃、反撃、破壊、疲労ダメージを検証する。
- 同時発動順と、同時にライフ0になる場合の勝敗を固定テストする。
- すべての `sourceCardId` が `CARDS_LIBRARY` に存在し、名称とイラスト以外の本編効果フィールドを参照していないことを検査する。
- 200種の `Mini ID`、`sourceCardId`、名前がそれぞれ重複せず、全件にミニTCG専用効果があることを検査する。
- 報酬3枚に重複がなく、1枚選択後にデッキ枚数が1増えることを確認する。
- CPUもプレイヤーと同じSP、カード、配置、攻撃制限を通ることを検査する。
- 100以上のランシードで、先頭9戦のライバルに重複がなく、校長ゲンダが含まれず、10戦目が必ず校長ゲンダになることを確認する。
- 抽選した9人と校長の全立ち絵が、放課後ポーカーと同じシート、行、表情列を解決できることを確認する。
- 戦闘中のアプリ終了後は戦闘開始状態、報酬選択中の終了後は同じ3枚へ戻ることを確認する。

### 10.3 UI・統合テスト

- タッチの短押しと長押しが二重発火しない。
- 将棋の移動候補と実際に着手できるマスが常に一致する。
- 配置型TCGはドラッグを使わなくても全操作できる。
- キーボードとXboxコントローラーだけでモード選択、対局/戦闘、詳細表示、報酬選択、結果画面を完遂できる。
- 日本語、英語、ひらがなでレイアウトが破綻しない。
- 縦画面と360×800、横画面と1280×720を最低確認対象とする。
