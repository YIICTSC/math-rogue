# エンドレスモード：50章・1章15F・5章ごとボス改訂仕様

更新日：2026-09-02

## 1. この資料の位置づけ

エンドレスモードのマップ構造、ボス間隔、ギミック進捗、マップ背景の扱いを整理する仕様検討資料。

この版では、前回指定された「全50Fを50章として扱う」を維持し、さらに「1章＝15F」を適用する。そのため、エンドレスモードの総進行量は **50章×15F＝750F相当** になる。

この仕様は実装済みである。エンドレスでは15Fの章マップを都度生成し、C05、C10…C50の終端だけをボスにする。

## 2. 決定事項

| 項目 | 改訂後 |
|---|---|
| 章数 | 50章（C01〜C50） |
| 1章の長さ | 15F。通常モードのAct1と同じ長さ・読みやすさ |
| 総進行量 | 750F相当 |
| ボス章 | C05、C10、C15、C20、C25、C30、C35、C40、C45、C50 |
| ボス到達F | 累計75F、150F、225F、300F、375F、450F、525F、600F、675F、750F |
| ボス間隔 | 5章＝75F。4章分の準備＋5章目のボス |
| マップ表示 | 1章ごとに15Fのマップを生成・表示し、章終了後に次の15Fマップへ切り替える |
| 画像の役割 | マップUIの背面に置く各編の背景デザイン。ノード・経路・アイコンは画像に描かない |

### 2.1 通常モードとの章番号の分離

- 通常モードは既存どおりAct1〜Act4で進行する。各Actの15F目にボス戦がある。
- 通常モードのAct4をクリアしても、エンドレスの章番号へ「4」を引き継がない。
- エンドレス開始時は必ず **エンドレス第1章（C01）** とする。
- エンドレス画面では通常モードのAct番号と区別して、「エンドレス 第N章」と表示する。
- エンドレス内で章を進めた場合だけ、C02、C03…と増加させる。

### 2.2 50F固定との関係

「50Fを50章」と「1章＝15F」は同時に採用すると、50F固定ではなく750F相当になる。50F固定のまま1章15Fにすることは、5章分の長さが75Fになるため成立しない。本仕様では、直近の指定を優先して **50章・750F相当** とする。

## 3. マップは1枚ではなく、15Fマップを繰り返す

### 3.1 基本フロー

```text
C01の15Fマップ → C02の15Fマップ → C03の15Fマップ → C04の15Fマップ
                                                                  ↓
                                                        C05の15Fボスマップ
                                                                  ↓
C06の15Fマップ → C07の15Fマップ → C08の15Fマップ → C09の15Fマップ
                                                                  ↓
                                                        C10の15Fボスマップ
```

- 画面上にC01〜C50を一度に並べる縦長マップは作らない。
- 各章は通常Act1と同じ15Fマップとして生成する。
- C01〜C04などの非ボス章は、15F終端を章移行ノードにする。
- C05、C10などのボス章だけ、15F終端をボスノードにする。
- 章をまたいでも、同じ5章区間内ならギミック進捗を保持する。
- ボス報酬を確定した時点で区間進捗をリセットし、次の区間を開始する。

### 3.4 章クリア結果と次章開始

- 各章の最終戦（非ボス章は15Fの通常戦闘、ボス章は専用ボス）後に、通常モードと同じ章クリア結果画面を表示する。
- 章クリア結果には、エンドレス第1章〜第50章に対応した固有の深層記録を表示し、黒帳機関の存在を段階的に示唆する。
- 報酬処理後、未解禁の追加カードがあれば1枚を解禁し、章クリア結果画面でカードを表示する。
- 章結果から次章へ進む時にHPを全回復し、次の15Fマップと章番号へ移行する。
- 大ボス章のみ、章結果画面の後に従来どおり休息・強化・特別ショップを選べる。
- 第50章は最終ボス演出の後に第50章の章クリア結果を表示し、結果画面からタイトルへ戻る。

### 3.2 1章15Fの構造

現在の通常マップが持つ15Fの視認性とテンポを基準にする。画像にマップ構造を焼き込まず、構造は既存のノードUIで表現する。

| 15F | ボス章はボス。それ以外は章移行ノードまたは章末イベント |

### 4.3 通常章と同じ進行方向

3枚とも、通常モードの現行マップ背景に合わせて、画面の下から上へ進む構図にする。

- 下部：校門・入口。エンドレス章の開始地点
- 中央：校庭、校舎、講義棟、図書館、研究室などの中間領域
- 上部：最奥の校舎・塔・屋上施設。ボス戦へ向かう目的地
- 中央の階段・通路・テラスは、ゲーム内のマップノード経路ではなく、進行感を出す背景演出

そのため、プレイヤーは「入口から奥へ進み、最上部のボスへ近づいている」と視覚的に把握できる。ノードの配置やアイコンは従来どおりUI側で重ねる。

### 4.4 画像の仕様

画像は「各編のデザインイメージ」であり、マップデータの図解ではない。

画像に含めるもの：

- 各編を識別できる建築・光・色・材質
- 中央のマップUIを重ねられる余白
- 章の雰囲気を変える背景のバリエーション
- ボス章で使う場合の、背景全体の色調・光量の差分

画像に含めないもの：

- ノード、接続線、分岐ルート
- 戦闘・休憩・ショップ・イベントなどのアイコン
- ボス門、到達マーカー、章番号、F番号
- 文字、ボタン、UIラベル、キャラクター

ノードやアイコンは、現在の `MapScreen` が描画するUIをそのまま使用する。背景画像に焼き込むと、章ごとのランダムマップと一致しなくなるため禁止する。

### 4.5 背景パターンの運用

既存の基準画像と今回作成した15F用画像を合わせ、各編で複数パターンを用意する。今回の追加分は10章単位の深度切替用で、実装時は章番号に対応する画像を選ぶ。

## 5. ボス配置とギミックの共通仕様

### 5.1 進捗の有効範囲

- ギミック進捗のスコープは、5章区間S01〜S10とする。
- C01〜C04で達成した条件をC05ボスへ持ち越せる。
- 章をまたいでも、同じ区間なら連続成功・カード種類・学習成功数を保持する。
- 不正解は通常の累計成功数を減らさない。
- 不正解は「連続成功」だけを0へ戻す。
- ボス撃破・報酬確定後は、次区間の進捗を0から始める。
- 達成済みの過去ボス記録は周回中保持し、マップ画面から確認できる。

### 5.2 学習判定の扱い

- 同じ単元・同じ `subjectId` の成功だけでも達成可能にする。
- 「異なる分野」「異なる科目」を必須条件にしない。
- `subjectId` が未定義でも、単純な学習成功回数は加算する。
- リトライ成功は、再提出専用ギミック以外では通常成功として二重計上しない。
- 1章につき最低1回、区間全体で最低5回の学習機会を保証する。進捗はボス戦だけでなく、区間内の通常戦闘後の学習判定でも加算する。
- 3回以上の条件は、同じ単元の成功を許可する。

### 5.3 カード判定の扱い

カード種類条件で参照するのは次の3種類だけとする。

- `ATTACK`
- `SKILL`
- `POWER`

問題データに存在しない `attributeId`、色、属性、別分野などは、必須ギミック条件に使用しない。

## 7. マップ画面の表示

### 7.1 現在の章

マップ画面の上部には、全体の累計Fだけでなく、章内の位置を表示する。

```text
エンドレス　第06章　7F / 15F
累計進行　82F / 750F相当
次のボス　第10章　累計150F
```

「F」は章内のフロア、「章」はエンドレス全体の進行単位として分離する。

### 7.2 ギミック表示文

ギミックを達成した瞬間、既存のギミック表示文の末尾に必ず達成状態を追記する。

```text
ギミック：S02区間内に学習判定へ3回成功。同じ単元でよい。（達成済み）
```

ボス撃破後は、次のボス表示とは別に直近記録を残す。

```text
直近の達成記録：C10 三相試験体トライクス

```

未達成の場合は、現在値を表示する。

```text

```

## 8. 実装変更の要点

### 8.1 マップ生成

- `generateDungeonMap` のエンドレス時も `MAP_HEIGHT = 15` を使う。
- `endlessChapter` を受け取り、1回の生成対象を1章に限定する。
- 非ボス章の15F終端は、ボスではない章移行ノードにする。
- ボス章の15F終端だけをボスノードにする。
- ノードIDには章番号を含め、C01とC02のノードが衝突しないようにする。
- 章移行時に次の15Fマップを生成し、長大な750F配列を一度に描画しない。

### 8.2 状態データ

実装では既存の状態名を活用し、`act` と `endlessFloor` を現在の章番号、`floor` をその章内の15Fマップの階層として分離する。累計Fと区間番号は次の式で導出できる。

```ts
type EndlessChapterState = {
  chapter: number;          // 1〜50
  chapterFloor: number;     // 0〜14。表示時は1〜15F
  globalFloor: number;      // (chapter - 1) * 15 + displayedFloor
  segment: number;          // Math.ceil(chapter / 5)
  bossChapter: number;      // 次の5の倍数
};
```

- `act` / `endlessFloor` はC01〜C50の章番号。
- `floor` は現在の15Fマップ用。
- `globalFloor` は必要な表示・記録で `(chapter - 1) * 15 + floor` から導出する。
- `segment` はギミック進捗の保存範囲用。
- 既存のボスID・報酬IDは、既存セーブとの対応を壊さないよう別名または移行表を用意する。

### 8.3 ボス定義

既存のボス定義が持つ `floor: 5 | 10 | ... | 50` は、旧実装ではフロア番号として使われている。改訂後は意味を章番号へ寄せ、次のように扱う。

- `bossChapter`: 5、10、15、…、50
- `globalFloor`: 75、150、225、…、750
- `legacyFloor`: 旧セーブ・既存報酬・旧画像ファイル対応用。段階的に廃止

ボス画像ファイルが旧フロア名を使用している場合は、ファイル名を一度に変更せず、定義側の参照を章番号から対応するボス順へ変換する。

### 8.4 ギミック進捗

```ts
type EndlessGimmickProgress = {
  segment: number;
  progress: number;
  target: number;
  achieved: boolean;
  streak?: number;
  learningCount?: number;
  cardTypes?: string[];
  phases?: number[];
  lastSubjectId?: string;
  lastBattleId?: string;
};
```

- `segment` が変わったら新しい進捗を作る。
- `streak` は章をまたいで保持するが、不正解で0にする。
- `learningCount` と `cardTypes` は区間終了まで保持する。
- 最終ボスの4フェーズはHP演出として扱い、戦闘後に提示される3問の学習成功数をギミック条件にする。
- `lastBattleId` を使い、「連続カード」は同一戦闘内だけで判定する。
- 学習成功数の条件は `subjectId` の種類数ではなく、成功回数を記録する。
