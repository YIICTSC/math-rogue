# スポーツ4競技の開始画面・アクション練習

2026-11-13。野球・サッカー・バレーボール・大運動会が対象。

## 画面と導線

| 入口 | 次の画面 | 開始まで |
| --- | --- | --- |
| ひとりで遊ぶ | モード・チーム／選手・ルール・操作説明のタブ | 単元選択 → 学習3問 → 試合 |
| プラクティス（大運動会を除く） | イラスト付き練習メニュー | 単元選択 → 学習3問 → 選んだ練習 |
| 観戦する | CPU観戦の設定 | 観戦開始 |
| オンラインの部屋を作る | 名前 → 単元選択 → 参加者・チーム・設定の待機室 | 全員準備完了 → 学習3問 → 試合 |
| 招待に参加する | 名前・6桁コード → 待機室 | ホストの開始 → 学習3問 → 試合 |

タイトルは競技イラストを背景に、遊び方3択（大運動会は2択）とオンライン2択を配置。設定画面は「次へ」の連打をなくし、必要な項目だけをタブで変更できる。既定設定なら最初のタブから開始可能。開始ボタンと選択内容は固定フッターに表示する。

デスクトップは左にモードイラスト、右に設定。縦画面では設定を全幅に、低い横画面では左右配置を維持してカードを4列にする。長い選手一覧・操作説明は設定枠内でスクロールし、全画面の縦スクロールや開始ボタンの画面外への押し出しを防ぐ。待機室の参加者詳細は開閉式。

## 練習内容

| 競技 | 練習 |
| --- | --- |
| 野球 | 打撃・投球・守備・ホームラン挑戦（既存の10打席練習を維持） |
| サッカー | 移動／ダッシュ・シュート・パス・ロングパス・切り返し・タックル・必殺シュート・選手交代 |
| バレーボール | サーブ・レシーブ・トス・スパイク・ブロック・飛び込み・必殺サーブ・移動／ジャンプ |

新しい16ドリルは各5回、1回12秒。操作案内・残り時間・成功数・再試行を表示する。成功／失敗の後、次の練習状況へ自動で戻す。成功数と練習名を競技記録に残す。途中の「この練習をやり直す」は現在の1回をリセットし、成功演出中の二重加算は防ぐ。

実際の競技エンジンを使い、ゴール・パス完了・奪取・レシーブなどの実イベントで判定する。CPUの操作だけでは成功にならない。必殺サーブは必殺球の準備と実際の発射を確認する。両チーム・通常ルール・操作補助なしでも成立する配置にする。選んだ主人公を練習の操作選手に割り当てる。オンライン対戦にはドリル設定を持ち込まない。

ロングパスは距離に合わせた滞空時間・速度に調整し、近い味方の頭上を大幅に通過する挙動も修正。

## イラスト

ImageGenで競技ごとに8枚、計24枚のオリジナル素材を生成。野球の4練習・対戦・観戦、サッカーとバレーのアクション選択に使用する。1枚ごとにWebP化し、アトラスの不要な領域が混ざらないよう個別ファイルを表示する。

- 配信: `public/sprites/academy-sports/modes/`
- 生成記録・SHA-256: `assets/academy-sports/mode-art.json`
- Web／Androidの素材一覧へ登録。部分チェックアウトでは `generate-web-asset-manifest.mjs --update-prefix sprites/academy-sports/modes/` とAndroid版の同オプションで対象ディレクトリのみ更新し、他の素材を落とさない。

## 検証

- `pnpm run test:academy-sports:practice`: 16ドリル×両チームの成功／無操作失敗、5回の完走、通常ルール・操作補助なし、主人公と通常試合の分離。
- `pnpm run test:academy-sports:preparation:browser`: 実3D描画、4競技、1280×720／390×844／844×390／320×568。タイトル、設定4タブ、ホスト作成・招待、単元選択と3問、練習HUD・結果、開始ボタンとカードのクリップを検査。
- 既存のルール・オンライン・アクション演出試験、および実WebRTC接続による待機室から試合・再戦までの操作確認。

スマホの検証はChromiumでの画面サイズ・タッチ操作検証。実機iOS確認を意味しない。
