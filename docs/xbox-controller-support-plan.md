# Xboxコントローラー対応 実装方針

画面別の進捗確認には [Xboxコントローラー対応 画面別チェックリスト](./xbox-controller-screen-checklist.md) を使用する。

## 目的

学習ローグ内の各ゲームを、Xboxコントローラーだけで開始から終了まで操作できるようにする。

通常の選択画面まで一律にボタンショートカットを増やすのではなく、画面の役割に応じて次の2方式を使い分ける。

1. **各ゲームのバトル／プレイ画面**では、現在の通常バトル画面と同様にXboxボタンのショートカットを配置する。
2. **ゲーム内の選択肢画面**ではショートカットを追加せず、画面を開いた時の初期フォーカスだけを設定する。

## 確定事項

- 対応順は、通常ローグ画面を先に完了し、その後ミニゲームへ進む。
- Xboxコントローラー接続中は、選択画面の表示時に左上の有効なゲーム内選択肢へ初期配置する。
- Xboxボタンのショートカット表記は、コントローラー接続中だけ表示する。

## 対象範囲

### 対象

- 通常バトルおよび各モード固有のバトル画面
- ミニゲームの実プレイ画面
- ゲーム進行中に表示されるカード、行動、報酬、ルート、キャラクターなどの選択肢
- ゲーム内モーダルに表示される選択肢

### 対象外

- 設定画面
- ヘルプ、図鑑、クレジット、デバッグ画面などの情報・管理UI
- OS、Electron、ブラウザ側のUI
- テキスト入力そのものをコントローラーに置き換える対応

対象外画面には、この計画による「左上の選択肢への初期配置」を適用しない。既存の共通ナビゲーションが利用できる場合は、その挙動を維持する。

## 共通操作

既存の `src/hooks/useXboxControllerNavigation.ts` を基準とする。

| 入力 | 基本動作 |
| --- | --- |
| 左スティック／方向パッド | フォーカス移動、ゲーム内移動 |
| A | 決定、選択中の操作を実行 |
| B | 戻る、閉じる、キャンセル |
| LB / RB | 前後のタブ・領域への移動、または画面固有ショートカット |
| X / Y / RT | バトル／プレイ画面固有のショートカット |
| START | 決定。ゲーム側にポーズがある場合はポーズを優先 |
| BACK | 戻る、キャンセル |

アナログスティックには、既存値を基準としてデッドゾーンと長押しリピートを適用する。

- 入力しきい値: `0.55`
- 初回リピート待ち: `280ms`
- 連続リピート間隔: `110ms`

## バトル／プレイ画面の仕様

### 基本方針

- 現在の `BattleScene.tsx` を操作感と実装方法の基準にする。
- 頻繁に使う行動には `data-gamepad-shortcut` を設定し、対応ボタンを押した時に直接実行できるようにする。
- フォーカス移動が必要な要素には `data-gamepad-zone` と `data-gamepad-order` を設定する。
- ショートカット対象が無効、非表示、実行不能の場合はクリックしない。
- 同じボタンに複数の対象を割り当てない。状態によって対象が切り替わる場合も、同時に有効になる対象は1つにする。
- 画面上にXboxボタン表記を表示し、コントローラー利用者が割り当てを確認できるようにする。
- 表示するボタン表記と `data-gamepad-shortcut` / `aria-keyshortcuts` の値を一致させる。

### 通常バトルを基準にする割り当て

| ボタン | 通常バトルでの基準動作 |
| --- | --- |
| A | フォーカス中のカード、敵、アイテム、行動を決定 |
| B | 対象選択やモーダルをキャンセル |
| X | アイテム／協力支援領域へ移動。両方ある場合は切り替え |
| Y | ターン終了 |
| LB | アイテム領域、または画面左側の主要な補助行動 |
| RB | 変身、友情コンボなど、その画面の主要な特殊行動 |
| RT | 次の敵を選択し、対象として決定 |

各ゲームに同じ名称の行動がない場合は、プレイ頻度と画面上の位置が近い行動へ割り当てる。ただし、**Yは終了／確定系、Bは取消系**という意味をできる限り維持する。

### ゲームごとの割り当て作業

各ゲームについて、実装前に次を1行の表として決める。

| ゲーム／画面 | A | B | X | Y | LB | RB | RT | 初期フォーカス |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 例: 通常バトル | 決定 | 取消 | アイテム／支援 | ターン終了 | アイテム | 特殊行動 | 次の敵 | 最初の手札 |

行動が存在しないボタンは無理に割り当てない。割り当てのないボタン表記も画面に表示しない。

## ゲーム内選択肢画面の仕様

### 初期位置

- 画面表示時、または選択肢モーダル表示時に、**選択可能なゲーム内選択肢のうち最も左上にある要素**へフォーカスを置く。
- 「左上」はDOM順ではなく表示座標で判定する。原則として `top` が小さいものを優先し、同じ行では `left` が小さいものを優先する。
- 非表示、無効、`aria-disabled="true"`、サイズ0、`aria-hidden="true"` 配下の要素は除外する。
- 左上に説明、戻る、ヘルプなどのUIがあっても、それらは初期位置の候補に含めない。
- 対象候補を明示するため、ゲーム内選択肢に `data-gamepad-initial-choice` を付ける。
- 候補が存在しない場合は、フォーカスを強制移動しない。

### 「初期位置のみ」の意味

- フォーカスを自動設定するのは、対象画面またはモーダルを開いた直後の1回だけとする。
- プレイヤーが移動した後に、再レンダーや選択状態の更新だけで左上へ戻さない。
- 選択肢一覧が遅延表示される場合は、最初に有効な候補が揃った時点で1回だけ設定する。
- 別の画面へ遷移して戻った場合は、新しい表示として再度初期位置を設定してよい。
- マウス、タッチ、キーボード操作中にフォーカスを奪わない。原則としてゲームパッド接続中、または直前の入力がゲームパッドだった場合に適用する。

### 選択肢に含めるもの

- 攻撃対象、カード、技、アイテム
- キャラクター、デッキ、難易度、モード
- マップ上の進行先
- イベントの回答
- 報酬、宝箱、レリック、休憩行動、ショップの商品
- ミニゲーム内のゲーム進行に必要な選択肢

### 選択肢に含めないもの

- 設定項目
- 音量、表示、言語などの環境設定
- ヘルプ、ルール、閉じる、戻るボタン
- デバッグ操作
- 単なる情報表示やツールチップ

## 実装案

### 1. 共通フックの拡張

`useXboxControllerNavigation.ts` に、初期選択肢を取得する共通処理を追加する。

```ts
const INITIAL_CHOICE_SELECTOR = '[data-gamepad-initial-choice]';
```

候補を既存の可視・有効判定に通し、`getBoundingClientRect()` の `top`、次に `left` で並べて先頭を選ぶ。画面／モーダル単位で一度だけフォーカスしたことを記録し、通常の再レンダーでは再適用しない。

画面の識別には、対象ルートへ `data-gamepad-screen="..."`、モーダルへ `data-gamepad-dialog="..."` を付ける方式を推奨する。

### 2. バトル領域の共通化

通常バトル専用になっている `.battle-scene-root` と `battle-*` ゾーンを、各ゲームでも利用できる共通APIへ段階的に広げる。

- 既存の通常バトル挙動は変更しない。
- 各ゲーム固有の操作は、画面ルート内の宣言的な `data-gamepad-shortcut` を優先する。
- キーボードイベントをゲーム操作に変換済みの画面では、二重実行を避けるため「ゲームパッド→キーイベント」と「直接クリック」のどちらを採用するか画面単位で統一する。
- 横並びのカードやボタンには共通のナビゲーションゾーンを設定する。同じゾーン内の左右入力は端で停止し、別の操作列へは上下入力でのみ移動する。ポーカー以外の各ゲームにも同じ規則を適用する。
- ゾーン未設定の画面でも、左右移動は縦方向に重なる同一表示行の要素だけを候補にする。斜め位置の説明・ヘルプ・設定UIへは移動せず、別行へは上下入力で移動する。

### 3. フォーカス表示

- `.gamepad-navigation-active` の時だけ、フォーカス中の要素が明確に分かるリングまたは枠を表示する。
- 背景色だけに頼らず、明度差のあるアウトラインを使用する。
- フォーカス時に要素が画面外なら `scrollIntoView({ block: 'nearest', inline: 'nearest' })` を実行する。

## 実装順序

1. 共通フックにゲーム内選択肢の左上初期フォーカス処理を追加する。
2. 通常バトルの既存操作を回帰テストする。
3. 各バトル／実プレイ画面を棚卸しし、ボタン割り当て表を完成させる。
4. ターン制・カード選択型のゲームからショートカットを導入する。
5. リアルタイム操作型ゲームへ導入する。
6. 報酬、イベント、ルート、キャラクターなどのゲーム内選択画面へ初期候補属性を追加する。
7. 設定・管理UIが初期位置処理の対象外であることを確認する。

## 完了条件

- Xboxコントローラーだけで、対象ゲームの開始、プレイ、結果確認、次画面への遷移ができる。
- 各バトル／プレイ画面に、必要なボタンショートカットと対応する画面表示がある。
- ショートカット表示と実際のボタン動作が一致する。
- ゲーム内選択肢画面を開いた時、最も左上の有効なゲーム内選択肢に初期フォーカスがある。
- 初期フォーカス後、再レンダーによって意図せず左上へ戻らない。
- 設定画面や管理UIでは、ゲーム内選択肢用の初期フォーカスが発生しない。
- 無効・非表示の選択肢がフォーカスまたは実行されない。
- Aの長押しやボタン押下の境界で、1回の入力が二重実行されない。
- マウス、タッチ、キーボードの既存操作を損なわない。
- コントローラーの切断・再接続後も操作を再開できる。

## テスト観点

- コントローラー接続済みで画面を開く
- 画面表示後にコントローラーを接続する
- 方向パッドと左スティックの両方を使う
- 選択肢が1件、複数件、0件、無効項目を含む場合を確認する
- 横並び、折り返し、スクロール領域、レスポンシブ表示で左上判定を確認する
- モーダルを開く、閉じる、再度開く
- 選択肢の遅延ロードや状態更新後にフォーカスが戻らないことを確認する
- ショートカット先が無効な時に別要素が誤実行されないことを確認する
- 日本語、英語、ひらがな表示でレイアウトとフォーカスを確認する
- ゲームパッド操作後にマウス／タッチへ切り替え、フォーカス表示が適切に解除されることを確認する
