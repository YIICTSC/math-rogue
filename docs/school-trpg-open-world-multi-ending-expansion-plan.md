# 放課後スクールTRPG オープンワールド級拡張計画

作成日: 2026-08-21
ステータス: 企画・設計（実装前）
対象: `GameScreen.MINI_GAME_SCHOOL_TRPG` / 放課後スクールTRPG

## 1. 企画ビジョン

放課後スクールTRPGを、5場面の短編ダイスゲームから、何度も遊べる長編の学園探索キャンペーンへ拡張する。

目指す体験は、航海図を見ながら未知の場所を選び、仲間と物語を進め、発見したアイテムや知識によって後のルートが変わる探索型ボードゲームである。プレイヤーは「正解の一本道」を探すのではなく、限られた時間・体力・手がかりをやりくりしながら、自分だけの学園史を作る。

本計画では、以下を同時に成立させる。

- 学習ローグ本編の世界とつながる広い学園マップ
- 何度も訪れたくなる多彩なイベントと分岐
- 学習ローグ内の既存ビジュアル素材を活用した戦闘・探索演出
- アイテム、仲間、知識、評判、時間帯が相互に作用するシステム
- 通常エンディング、隠しエンディング、失敗から生まれるエンディングを含むマルチエンディング
- 1プレイを短時間でも進められ、長期的にはキャンペーンとして積み上がる構造

### 1.1 参考にする体験の範囲

「Sleeping Gods」からは、次の体験設計だけを参考にする。

- 大きな地図から次の行き先を選ぶ自由度
- 発見番号／ログによる再訪可能なイベント
- 仲間それぞれの目的と個別ストーリー
- アイテムや状態が別の場所で意味を持つ連鎖
- 一度のプレイで全てを回収しない前提のキャンペーン

固有の世界観、固有名詞、物語、キャラクター、地図、イラスト、ルール文は流用しない。学習ローグの学校・放課後・学年・本編キャラクター・カード世界を基盤に、独自の設定として再設計する。

## 2. 現状と拡張上の課題

### 2.1 現在の実装

現行の `SchoolTrpgGame` は、`TriviaMiniGameScreen.tsx` 内に以下を持つ短編構成である。

- 5つの固定シーン
- 学力、体力、友情、勇気の4能力
- 1d6 + 能力値の判定
- 運命ポイント
- 手がかり、疲労、直前のログ
- 1シーンにつき2択
- 手がかり数と疲労値による実質2種類の結末
- 勝利時にミニゲーム後の3問問題チャレンジへ接続

この実装は、短時間のミッションとしては扱いやすい一方、次の不足がある。

1. 地図上の行き先選択がなく、探索の順序が固定されている。
2. イベントがシーン内の選択肢だけで完結し、再訪や連鎖がない。
3. アイテム、仲間、装備、知識の永続的な組み合わせがない。
4. 戦闘が判定の一部に留まり、既存ミニゲームの視覚資産を十分に活用していない。
5. エンディング条件が少なく、プレイごとの差が小さい。
6. コンテンツを `TriviaMiniGameScreen.tsx` に集約しており、長編化すると保守しにくい。

### 2.2 拡張時の最重要制約

- 本編の学習進行を妨げず、短いセッションでも区切りよく遊べること。
- 問題出題を「罰ゲーム」ではなく、物語上の知識・推理・準備として扱うこと。
- 日本語、ひらがな、英語で、固有の駒名・カード名・アイテム名を意図せず変換しないこと。
- 既存のミニゲーム、課題問題、セーブデータ、モバイル横画面UIを壊さないこと。
- 既存素材を再利用する場合も、アセットの出典・用途・ライセンスを管理すること。

## 3. ゲーム全体像

### 3.1 プレイヤーの基本ループ

```text
キャンペーン開始
  ↓
学園マップを確認
  ↓
行き先・仲間・持ち物を選ぶ
  ↓
探索イベント／会話／調査／戦闘
  ↓
判定・問題チャレンジ・アイテム獲得
  ↓
発見ログと分岐フラグを更新
  ↓
時間・疲労・評判を調整
  ↓
次の場所へ移動、または帰還
  ↓
章の終幕・エンディング判定
```

### 3.2 1プレイの単位

長編でありながら、スマホで遊びやすいように「セッション」を分ける。

| 単位 | 内容 | 目安 |
|---|---|---:|
| 行動 | 移動、調査、会話、休息、使用 | 数秒〜1分 |
| イベント | 1つの発見、判定、戦闘、選択 | 1〜5分 |
| ルート | マップ上の3〜6地点を巡るまとまり | 10〜20分 |
| 章 | 導入、複数ルート、章ボス、後日談 | 30〜60分 |
| キャンペーン | 全5章＋隠し章 | 複数プレイ |

「今日は1ルートだけ」「続きは次回」という中断が自然に成立することを完了条件にする。

## 4. 世界とマップ設計

### 4.1 世界設定

舞台は、放課後になると校舎・校庭・部室棟・旧校舎・町の学習施設がつながり、昼間には見えない「学びの回廊」が現れる学園都市である。学習ローグ本編のカードや敵は、単なるコレクションではなく、各地の記憶・噂・課題・人物の象徴として登場する。

### 4.2 大マップのゾーン

| ゾーン | 主な場所 | 主題 | 主に使う既存素材 |
|---|---|---|---|
| 中央校舎 | 教室、職員室、廊下、階段 | 学校の謎と人間関係 | `backgrounds/learning-rogue/*classroom*`, `*hallway*` |
| 知識区 | 図書室、資料室、理科室 | 調査、暗号、科学 | `*library*`, `*science-lab*`, カードイラスト |
| 運動区 | 体育館、校庭、屋上 | 体力、競技、追跡 | `*gym*`, `*courtyard*`, `battle-gym*` |
| 芸術区 | 音楽室、美術室、放送室 | 音、色、記憶 | `*music-room*`, イベント演出素材 |
| 旧校舎 | 封鎖教室、地下倉庫、時計塔 | 怪異、過去、危険 | ダンジョン背景、暗い廊下素材 |
| 部室棟 | ポーカー部、TCG部、将棋部、囲碁部、麻雀部 | ミニゲーム間の交流 | 各ミニゲームの背景・バッジ・駒・カード |
| 学園外周 | 商店街、駅、公園、地域資料館 | 交換、買い物、地域学習 | `map-campus`, `event-hallway`, 本編イベント素材 |
| 異界ルート | カードの記憶、空中回廊、夢の校庭 | 隠し章、最終分岐 | マジック背景・エンディング背景 |

### 4.3 地図の仕様

- 1枚の大マップを一度に全表示するのではなく、ゾーン単位で切り替える。
- 各ゾーンは5〜9地点を持ち、地点ごとに「未発見」「発見済み」「再訪可能」「危険」「封鎖」の状態を持つ。
- 地点は座標ではなく、接続グラフとして管理する。一本道にせず、最低2つの別ルートを用意する。
- 行き先選択時に、消費する時間、必要なアイテム、危険度、得られる学習タグを表示する。
- 一度訪れた地点は、短いログとアイコンで再訪の価値を示す。
- スマホ横画面では、左に地図、右に地点情報と行動ボタンを置く。縦画面では地図→詳細の順に積む。

### 4.4 章ごとの進行案

| 章 | 仮タイトル | 中心テーマ | 章ボス／大きな問題 |
|---:|---|---|---|
| 1 | 消えた校章 | 仲間集めと基本探索 | 旧校舎の見張り番 |
| 2 | 図書室の航路図 | 情報の信頼性と暗号 | 偽情報を流す記録係 |
| 3 | 雨上がりの競技祭 | 協力、競争、時間管理 | 競技祭の暴走装置 |
| 4 | 時計塔の逆回転 | 歴史、因果、選択の責任 | 時間を止める時計守 |
| 5 | 学園の記憶庫 | 本編との接続、知識の統合 | 記憶庫の管理者 |
| 隠し章 | もう一つの放課後 | 全章のフラグ回収 | プレイヤーの選択が生んだ影 |

## 5. キャラクターとパーティー

### 5.1 主人公の能力

現行4能力を残しつつ、長編向けに「能力値」と「得意タグ」を分離する。

- 学力: 読解、計算、暗号、科学、資料の検証
- 体力: 追跡、運搬、耐久、スポーツ、危険地形
- 友情: 会話、協力、交渉、仲間の回復
- 勇気: 怪異、決断、戦闘開始、禁じられた場所への進入
- 得意タグ: `図書委員`, `運動部`, `放送部`, `カード研究`, `工作`, `地域ボランティア` など

得意タグは数値を直接上げるだけでなく、特定イベントの追加選択肢や安全なルートを開く。

### 5.2 仲間

初期6人、章ごとに加入する仲間6〜8人、隠し仲間4人を目標とする。1回の遠征には主人公＋3人を連れて行く。

仲間ごとに以下を持つ。

- 個別目的
- 好きな場所と苦手な場所
- 戦闘役割
- 探索アビリティ
- 絆レベル
- 個別イベントチェーン
- 章終盤の離脱／成長／告白／和解分岐

仲間の出番を均等化するため、イベント条件に「未使用の仲間を優先」「絆が低い仲間の補助イベント」を組み込む。

### 5.3 関係性の扱い

友情値を単一の好感度にせず、次の3軸で持つ。

| 軸 | 意味 | 変化する行動 |
|---|---|---|
| 信頼 | 危険な場面で任せられるか | 約束を守る、真実を伝える |
| 共鳴 | 好きなテーマや価値観の一致 | 一緒に調査、学習問題を解く |
| 摩擦 | 価値観の衝突や未解決の問題 | 隠す、急ぐ、独断で決める |

エンディングでは、信頼だけでなく共鳴と摩擦の履歴を参照する。これにより、単なる「高ければ良い」ではない人間関係を作る。

## 6. アイテムと収集システム

### 6.1 アイテムのカテゴリ

初期目標は、通常アイテム60種、仲間装備30種、キーアイテム40種、消耗品30種、隠しアイテム20種の計180種とする。

| カテゴリ | 例 | 用途 |
|---|---|---|
| 学用品 | 書き込みノート、予備電池、定規、方位磁針 | 調査・探索の成功率を補助 |
| 共有アイテム | 救急セット、軽食、工具箱、録音機 | パーティー全体の回復・解錠 |
| 仲間装備 | カードスリーブ、将棋盤、ホイッスル、古い鍵 | 仲間ごとの能力とイベントを強化 |
| 知識アイテム | 年表、用語カード、観察記録、実験データ | 問題チャレンジや暗号のヒント |
| キーアイテム | 校章の欠片、時計塔の歯車、放送室テープ | ルートとエンディングを解放 |
| 消耗品 | 集中ドリンク、絆のお菓子、ライト、絆創膏 | 1イベントの判定・疲労・戦闘を補助 |
| 謎の品 | 破れたカード、裏返しの駒、眠る牌 | 複数章をまたぐ隠しフラグ |

### 6.2 アイテムの設計ルール

- すべてのキーアイテムは、少なくとも2つの場所で意味を持たせる。
- 「持っているだけで正解」にはせず、使うタイミングにリスクを置く。
- 同じアイテムでも、仲間や時間帯によって説明文と効果が変化する。
- アイテム説明に、学習につながる短い豆知識を添える。
- アイテム図鑑では、未発見のシルエットと発見ログを表示する。

### 6.3 収集と周回

- 1周で全アイテムを取得できない。
- クリア後は「記憶のしおり」として、発見した地点・人物・知識タグを次周へ引き継ぐ。
- 引き継ぎは強さを直接インフレさせず、新しい会話・ショートカット・安全ルートを開く形式を優先する。

## 7. 戦闘・危険イベント

### 7.1 戦闘の基本方針

戦闘は本編のカードバトルや既存ミニゲームと同一化せず、TRPGの「準備」「判定」「仲間の役割」「環境利用」を中心にする。ただし視覚的には既存のカード、敵、背景、エフェクトを活用し、ゲーム全体の統一感を出す。

1戦闘は次の3段階で構成する。

1. **状況確認**: 敵の意図、環境、逃走条件、学習タグを表示
2. **行動選択**: 攻撃、守る、調べる、説得、道具、仲間アビリティ
3. **解決**: ダイス、知識ボーナス、アイテム効果、敵反応、演出

### 7.2 戦闘タイプ

| タイプ | 目的 | 代表イベント |
|---|---|---|
| 直接戦闘 | 敵の脅威を下げる | 旧校舎の見張り、暴走した教材 |
| 脱出戦 | 数ターン耐えて出口へ | 時計塔の崩落、校庭の追跡 |
| 防衛戦 | 対象を守る | 放送室、図書室の資料 |
| 調査戦 | 戦うほど情報を失う | 記憶庫の番人、偽資料 |
| 交渉戦 | 会話と知識で勝つ | 部長会議、地域資料館 |
| ボス戦 | 複数条件を満たして決着 | 章ボス、隠し章ボス |

### 7.3 既存ビジュアル素材の活用方針

実装時は、素材を直接ベタ書きせず、用途をアセットレジストリに登録する。

| 素材群 | TRPGでの用途 |
|---|---|
| `public/sprites/backgrounds/learning-rogue/` | 学園、図書室、体育館、屋上、理科室、イベント背景 |
| `public/sprites/backgrounds/mini-games/` | 部室、ボードゲーム区画、異界ルートの舞台 |
| `public/sprites/backgrounds/mini-games/foreground/` | キャラクター前景、シーン開始・終了のカットイン |
| `public/sprites/backgrounds/mini-games/badges/` | 地点アイコン、仲間章、イベント種別アイコン |
| `CARDS_LIBRARY` / `cardIllustrationManifest` | 道具、敵の記憶、戦闘アクション、報酬カード |
| 放課後ポーカーのライバル画像 | 交渉相手、部室イベント、章ボスの側近 |
| 将棋の駒アイコン・駒画像 | 戦術イベント、封鎖マス、敵の行動予告 |
| TCGのカードアート | 敵の意図、学習スキル、仲間の必殺演出 |
| 囲碁・チェス・麻雀の盤面素材 | パズル地点、知識判定、戦闘フィールドの装飾 |
| ダンジョン／校庭サバイバー／紙飛行機素材 | 危険地域、追跡戦、移動イベント |

素材を再利用する際は、次の変換だけを許可する。

- 色調、明度、トリミング、レイヤー合成
- 既存のカードアートをフレームに収める
- 既存アイコンをマップノード用に縮小する
- 既存の敵・背景を複数レイヤーで構成する

新規画像が必要な場合は、プロジェクトの画像生成ルールに従いImageGenで作成し、出典と用途をマニフェストに記録する。

### 7.4 戦闘報酬

勝利だけでなく、次の成果を別々に評価する。

- 危険度を下げた
- 仲間を無傷で守った
- 敵の正体を調べた
- 学習タグを解放した
- アイテムを温存した
- 逃走して別ルートを開いた

これにより、戦闘を避けるプレイにも明確な価値を持たせる。

## 8. イベントシステム

### 8.1 イベントの基本構造

すべてのイベントは、次のデータで定義する。

```ts
type SchoolTrpgEvent = {
  id: string;
  zone: string;
  location: string;
  phase: 'DAY' | 'AFTER_SCHOOL' | 'NIGHT' | 'DREAM';
  tags: string[];
  prerequisites?: Condition[];
  actors?: string[];
  setup: LocalCopy;
  choices: EventChoice[];
  onEnter?: Effect[];
  onResolve?: Effect[];
  revisit?: RevisitPolicy;
};
```

### 8.2 イベントタイプ

- **発見**: 新しい地点、アイテム、地図断片を見つける
- **会話**: 仲間・ライバル・先生・地域人物と関係を変える
- **調査**: 複数の資料を照合し、知識タグを使って真相へ進む
- **問題チャレンジ**: 3問の小さな学習セットで扉・暗号・交渉を解く
- **戦闘**: 敵の意図と環境を見ながら行動する
- **交換**: アイテム、カード、知識、時間を別の価値へ変換する
- **休息**: 疲労を回復する代わりに時間やイベント機会を消費する
- **再訪**: 過去の選択によって台詞、報酬、危険が変わる
- **記憶**: 前周の発見が現周の会話を変える

### 8.3 イベントの連鎖

1つのイベントで完結させず、以下のような3段階以上の連鎖を標準にする。

```text
校庭で破れたカードを発見
  → TCG部でカードの来歴を聞く
  → 図書室で関連する記録を調査
  → 旧校舎でカードの持ち主と対決
  → エンディング条件「記憶を返す／利用する」が確定
```

## 9. 学習要素の統合

### 9.1 問題を物語の中に置く

既存の「ミッション後3問」を維持しつつ、長編版では以下の場面にも問題を組み込む。

| 場面 | 問題の役割 | 失敗時の扱い |
|---|---|---|
| 暗号・資料 | 読解、漢字、英語、一般知識 | 時間消費、別の手がかり、追加ルート |
| 戦闘準備 | 敵の特徴、科学、数学、地理 | 初期状態が不利になるが続行可能 |
| 仲間イベント | 趣味・専門分野の確認 | 信頼は下がらず、別の会話へ |
| 章クリア | 3問のミッションゲート | 正解報酬、誤答は補習ルート |
| 隠しイベント | 高難度・複数教科 | 隠しエンディング条件の判定 |

問題の不正解で物語を強制終了させない。正解はショートカット、情報、装備、絆などを得る機会として扱う。

### 9.2 問題タグ

イベントごとに、`subjectTags` と `difficultyBand` を設定する。問題は既存の問題バンクから選び、TRPG専用の説明文とヒントを添える。

- `TRPG_RULES`
- `READING`
- `SCIENCE`
- `MATH`
- `ENGLISH`
- `HISTORY`
- `GEOGRAPHY`
- `MEDIA_LITERACY`
- `ETHICS`
- `GENERAL_TRIVIA`

### 9.3 学習成果の可視化

クリア後に「今回使った知識」を、正解率だけでなく次の観点で表示する。

- どの場所で使ったか
- どの仲間の助けになったか
- どの分岐を開いたか
- 次回に再利用できる知識タグ

## 10. マルチエンディング設計

### 10.1 エンディングの目標数

初回の完成版では、最低36種類を用意する。

- 通常エンディング: 12
- 仲間個別エンディング: 8
- ルートエンディング: 6
- 失敗・逃走・時間切れエンディング: 4
- 隠しエンディング: 4
- 完全収集エンディング: 2

将来的には、同じタイトルでも本文・後日談・獲得称号・次周への引き継ぎが変わる「差分エンディング」を含め、60以上の結果を目標にする。

### 10.2 分岐軸

エンディング判定は、単一の善悪値にしない。

| フラグ軸 | 例 |
|---|---|
| 謎の理解度 | 校章の正体、時計塔の目的を把握したか |
| 仲間の信頼 | 約束、救助、秘密の共有 |
| 知識タグ | 科学、歴史、読解、英語などの解放 |
| 学園評判 | 先生、部活、地域、ライバルからの評価 |
| 時間 | 放課後、夜、期限、章ボス到達時刻 |
| アイテム | 特定の鍵、記録、カード、駒、テープ |
| 戦闘方針 | 撃破、説得、逃走、無傷、防衛成功 |
| 再訪記憶 | 前周で何を発見し、何を見逃したか |

### 10.3 エンディング例

- **探偵団の始業式**: 3手がかり以上、仲間3人以上の信頼が高い
- **校章を返す日**: 校章の欠片をすべて回収し、独占しない
- **記憶庫の司書**: 資料の信頼性を検証し、偽記録を公開する
- **競技祭の平和**: 防衛戦で全員を守り、競争を協力に変える
- **時計塔の選択**: 時間を巻き戻す力を使わず、現在を受け入れる
- **部室連合**: 3つ以上のミニゲーム部と協力協定を結ぶ
- **一人だけの勝利**: 仲間を犠牲にして最短ルートを選ぶ
- **静かな帰宅**: 事件を解決できなくても、仲間との絆を守る
- **夢の校庭**: 異界ルートで、カード世界の記憶を統合する
- **もう一人の放課後**: 全章の隠しフラグと再訪イベントを回収する

## 11. セーブ、周回、引き継ぎ

### 11.1 セーブ構造

現行の短編状態と分離し、バージョン付きのキャンペーンセーブにする。

```ts
type SchoolTrpgCampaignSave = {
  version: 1;
  seed: number;
  chapter: number;
  currentZone: string;
  currentLocation: string;
  time: number;
  party: string[];
  stats: Record<TrpgStat, number>;
  bonds: Record<string, BondState>;
  inventory: string[];
  knowledgeTags: string[];
  discoveredEvents: string[];
  flags: Record<string, boolean | number | string>;
  endings: string[];
  log: DiscoveryLogEntry[];
};
```

### 11.2 中断と再開

- イベント選択前、イベント解決後、章終了時に自動セーブする。
- 戦闘中はターン開始時にスナップショットを保存する。
- 画面を閉じても、最後の安全地点から再開できる。
- 旧 `SchoolTrpgGame` のセーブが存在する場合は、5シーンの結果を新キャンペーンの導入フラグへ変換する。

## 12. 技術アーキテクチャ

### 12.1 ファイル分割案

長編化に伴い、`TriviaMiniGameScreen.tsx` からTRPG固有ロジックを分離する。

```text
src/mini-games/school-trpg/
  SchoolTrpgGame.tsx          # 画面・入力・レスポンシブUI
  schoolTrpgEngine.ts          # 状態遷移、判定、戦闘、効果
  schoolTrpgWorld.ts           # ゾーン、地点、接続、時間帯
  schoolTrpgEvents.ts          # イベント定義と分岐条件
  schoolTrpgCharacters.ts      # 仲間、ライバル、関係性
  schoolTrpgItems.ts           # アイテム、装備、キーアイテム
  schoolTrpgEndings.ts         # エンディング条件と後日談
  schoolTrpgQuestions.ts       # イベントと問題タグの接続
  schoolTrpgAssets.ts          # 既存素材の用途レジストリ
  schoolTrpgSave.ts            # バージョン付きセーブと移行
  schoolTrpgTranslations.ts    # 日本語・ひらがな・英語の専用文
```

### 12.2 状態遷移

UIの表示条件を個別のbooleanに増やさず、状態機械を使う。

```text
TITLE
  → CAMPAIGN_SELECT
  → PARTY_SELECT
  → WORLD_MAP
  → LOCATION_BRIEF
  → EVENT
  → CHECK / QUESTION
  → COMBAT
  → REWARD
  → DISCOVERY_LOG
  → WORLD_MAP
  → CHAPTER_END
  → ENDING
```

モーダル（ルール、図鑑、アイテム詳細）は、この状態機械の上に重ねる表示状態として分離する。

### 12.3 決定性と再現性

- キャンペーン開始時にseedを生成する。
- 乱数はエンジンの一箇所から取得し、UIの再レンダーで結果が変わらないようにする。
- イベント選択、敵行動、報酬候補をseedから再現できるようにする。
- デバッグ時はseed、現在地点、主要フラグ、次イベントを表示できるようにする。

## 13. UI／演出方針

### 13.1 マップ画面

- 横画面: 左60%を地図、右40%を地点情報・パーティー・行動にする。
- 縦画面: 地図を上、詳細を下へ積む。
- 目的地の危険度を色ではなく、アイコン＋短文＋数値で伝える。
- 未発見地点は暗いシルエット、発見済み地点は素材バッジ、再訪可能地点は脈動表示にする。

### 13.2 イベント画面

- 背景、前景キャラクター、イベントカード、選択肢をレイヤー化する。
- 選択肢に「必要タグ」「消費時間」「危険度」「得られる可能性」を表示する。
- 長文はログに送り、現在の選択に必要な要約を先に表示する。
- 選択直後に、変化したフラグ・アイテム・仲間の反応を短く表示する。

### 13.3 戦闘画面

- 敵の意図を上部、仲間を左、行動カードと道具を下、環境情報を右に配置。
- アタック、守る、調べる、説得、逃走を色とアイコンで統一する。
- 攻撃時は既存TCGカードアート、駒・盤面素材、効果音、画面揺れを組み合わせる。
- 視覚効果に依存せず、ログでも「誰が何をして何が変わったか」を読めるようにする。

### 13.4 BGM・効果音

- 探索、危険、戦闘、発見、仲間イベント、章ボス、エンディングでBGMスナップショットを切り替える。
- 既存の放課後ポーカー／本編戦闘BGMとの役割を整理し、同じ曲を無秩序に重ねない。
- 音量を下げても、画面のフラッシュ・ログ・アイコンで状態が分かるようにする。

## 14. 翻訳・表記

- 駒名、カード名、固有アイテム名は英語化・ひらがな化の対象外にするか、専用辞書で管理する。
- アイテム説明、イベント本文、戦闘ログ、エンディングは日本語・ひらがな・英語の3言語を用意する。
- 固有名詞の翻訳と説明文の翻訳を分離する。
- `englishMinigameExact.ts`、`hiraganaRuntimeExact.ts` と同じ監査ルートへ登録する。
- 画面に収まらない長文は、短縮表示と詳細ログ表示を分ける。

## 15. 制作フェーズ

### Phase 0: 監査と基盤整理

- 現行5シーンを新エンジンへ移植できるデータ形式にする。
- 既存画像、カード、敵、BGM、効果音を棚卸しする。
- セーブキーと問題チャレンジ接続を確定する。
- マップとイベントのデータスキーマを確定する。

### Phase 1: 探索キャンペーンの最小版

- 中央校舎、知識区、部室棟の3ゾーン。
- 地点15、イベント30、アイテム45、仲間6。
- 章1〜2、通常エンディング4、失敗エンディング2。
- マップ、再訪、基本アイテム、3問学習ゲートを実装する。

### Phase 2: 戦闘と既存素材連携

- 直接戦闘、脱出戦、防衛戦、交渉戦の4タイプ。
- 既存TCGカードアート、将棋駒、ミニゲーム背景をアセットレジストリ経由で表示する。
- 戦闘ログ、敵意図、状態効果、逃走、環境効果を実装する。
- 戦闘後の報酬とアイテム合成を実装する。

### Phase 3: マルチエンディングと仲間個別章

- 全仲間の個別目的、絆イベント、離脱・成長分岐。
- 章3〜5と異界ルート。
- 36エンディングの条件表と自動検証。
- エンディング後の図鑑・称号・次周引き継ぎ。

### Phase 4: コンテンツ拡張と磨き込み

- アイテム180種、地点40以上、イベント120以上を目標にする。
- 既存ミニゲームの部室イベントを追加する。
- BGM、効果音、戦闘エフェクト、画面遷移、アクセシビリティを調整する。
- 横画面・縦画面、英語・ひらがな、低データモードを通しで検証する。

## 16. QAと完了条件

### 16.1 機能テスト

- すべての地点に到達できる、または理由付きで封鎖される。
- 全イベントに、前提条件・解決効果・再訪時の挙動がある。
- アイテム使用後の消費・返却・重複取得が正しい。
- 戦闘の勝利、敗北、逃走、引き分けがすべて保存される。
- 章ボスを複数の方法で解決できる。
- 36エンディングが条件表どおりに到達できる。
- 旧短編セーブから新キャンペーンへ安全に移行できる。

### 16.2 学習・翻訳テスト

- 章クリアごとに3問が必ず出題される。
- 問題の不正解で進行不能にならない。
- 問題モード、課題問題、英語、ひらがな設定がイベント内でも維持される。
- 固有のカード名・駒名・アイテム名が意図せず翻訳されない。
- `audit:english`、`audit:hiragana`、表示文言監査が通過する。

### 16.3 UI・端末テスト

- 844×390、896×414、1280×560の横画面で、マップ・イベント・戦闘の主要操作が1画面に収まる。
- 390×844、412×915の縦画面で、必要なスクロールだけが発生する。
- セーフエリア、ノッチ、ホームインジケータと操作ボタンが重ならない。
- 低データモードで画像が欠落しても、説明と操作が成立する。
- 効果音・BGMを無効にしても、状態変化が視覚的に把握できる。

### 16.4 コンテンツ品質

- 各仲間に、加入・危機・成長・結末の最低4イベントがある。
- 各キーアイテムに、取得・使用・再訪の最低3つの用途がある。
- 各ゾーンに、戦闘を避けるルートと問題解決ルートがある。
- エンディングが単なる数値の高低でなく、プレイヤーの行動履歴を反映する。

## 17. リスクと対策

| リスク | 対策 |
|---|---|
| コンテンツ量が膨らみ完成しない | Phase 1を独立して遊べる縦切りスライスにする |
| `TriviaMiniGameScreen.tsx` が肥大化する | TRPG専用ディレクトリへ早期分離する |
| 分岐の組み合わせがテスト不能になる | 条件をデータ化し、フラグ可視化とシード固定を用意する |
| 問題出題が物語を止める | 失敗しても別ルートへ進む設計にする |
| 既存素材の権利・用途が不明 | アセットレジストリと出典台帳を必須にする |
| モバイル画面で情報量が多すぎる | 要約、詳細ログ、図鑑の3層表示にする |
| 周回が作業化する | 新規イベント、再訪差分、引き継ぎショートカットを用意する |
| BGM・演出が過剰になる | reduced motion、音量設定、視覚ログを用意する |

## 18. 最初に実装する縦切りスライス

本格的な全章制作の前に、次の1ルートを完成させて設計を検証する。

1. 中央校舎から図書室へ移動する。
2. 仲間を1人選び、破れたカードを発見する。
3. 資料を調査する問題を3問解く。
4. TCG部のライバルと交渉する。
5. 旧校舎で、既存カードアートを使った記憶の番人と戦う。
6. 戦う、説得する、逃げるの3ルートを用意する。
7. アイテム「校章の欠片」を獲得する。
8. 章終了時に4種類の短いエンディング候補を判定する。
9. 発見ログと次周引き継ぎを保存する。

この縦切りで、マップ、イベント、問題、戦闘、既存アセット、セーブ、エンディング、横画面UIが一続きに動くことを確認してから、地点・仲間・アイテムを増やす。

## 19. 実装開始時の確認事項

- マルチエンディングの最終目標数を36／48／60のどこに置くか。
- 仲間を既存キャラクター中心にするか、TRPG専用キャラクターを追加するか。
- 戦闘をカード寄り、ダイス寄り、環境パズル寄りのどこに置くか。
- 章クリア以外の問題チャレンジ頻度をどこまで増やすか。
- 旧短編の5シーンを新キャンペーンの導入章として残すか、別モードにするか。
- 新規画像・音声をどこまで生成し、既存素材をどこまで再構成するか。
- キャンペーンセーブをタイトル画面から独立して管理するか。

このMDの承認後、Phase 0のアセット台帳・状態スキーマ・イベントサンプルを作成し、最初の縦切りスライスへ進む。
