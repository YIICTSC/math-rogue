# 放課後スクールTRPG 既存素材連携・UI導入・マップ補完計画

作成日: 2026-08-21
ステータス: アセット実装・UI設計（実装前）
関連計画:

- [school-trpg-open-world-multi-ending-expansion-plan.md](./school-trpg-open-world-multi-ending-expansion-plan.md)

## 1. 目的

長編化する放課後スクールTRPGで、学習ローグ本編と既存ミニゲームの画像・カード・駒・敵・背景・音声を、場面ごとに一貫したUIへ差し込むための実装計画を定める。

この文書の対象は、単に画像を表示することではない。

- どのシーンにどの素材を使うか
- 背景、前景、キャラクター、UI、エフェクトを何層に分けるか
- 既存画像がない場合に、どの種類のマップ画像を追加するか
- Web、iPhone、Android asset pack、低データモードで同じ表示を成立させる方法
- 画像の読み込み失敗、言語切り替え、縦横画面、アクセシビリティにどう対応するか

を、実装担当がそのままタスク化できる粒度まで落とし込む。

## 2. 基本方針

### 2.1 素材は「場面」ではなく「レイヤー」に割り当てる

1枚の完成画像に全情報を焼き込まず、次のレイヤーを独立して管理する。

```text
L0 背景           学園・部屋・マップのベース
L1 環境前景       机、窓、雨、煙、光、霧、ボードの装飾
L2 マップ情報     道、ノード、未発見領域、危険範囲
L3 キャラクター   仲間、NPC、ライバル、敵
L4 物語カード     イベント画像、発見物、キーアイテム
L5 戦闘情報       敵意図、HP、状態、行動順、判定情報
L6 操作UI         行動ボタン、手札、アイテム、ログ
L7 フィードバック エフェクト、ダメージ、成功、失敗、発見演出
```

同じ背景でも、L1〜L7を差し替えることで「昼の図書室」「夜の図書室」「記憶庫の図書室」を別場面として成立させる。

### 2.2 既存素材を優先し、不足部分だけを追加する

優先順位は以下とする。

1. 既存の学習ローグ本編素材をそのまま適合させる
2. 既存ミニゲームの背景・バッジ・駒・カード・敵素材を役割転用する
3. 既存素材の色調、トリミング、レイヤー合成で変種を作る
4. それでも不足するマップ、地点、前景だけをImageGenで新規生成する

新規画像を作る場合は、ImageGenを使用し、生成プロンプト、参照画像、用途、ライセンス扱い、生成日をアセット台帳に記録する。コードで画像を描き起こすことを標準にしない。

### 2.3 固有名詞と画像ファイル名を分離する

画面に表示する名前をファイル名から直接生成しない。

```ts
type TrpgAssetRef = {
  id: string;
  path: string;
  kind: 'background' | 'foreground' | 'character' | 'enemy' | 'card' | 'icon' | 'vfx';
  altKey?: string;
  languageNeutral?: boolean;
  fallback?: string;
};
```

表示文は翻訳辞書、画像はアセットレジストリで管理する。英語・ひらがなモードで、駒名・カード名・アイテム名がファイル名由来で誤変換されないようにする。

## 3. 現在利用できる仕組み

### 3.1 URL解決とAndroid asset pack

画像パスは、直接 `/public` を参照せず、`src/utils/assetPaths.ts` の `assetUrl()` を通す。

- Webでは `BASE_URL` と大容量アセットの設定を考慮する。
- Androidでは、画像系・音声系asset packのインストール状態に応じてローカルパスを解決する。
- マジック系・高校生編系の一部はバージョンパラメータを付与する。
- 追加素材も、Android配布対象になる場合は生成済みasset pack manifestに含める。

### 3.2 画像フォールバック

既存の次の仕組みを再利用する。

- `ResilientAssetImage`: 複数候補を順番に読み込み、最後にフォールバックを表示
- `EnemyIllustration`: 敵名・別名・テーマ・行動フェーズから敵画像を解決し、PixelSpriteへフォールバック
- `Card`: カードのイラスト参照、カード種別、テーマ別アートを共通表示
- `getWebpFirstAssetPaths`: PNG/JPEG指定時にWebPを優先
- `CARD_ILLUSTRATION_MANIFEST`: カード名のUnicode揺れを吸収
- `ENEMY_ILLUSTRATION_MANIFEST`: 敵名の表記揺れと画像ファイルを対応

### 3.3 読み込みルール

| 素材 | 初期読み込み | 遅延読み込み | 失敗時 |
|---|---|---|---|
| 現在地点の背景 | 必須 | なし | 共通学園背景 |
| 次地点のサムネイル | 低解像度を先行 | 本画像を遅延 | ノードの色付きプレースホルダー |
| 現在の仲間 | 必須 | 行動差分を遅延 | シルエット＋名前 |
| 現在の敵 | 必須 | 攻撃差分を遅延 | `EnemyIllustration`の既存フォールバック |
| 報酬カード | 候補3枚だけ | その他の図鑑を遅延 | `unknown-card` |
| エフェクト | 主要3種を先行 | 場面別に遅延 | CSSの簡易フラッシュ |

## 4. UIの画面構成

### 4.1 共通シェル

新しい `SchoolTrpgGame` は、現行の `GameShell` の見た目と操作規約を引き継ぎつつ、状態ごとの専用レイアウトを持つ。

```text
<SchoolTrpgShell>
  <TrpgTopBar />
  <TrpgSceneViewport>
    <TrpgBackgroundLayer />
    <TrpgForegroundLayer />
    <TrpgStateLayer />
    <TrpgContentPanel />
  </TrpgSceneViewport>
  <TrpgBottomActionBar />
  <TrpgModalLayer />
</SchoolTrpgShell>
```

トップバーには章、時間、疲労、現在地点、セーブ状態を表示する。操作ボタンは、ゲームパッドの `data-gamepad-zone` と `data-gamepad-order` を必ず付ける。

### 4.2 横画面

スマホ横画面を基本レイアウトとし、844×390を基準にする。

```text
┌────────────────────────────────────────────┐
│ 章 / 時間 / 目的 / セーブ        設定・ログ │
├──────────────────────┬─────────────────────┤
│                      │ 場面タイトル         │
│  背景＋前景＋人物     │ 要約・手がかり       │
│  マップまたは戦闘     │ 選択肢／アイテム     │
│                      │ 仲間反応・詳細ログ   │
├──────────────────────┴─────────────────────┤
│ 仲間 / 手札 / アイテム / 行動 / 終了         │
└────────────────────────────────────────────┘
```

- マップ状態: 左58%、右42%
- イベント状態: 背景60%、イベントカード40%
- 戦闘状態: 敵・環境55%、行動・情報45%
- 重要な操作は画面下部に固定し、背景の上に浮かせない。
- 画面高が短い場合は、説明文を要約し、詳細はログモーダルへ送る。

### 4.3 縦画面

```text
上部バー
背景＋地点／敵
場面要約
仲間・状態
選択肢／行動
アイテム・ログ
```

縦画面では、背景の見栄えより操作の優先順位を上げる。重要な選択肢は常に画面下部に残し、背景画像の中央に長文を置かない。

## 5. 画面状態ごとの素材差し込み方法

### 5.1 `WORLD_MAP`: マップ画面

#### レイヤー

| レイヤー | 差し込む素材 | UI処理 |
|---|---|---|
| L0 | ゾーンマップWebP | `object-fit: cover`、焦点位置を設定 |
| L1 | 道、川、校舎の前景 | 背景と別画像、暗転可能 |
| L2 | ノード、接続線、危険範囲 | DOM/SVGの操作可能レイヤー |
| L3 | 未発見・発見済みアイコン | 既存ミニゲームバッジを縮小使用 |
| L4 | 現在位置、目的地、仲間の位置 | CSSアニメーション、ARIAラベル |
| L5 | 地点詳細パネル | タイトル、消費時間、必要条件、報酬 |

#### 実装ルール

- 背景マップに文字を焼き込まない。
- ノードは画像内の座標ではなく、正規化座標（0〜1）で保存する。
- ノッチや横画面の端でノードが隠れないよう、表示領域に安全マージンを持つ。
- 未発見地点は同じ形のシルエットにし、画像の色だけで情報を伝えない。
- ロック地点には「必要アイテム」「必要知識」「再訪条件」を短文で表示する。

#### ノードデータ例

```ts
const centralCampusMap = {
  id: 'map.central-campus',
  asset: 'trpg-map-central-campus',
  nodes: [
    {
      id: 'central-classroom',
      x: 0.28,
      y: 0.38,
      icon: 'badge-school-trpg',
      state: 'DISCOVERED',
      eventIds: ['P0-01', 'C1-01'],
    },
  ],
};
```

### 5.2 `LOCATION_BRIEF`: 地点到着画面

到着直後の2〜4秒の情報提示。マップからイベントへ切り替わる間に、プレイヤーが「どこへ来たか」「何が変わるか」を理解する。

- 背景: 地点の通常背景
- 前景: 地点固有の小さな環境素材
- 中央: 地点名、時間帯、危険度
- 右: その地点で可能な行動
- 下: パーティーと持ち物の簡易表示

背景はフェード、前景は短いスライド、地点バッジはスケールインで表示する。演出を切った場合でも、地点名と目的は即時に表示する。

### 5.3 `EVENT`: イベント画面

#### 標準レイヤー

```text
L0 背景画像
L1 環境前景（窓、雨、机、霧など）
L2 登場人物（仲間／NPC／ライバル）
L3 イベントカード（タイトル、要約、手がかり）
L4 選択肢パネル
L5 反応バブル、報酬、ログ
```

#### UI導入手順

1. `event.backgroundAsset` を `assetUrl()` で解決する。
2. `event.foregroundAssets` を `ResilientAssetImage` で重ねる。
3. `actors` を `EnemyIllustration` または仲間用共通コンポーネントで表示する。
4. 選択肢を `EventChoiceCard` に変換し、必要条件と費用を付ける。
5. 選択後は画像の差し替えではなく、L5の反応レイヤーを追加する。
6. 結果ログを保存し、再訪時に差分イベントを選ぶ。

#### 選択肢カードの表示項目

- 行動名
- 使う能力
- 必要な知識タグ
- 必要アイテム
- 消費時間
- 危険度
- 成功時に得られる可能性
- 失敗時に失う可能性
- 仲間の得意反応アイコン

### 5.4 `CHECK` / `QUESTION`: 判定・問題画面

- 背景と前景は暗くし、問題パネルの視認性を優先する。
- ダイス判定では、使用能力、修正値、必要値、結果を1列に置く。
- 問題では、問題文、選択肢、ヒント、学習タグを表示する。
- 問題の正解・不正解は、背景の色変化だけでなく、アイコン、短文、効果音で伝える。
- 3問ゲート時は、進捗 `1/3` と物語上の目的を常に表示する。

### 5.5 `COMBAT`: 戦闘画面

#### 横画面レイアウト

```text
┌──────────────────────────┬───────────────────┐
│ 敵背景＋前景              │ 敵情報             │
│ 敵スプライト／敵意図      │ HP / 状態 / 目的   │
│ 環境危険                  │ ターンログ         │
├──────────────────────────┼───────────────────┤
│ 仲間ポートレート＋状態    │ 選択中行動の詳細   │
├──────────────────────────┴───────────────────┤
│ 行動カード / アイテム / 逃走 / 終了             │
└───────────────────────────────────────────────┘
```

#### 敵画像の差し込み

- 名前、別名、敵タイプ、フェーズ、行動を `EnemyIllustration` に渡す。
- 攻撃・スキル・アイドルで画像がある場合は、行動開始時だけ差し替える。
- 画像がない敵は、敵名に対応する既存マニフェストを探し、なければPixelSpriteへフォールバックする。
- 敵画像の上にHPや意図を焼き込まない。UIレイヤーで表示する。
- 敵のフェーズ変更時は、背景の色調、前景、敵意図、ログを同時に更新する。

#### カード画像の差し込み

- 本編カードをそのまま効果データに流用せず、`trpgActionId` と `sourceCardId` を分離する。
- `Card` コンポーネントに表示用カードを渡す場合、TRPG固有のコスト・判定補正は外部の行動定義から渡す。
- カードアートがない場合は `unknown-card` へフォールバックする。
- カードを大きく見せる場面では、カード詳細モーダルを開き、戦闘画面の盤面を狭めない。

#### 戦闘エフェクト

既存 `audioService.playSound()` と戦闘エフェクトの対応を共通化する。

| 行動 | 画面 | 効果音 |
|---|---|---|
| 攻撃 | 対象を短く発光、ダメージ数 | `attack` または `damage` |
| 防御 | 仲間の前にシールド | `block` |
| 強化 | 仲間の周囲に上昇粒子 | `buff` |
| 弱体 | 敵の周囲に紫／赤の輪 | `debuff` |
| 重要発見 | アイテムカードが浮上 | `correct` または専用音 |
| 逃走 | 背景を横方向に流す | `jump` |
| ボス撃破 | 全画面の短いフラッシュ | `finisher_explosion` |

音声が無効でも、エフェクト、ログ、状態アイコンの3つで意味が伝わるようにする。

### 5.6 `REWARD`: 報酬画面

- 報酬候補は3枚まで表示し、カードアートを大きく使う。
- アイテム、知識タグ、仲間の絆、地図解禁を種類別に色分けする。
- 報酬の取得前に「次のどの場面で使えるか」を1行で表示する。
- 取得後はカードを図鑑に登録し、発見ログへ記録する。
- 3問ゲートがある場合は、問題完了後に報酬画面へ戻る。報酬候補を再抽選しない。

### 5.7 `DISCOVERY_LOG`: 発見ログ

Sleeping Gods風の再訪感を、発見番号だけに依存せず、ログと差分画像で実現する。

- 発見したイベントID
- 発見地点
- 発見時の仲間
- 使用したアイテム
- 選択結果
- 再訪時に変わる要素
- 関連する知識タグ
- 未回収の手がかり

ログのサムネイルは、場面背景の切り抜きまたは既存カードアートを使用する。新しい画像を増やしすぎず、既存素材の組み合わせで一覧を作る。

## 7. 足りないマップ画像の補完計画

### 7.1 現状の不足

既存アセットには、本編の校舎・戦闘・イベント背景と、各ミニゲーム固有の背景はある。一方、長編TRPGに必要な以下は専用マップとして不足している。

- 複数地点をつなぐ俯瞰マップ
- 地図上の未発見領域と発見済み領域の差分
- 時計塔内部を階層で見せるマップ
- 部室棟を一枚で見渡すマップ
- 記憶庫・異界回廊の抽象的な移動マップ
- 地点ノードへ重ねる道路、矢印、危険範囲、封鎖表示

### 7.3 マップ画像の生成仕様

新規マップ画像はImageGenで作成する。各マップは、背景1枚ではなく、次の3種類を同じ構図で用意する。

1. **Base**: 文字、ノード、道標を含まない背景
2. **Fog／Unvisited**: 未発見領域を暗く覆う差分
3. **Hazard／Event overlay**: 危険区域、章ボス、期間限定地点の差分

プロンプト共通条件:

- 学習ローグのダークな学園ファンタジー調
- 既存本編背景と同じ遠近感、光源、色温度
- UI文字、ロゴ、ボタン、固有名詞を画像内に描かない
- ノードを置く場所に十分な余白を残す
- 横画面と縦画面の両方で主要建物が切れない構図
- 画像の端に重要な手がかりを置かない

### 7.4 ImageGenの作業単位

1. 既存背景を参照画像として確認する。
2. ゾーンの目的、主要建物、光源、時間帯をプロンプトに記載する。
3. Baseを生成する。
4. 同じ構図を参照してFog差分を生成する。
5. 同じ構図を参照してHazard差分を生成する。
6. 2560×1440、2048×1536の実寸で文字・ノードなしを確認する。
7. `schoolTrpgAssets.ts` とアセット台帳に登録する。
8. Web、iPhone、Android asset packで読み込み確認する。

### 7.5 不足している小物画像

マップ画像と同時に、次の小物を追加する。

- 未発見ノード、発見済みノード、再訪ノード、危険ノード、封鎖ノード
- 校章の欠片、地図断片、時計の歯車、放送テープ、空白カード、裏返しの駒、眠る牌
- 目的地ピン、現在位置ピン、仲間位置ピン、章ボスピン
- 道の分岐、通行止め、時間制限、必要知識、必要アイテムのアイコン

既存のミニゲームバッジを第一候補として使い、専用の新規アイコンが必要な場合はImageGenで透明背景の単体アイコンを生成する。スプライトシートにまとめる場合は、等間隔・枠線なし・広い余白・クロマキー処理用背景の要件を守る。

## 8. イベント画像が不足する場合の補完

### 8.1 追加イベント画像の優先順位

1. 章ボス、章開始、章終了、主要仲間の危機
2. マップの初回到着と隠し章の入口
3. キーアイテム取得、重要な再訪、エンディング差分
4. 小イベントのサムネイル

小イベントは、背景＋既存人物＋カード／アイテムを合成して対応し、イベントごとに新規イラストを必須にしない。

### 8.2 新規イベント画像の仕様

| 種類 | 比率 | 用途 |
|---|---:|---|
| Scene key art | 16:9 | 章開始、章ボス、エンディング |
| Event card art | 4:3 | 発見、会話、調査 |
| Character portrait | 1:1 | 仲間の表情差分 |
| Item cutout | 1:1 | 報酬、発見、図鑑 |
| Battle foreground | 16:9 | 敵の前景、環境危険 |

新規画像には文字を入れず、タイトル・台詞・効果はDOM/UIで表示する。

### 9.2 IDの命名規則

- `map.<zone>`: 地図
- `scene.<sceneId>.background`: 場面背景
- `scene.<sceneId>.foreground.<name>`: 場面前景
- `event.<eventId>.actor.<actorId>`: イベント人物
- `encounter.<encounterId>.enemy.<enemyId>`: 戦闘敵
- `item.<itemId>`: アイテム
- `vfx.<effectId>`: エフェクト
- `ui.<component>.<variant>`: UI専用素材

### 9.3 監査項目

- パスが実在するか
- WebP優先候補があるか
- Android asset packの分類が正しいか
- alt文が翻訳辞書へ登録されているか
- 画像内に翻訳が必要な文字を含まないか
- 低データモードの代替があるか
- 画像の比率がUIの表示枠と一致するか

## 10. マップUIの実装方法

### 10.1 コンポーネント分割

```text
src/mini-games/school-trpg/ui/
  TrpgMapScreen.tsx
  TrpgMapCanvas.tsx
  TrpgMapNode.tsx
  TrpgMapDetails.tsx
  TrpgMapLegend.tsx
  TrpgEventPanel.tsx
  TrpgCombatViewport.tsx
  TrpgCombatHud.tsx
  TrpgActionBar.tsx
  TrpgDiscoveryLog.tsx
  TrpgAssetImage.tsx
```

### 10.2 ノードの操作

- クリック、タップ、ゲームパッドのいずれでも同じ `selectNode(nodeId)` を呼ぶ。
- 選択中ノードは枠線と説明文で示す。点滅だけに頼らない。
- ロック中でも選択でき、ロック理由を表示する。
- ノードの移動先が画面端にある場合、詳細パネルを画面中央へ寄せる。
- ノードの状態更新は画像の差し替えではなく、アイコン、色、バッジ、ログで表現する。

### 10.3 イベントパネル

- 横画面では右側に固定。
- 縦画面では下部に折りたたみ可能なシートとして表示。
- 長い文章は要約→詳細ログの順にする。
- 選択肢の高さを揃え、必要条件をアイコン＋短文で示す。
- 見た目が似た選択肢には、行動タグを付けて差を明示する。

## 11. パフォーマンスと配信

### 11.1 Web

- 現在地点と次の候補地点だけを優先読み込みする。
- 地図Baseは低解像度サムネイルを先に表示し、本画像へ差し替える。
- 同じ背景を使うイベントは、キャッシュキーを共通化する。
- イベントログのサムネイルは、本画像を再生成せずCSSのobject-positionで切り抜く。

### 11.2 iPhone／Android

- 新規TRPGマップは、マップ系のvisual asset packへ分類する。
- BGM・効果音はaudio packへ分類する。
- asset pack未導入時でも、共通背景・文字・ノード操作は利用可能にする。
- 画像読み込み中は、暗転しすぎないプレースホルダーを表示する。
- 画面遷移のたびに大きな画像を全破棄せず、現在章の背景を小さなLRUキャッシュに残す。

### 11.3 低データモード

- マップBaseを軽量版へ切り替える。
- 前景アニメーション、パーティクル、攻撃差分を停止する。
- カード・駒・アイテムは静止画を維持する。
- 敵画像がない場合も、敵名、HP、意図、行動ログを表示する。

## 12. 翻訳とアクセシビリティ

### 12.1 画像のaltと説明

- 背景は装飾扱いなら `alt=""`。
- 操作対象のノード、カード、敵、アイテムは状態を含むalt文を持つ。
- 画像内の文字を読ませる設計にしない。重要情報はDOMテキストにも出す。
- 敵の意図やエフェクトは、色だけでなくアイコンとテキストで示す。

### 12.2 言語モード

- `assetId` は言語非依存にする。
- `altKey` と表示文を辞書で管理する。
- カード名、駒名、固有アイテム名は翻訳対象外または専用訳を登録する。
- ひらがなモードでは、説明文だけを専用ひらがな訳にする。
- 英語モードでは、イベント本文、選択肢、戦闘ログ、報酬説明を翻訳する。

### 12.3 視覚効果の設定

- `prefers-reduced-motion` とアプリの演出軽減設定を尊重する。
- 画面揺れ、強いフラッシュ、粒子を個別に停止できるようにする。
- 成功・失敗・危険の色を、アイコンと文言でも同時に表示する。

## 13. 音声・演出の導入

### 13.1 BGM状態

| 状態 | 推奨BGM | 切り替えタイミング |
|---|---|---|
| マップ | `map` | `WORLD_MAP`に入った時 |
| 通常イベント | `event` | `EVENT`開始時 |
| 危険イベント | `mid_boss` または専用 | 危険度が閾値を超えた時 |
| 戦闘 | `battle` | `COMBAT`開始時 |
| 章ボス | `boss` | 章ボス演出開始時 |
| 発見・報酬 | `reward` | 報酬確定時 |
| 勝利 | `victory` | 戦闘・章クリア時 |
| エンディング | `menu` または専用 | `ENDING`開始時 |

`audioService.playBGM()` と `setBgmTheme()` の呼び出しを画面コンポーネントに分散させず、TRPG状態機械の遷移フックから発火する。

### 13.2 効果音

- ボタン選択は `select`
- ダイス・問題正解は `correct`
- 不正解・条件不足は `wrong`
- 取得は `buff`
- ダメージは `damage`
- 防御は `block`
- ボス撃破は `finisher_explosion`

新規音声が必要な場合は、既存音の役割と音量を確認し、短いUI音を優先する。長いBGMやボイスは後段で追加する。

## 14. 追加マップ制作の受け入れ基準

### 14.1 画像単体

- 指定解像度と比率を満たす。
- 主要建物が横画面・縦画面の安全領域内にある。
- 画像内に文字、UI、ボタン、固有名詞を含まない。
- 既存背景と明度、彩度、光源が馴染む。
- Base、Fog、Hazardの構図が一致する。
- ImageGenの参照・プロンプト・生成日が台帳にある。

### 14.2 UI組み込み

- `assetUrl()` 経由で表示できる。
- 読み込み失敗時に代替背景が表示される。
- ノードの座標が端末比率で崩れない。
- 現在地、目的地、未発見、危険、封鎖の状態が区別できる。
- 画像を切っても、テキストと操作が成立する。
