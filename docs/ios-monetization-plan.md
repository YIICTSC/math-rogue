# iOS課金方針（検討案）

更新日: 2026-07-22

## 結論

初版はアプリ内課金ではなく、有料アプリとして販売する。

- Web版は無料で、現在の1日あたりプレイ時間制限を維持する。
- Steam／iOS／Android版は各ストアで有料販売し、1日のプレイ時間制限を撤廃する。
- 初版ではゲーム内通貨、スタミナ、ランダム報酬、サブスク、広告を導入しない。
- 各ストアの購入権は別々に扱い、1ストアの購入で他ストアを解放するクロスバイは行わない。

## この方針にする理由

- Web版が体験版・導入版となり、有料版の価値を「時間制限なし」で明確に説明できる。
- アプリ内購入画面や子どもの誤購入につながるゲーム内課金導線を持たずに済む。
- 購入、返金、ファミリー共有等の配布管理を各ストアへ任せられる。
- 現時点で毎月更新される価値が明確でないため、サブスクより買い切りが内容に合う。

## Apple要件として設計へ入れること

- アプリ内のデジタル機能・コンテンツ解除にはIn-App Purchaseを使う。
- 復元可能な購入には「購入を復元」を用意する。
- 有料ランダム報酬を導入する場合は提供割合の事前表示が必要になるため、初版では採用しない。
- Kids Categoryを選択する場合、購入導線や外部リンクは保護者向けゲートの内側へ置く。
- Kids Categoryでは第三者広告・第三者分析・子どもの識別情報送信に強い制約がある。
- App Store Connectの年齢評価では、ポーカー等の疑似ギャンブル表現を正確に申告する。

## 初版の商品構成

| 配布先 | 価格モデル | 1日の制限時間 |
| --- | --- | --- |
| Web | 無料 | あり（現行の基本1時間＋学習達成ボーナス） |
| Steam | 有料アプリ | なし |
| iOS | 有料アプリ | なし |
| Android | 有料アプリ | なし |

iOS初版ではIn-App Purchase商品を作成しない。正式Bundle ID確定後、App Store Connectで
アプリ本体の価格を設定する。

### 将来候補

| 商品 | 種類 | 導入条件 |
| --- | --- | --- |
| 学習プラス | 自動更新サブスク | 定期問題追加、複数端末同期、継続レポートを提供できる |
| 学校・家庭向け機能 | 別途設計 | 購入者、児童アカウント、学校契約の権限を分離できる |

## 実装順序

1. 正式Bundle ID、Android package、Steam App IDを確定する。
2. 対象年齢とKids Category参加有無を確定する。
3. 同一ソースからWeb制限版／各ストア無制限版を再現可能にビルドする。
4. SteamとAndroidには必要に応じてストア所有権検証を追加する。
5. App Store Connect、Google Play Console、Steamworksで本体価格を設定する。
6. 同一ゲームバージョンで3ストア同時リリース候補を作成する。
