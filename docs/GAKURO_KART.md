# 学ロカート / GAKURO APEX

旧カートの疑似3D・学習ピットストップ・最高速度クイズ・90秒距離競争は廃止。WebGLの立体コースを3周するアーケードレースへ全面改修した。タイトルのデバッグモード専用入口（1A1D列の下、RPGオンラインと並ぶ位置）は維持する。本編/RPGのセーブとは独立している。

## レース

- NEON CAMPUS（夜のキャンパス）、CLOUD GARDEN（雲上の庭園）、SOLAR WORKS（夕景の実験都市）の3コース。道路・ガードレール・ジャンプ台・建物・車体を立体描画。コース形状と高低差も異なる。
- オート加速、通常約209km/h。加速中は約292km/h、スリップストリームを重ねるとさらに速くなる。コース外と壁への接触は減速。直線ではハンドルを離して直進できる。
- カーブで操舵しながらドリフトを保持。0.6/1.1/1.7秒のチャージで、解放時に0.65/1.25/2秒のターボ。直線での蛇行だけではチャージしない。
- 前方5〜35m・横方向2.4m以内の車を追うとスリップストリームがたまり、0.7秒以上で最高速度+8m/s。
- 光る加速パネル、ジャンプ台、アイテムクリスタルを配置。ジャンプは着地後まで加速が続く。アイテムは各車がコース上で取得し、1個だけ保持する。
- NITRO：2.8秒ターボ。AEGIS：6秒間パルス無効、使用時に減速を解除。PULSE：85m以内の前方最大3台を1.3秒減速。COMEBACK：4.5秒ターボ+防御。後方ほどCOMEBACKを引きやすい。
- 40台でも渋滞で停止しないよう、接触は軽く横に押し合う。アイテムによる停止・長時間の操作不能はない。
- 3周のゴール時刻で順位を確定。最初のゴール後25秒で締め切り。最大4分で終了し、未完走者は走行距離順のDNF。結果画面にタイム、ドリフト加速回数、追い抜き回数を表示。
- ソロでもCPUで最大40台。オンラインではホストがCPUによる空き枠補充を選択できる。パイロットは見た目のみの違いで性能差なし。

## オンライン40人

- 6文字コードでホスト1人+参加者39人。待機中のみ参加可能。41人目と開始後の参加は拒否する。旧カートと接続先を分けたプロトコルv2。
- ホストが60Hz固定刻みで全車を計算し、クライアントは20Hzで入力のみ送信する。速度・位置・アイテム獲得・ゴールの自己申告は受け付けない。
- 状態配信10Hz。1台32バイト+ヘッダー32バイト、40台で1,312バイト。名前等は名簿変更時だけ送信。40人時のホスト送信量の目安は約512KB/秒（WebRTC等のオーバーヘッドを除く）。描画はフレーム単位の補間と最大150msの予測で滑らかにする。
- 遅い相手には古いスナップショットをためず送信をスキップ。入力レート制限、形式/数値の検証、版違い・古い/破損パケットの拒否を実施。
- 待機中の退出は枠を解放。走行中の参加者切断はCPUが引き継ぐ。ホスト退出/12秒以上の配信途絶時は終了を通知。ホスト移譲と途中再接続は未実装。結果画面の再スタートは全参加者とCPUのグリッドを組み直し、同じ部屋・コースで新しい3秒のカウントダウンを始める。
- ホストのページが非表示になると全員を一時停止し、復帰すると再開する。40人運用では安定した回線のPCをホストに推奨する。
- 既存RPGと同じ `VITE_RPG_PEER_HOST / PORT / PATH / SECURE` を利用。未設定時はPeerJSの既定シグナリング/ICE設定を使用する。必要に応じ `VITE_KART_ICE_SERVERS` にJSON配列でSTUN/TURNを設定できる。VITE設定はクライアント公開情報なので長期の秘密鍵は入れない。
- 検証した40接続はローカルの実WebRTC接続。40台の実機、学校Wi-Fi、外部回線/NATをまたぐ同時運用や有料TURNの帯域は未計測。専用常駐ゲームサーバーではなくホスト方式であり、実運用の安定性はホスト性能と接続環境に依存する。

## 描画・素材

Three.jsを遅延読み込みされるカート内だけで利用。車体/タイヤ/ヘルメット/効果と大部分の背景はInstancedMeshでまとめて描画する。端末の描画が遅いと解像度を段階的に下げる。終了時にはGPU資源・音声・タイマー・接続を解放する。WebGL非対応/コンテキスト喪失時は再読込案内を表示する。

すべてのコース、車体、建築物、テクスチャ、音は独自のコードで生成。ROMの読み込み、素材抽出、同梱は行わない。
