# GAKURO VR：40人サーバー・現地調達・爆弾バトル（2026-10-14）

## 実装
- VR専用WebSocket `/vr` を既存オンラインサーバーに追加。最大40人、41人目は拒否。サーバーが進行・入力・解答・勝敗を管理し、ホスト切断時は権限を引き継ぐ。
- 問題と地形は開始時のメタデータ、通常更新は差分。協力モードの見回りを40人分重複配信しない。遅い接続は古い更新を蓄積せず、次回に完全同期する。
- バトルロイヤルは武器・アイテムを持たずに開始。現地の紫の武器箱・緑のアイテム箱を拾って装備する。未取得の武器はサーバーでも使用を拒否する。
- 爆弾バトル：放課後の中庭（中央広場）、図書室ラビリンス（本棚の通路）、体育館クロスロード（十字通路）の3マップ。人数に応じて拡張し、開始位置と脱出用の隣接マスを確保する。
- 時限爆弾、十字の炎、壊せる箱、連鎖爆発、3回被弾で脱落、最後の生存者／時間終了で勝敗確定。
- 強化アイテム：炎の長さ、リモート起爆、キック、移動速度、同時設置数。箱を壊すと出現する。
- 初期爆弾3個、所持上限12個。補充モーダルの正答1問につき1個。誤答は補充しない。同じ解答の再送は重複加算しない。解答中も対戦が進み、炎に当たる。
- 左にバーチャルスティック、右に設置・起爆・補充ボタン。移動と設置を2本指で同時操作できる。キーボードはWASD／矢印、Space設置、F起爆、B補充。
- 3D盤面・炎・爆弾・アイテムはインスタンス描画。近い12人は既存のアバターモデル、遠いプレイヤーは軽量表示。

## ローカルで確認
VRタイトル → オンラインルーム作成 → サーバー通信 → 爆弾バトル → マップと単元を選択 → 待機室で開始。対戦は2人以上で開始する。

開発時のVRサーバーは `http://<ブラウザのホスト名>:10001`。現在はこのローカルサーバーを起動済み。起動コマンド（PowerShell）：

```powershell
pnpm run server:build
$env:PORT='10001'
node server/dist/index.mjs
```

任意の接続先は `VITE_VR_SERVER_URL` で指定する。製品ビルドでは未指定なら既存の `VITE_ONLINE_SERVER_URL` を使用する。他ゲームの接続先は変更していない。Renderへのデプロイは行っていない。

## 検証
- `pnpm run test:vr-bomb`：3マップの40人開始位置、正答／誤答／再送／上限、箱と炎の遮断、連鎖、キック、強化、リモート、脱落と再戦、現地武器取得、既存協力モードの脱出後3問を確認。
- `pnpm run test:vr-server`：実際のWebSocket 40接続、41人目の拒否、同期、補充の重複防止、ホスト権限引継ぎ。通常更新のテスト時パケットは約6.5KB。
- `pnpm run test:vr-bomb-browser`：実際のサーバーとブラウザのホスト／参加者、3マップ選択、補充、爆弾同期、390pxのスマホ表示、左スティック＋右設置の同時タッチと片指だけ離した後の移動継続。画像も確認。
- 本番ビルド・英語監査・サーバービルドは成功。型チェックには既存の475件があり、新規VR関連の型エラーはない。
- 古い `scripts/test-gakurogear.mjs` は50ミッションを前提とし、現行100ミッションの防衛／スイッチ条件に未対応で `playing !== clear` となる。この作業ではソロ用 `engine.ts` を変更していない。

実際の学校の端末40台・回線での負荷は未測定。ローカル40人・入門協力モードの20更新平均は約14～21ms（測定時の他プロセス負荷によって変動）。

既存の未コミット変更と先行する観戦ラグ修正は保持。commit・push・外部デプロイは行わない。
