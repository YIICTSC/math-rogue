# 紙飛行機バトル：艦橋演出

## 編成と画面

専用タイトルから新しい航海、保存した航海の再開、遊び方へ進む。タイトル絵はImageGenで新規生成。艦長は高校編9人・マジック編17人から選択する。機体、副官、任務を設定して出撃する。旧パイロット26人は副官として扱い、固有才能・ランダム才能・呼び直し・固定・解放条件を引き継ぐ。

艦長の顔窓は戦場の自機側左上、ライバルの顔窓は敵側右上。中央の装填スロットと下部の手札・FIREは通信UIで覆わない。高さが低い横画面では顔窓を上部ステータス帯へ移し、敵パーツにも重ならないようにする。字幕は戦場の下端に一時表示する。艦長選択は縦横のスマートフォンで一覧部分だけをスクロールし、進行ボタンを残す。

ImageGenで艦長26人、ライバル4人それぞれに通常・号令・被弾・勝利の4表情（計120枚）を制作。元の主人公の顔・髪色を参照し、艦長服と専用艦橋背景を追加。被弾や危機では緊迫した表情、発砲では号令、勝利画面では笑顔に切り替える。ライバルはセレナ、カイ、リゼ、ガルドの4人がステージ順に交替する。

`assets/paper-plane/bridge-art-build.json`に生成元シート、配置、画像ハッシュを記録。生成元のPNGを保持したフォルダを指定し、`node scripts/normalize-paper-plane-bridge-art.mjs <source-directory>`で等分抽出とWebP変換を再現できる。表情の作成自体はImageGenで行い、コードはセルの抽出・サイズ統一だけを行う。

## 通信とボイス

戦艦・リアルロボット作品のジャンル表現を参考にしたオリジナル台詞。既存作品のキャラクターや固有の名台詞を複製していない。

- 艦長：各20本（出撃・接敵各2種、砲撃4種、回避・装填・被弾・危機・勝利・撤退各2種）×26人。
- 副官：各16本（配置完了2種、射撃準備4種、回避・装填・被弾・危機・勝利報告各2種）×26人。
- ライバル：各12本（接敵2種、攻撃4種、被弾・敗北・勝利各2種）×4人。
- 合計984本（既存492本＋追加492本）。日本語原文、英語字幕、ひらがな字幕を用意。

武器へ装填すると副官が準備を報告し、発砲操作で艦長の号令・敵の応答へつなぐ。装填時に報告済みなら発砲時に同じ報告を繰り返さない。未報告の時は副官の準備報告→艦長の発砲号令→敵の応答の順に、計測した音声長で通信を再生する。通信は戦闘処理から独立し、移動・装填・次の操作に待ち時間を追加しない。移動・装填の短い通信は混雑時には省略。勝利・敗北は古い通信より優先する。ミュート時も字幕を表示し、画面を離れた時やアプリ非表示時は再生と待機キューを停止する。ボイス音量はSE音量から独立。

艦長・副官IDは途中保存に含める。古い保存には艦長の既定値を割り当て、副官は保存済み固有才能から可能な限り復元する。戦闘の数値・機体構築・副官才能の効果は変更しない。

## CPU生成と検証

公式Irodori-TTSの最新main `89f9d8fbd4d51ea019867ee1197725ede1df13c5`を2026-10-23に再確認。公開Largeモデルの重み13.15GBは作業環境のRAM9.7GiB・ディスク空き約6GiBを超えるため、最新コードでCPU実行可能な公開v4.1 Small MeanFlowを使用する。読みの修正に必要なら同世代Small RectifiedFlowで対象行だけを再生成する。モデルとcodecの両方をCPU指定し、SilentCipher透かしを保持。各キャラクターの既存の架空キャラクターボイスを参照する。

`assets/paper-plane/bridge-voice-plan.json`が台本・参照音声・声の方針、`bridge-voice-build.json`が実際のrevision・モデル・CPU設定・seed・透かし・出力ハッシュ・生成時間の記録。

```sh
OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 /workspace/irodori-kocho/.venv/bin/python scripts/generate-paper-plane-voices-irodori.py --device cpu --cpu-autocast
/workspace/irodori-kocho/.venv/bin/python scripts/verify-paper-plane-voices.py --speech --resume
/workspace/irodori-kocho/.venv/bin/python scripts/verify-paper-plane-voices.py --enable
node scripts/measure-paper-plane-voice-playback.mjs
```

`scripts/finish-paper-plane-voices.py` は生成完了後の音声認識、必要な追加認識、読み指定での対象行のCPU再生成、再検査、有効化を順に実行する。大きなモデルは同時に読み込まない。ブラウザのOgg再生尺は `node scripts/measure-paper-plane-voice-playback.mjs` で全件計測し、出力SHA付きの `voice-playback-qa.json` と再生一覧へ記録する。デコード後のPCM尺とコンテナのタイムスタンプ差を掛け合いに持ち込まない。

「迂闊な」「撃ち方、始め」「左舷ブラスター用意」「回避」と敵艦長の「通さん」は `scripts/audit-paper-plane-keyphrases.py --strict` で認識結果の読みを追加確認する。全体の一致率が高くても、主要な号令や否定が崩れていれば修正する。「よーい」と「ようい」の同じ長母音は同一の発音として扱う。

生成は行単位で再開可能。破損・無音・重複・尺・参照ハッシュ・CPU指定・透かしを検査し、音声認識で本文との一致を調べる。不明瞭な行は追加認識または読みを指定した再生成で確認してから再生一覧を有効化する。音声生成と大きなビルド・認識モデルの読み込みはメモリを確認して順序を調整する。

## 音声検証の記録（初回492本）

492本すべてについてCPU生成・codec・透かし・出力ハッシュ・末尾・無音・重複・音声認識を検査。不明瞭な行だけSmall RectifiedFlowで再生成し、全件の認識一致率0.85以上、末尾の問題0件、主要台詞43箇所の読みの欠落0件を確認した。認識はWhisper Small、必要な行にはTurboもCPUで使用した。人による聴取検査ではない。

Chromium 154で全492本のメタデータ読み込みと再生尺を確認し、実音声による副官→艦長の掛け合い、準備報告の重複防止、SE音量ゼロでも独立したボイス音量、ボイス音量ゼロからの再開、ミュート、退出後の停止を確認。ブラウザエラー0件。カード集の既存104本についても独立音量・勝敗・開始・操作・停止の回帰検証を通過した。

最終の型検査・英語UI監査・Webビルド・サーバービルドは通過。Web/Androidの両アセット一覧とdistについて、新規音声492本、艦橋画像121枚、既存カード音声104本の計717ファイルの出力SHA一致を確認した。Androidの6パックと生成済みバージョン定数も一致している。

## ボイスパターンの拡張

全56人に追加492本を制作し、合計984本へ倍増。新規の出撃・砲撃では、主人公の性格や得意分野、副官の元の部活動・役割、各ライバルの口調を反映した原文・英語字幕・読みを用意した。

各イベントの初回再生位置を航海ごとに変え、その後はパターンを順番に巡回する。砲撃と準備報告は4種。準備を報告してから発砲した場合は同じパターンの号令へつなぎ、準備報告を繰り返さない。追加した勝利台詞も勝利表情へ切り替える。通信は戦闘の進行を待たせない。

公式mainと公開モデル一覧を再確認し、最新コードのrevisionに変更はなかった。CPUで動作するv4.1 Small MeanFlowを使用し、修正が必要な台詞には同世代RectifiedFlowを使用する。
