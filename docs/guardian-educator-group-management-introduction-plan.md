# 学習ローグ 保護者・教員向けグループ管理システム導入案

作成日: 2026-07-16

## 1. 目的

保護者、教員、学校管理者が、権限を与えられた児童・生徒だけについて次の操作を行える仕組みを構築する。

- 家庭、クラス、学年、学校などのグループを作成・管理する。
- 児童・生徒を安全な方法でグループへ所属させる。
- 学習ローグ内の単元または教員作成問題を課題として配信する。
- 課題の着手、達成、正答率、再挑戦、学習時間、単元別進度を確認する。
- 必要な児童へ再挑戦課題や個別課題を配信する。
- 家庭と学校で閲覧できる情報を分離する。
- Web、Steam、iOS、Androidの学習ローグから同じ仕組みを利用できるようにする。

本システムは児童を監視または順位付けするためではなく、学習状況を把握し、適切な課題と支援を届けることを目的とする。

## 2. 現在の学習ローグで活用できる機能

現在の実装には、導入の土台として利用できる機能がすでにある。

| 現在の機能 | 活用方法 | 追加が必要な点 |
|---|---|---|
| `AssignmentPayload` | 課題タイトル、単元、目標正答数、期限、ゲームモード、回答方式を表現 | サーバー管理用ID、配信対象、公開状態、版番号を追加 |
| 課題URL | サーバー導入前の簡易配信、互換用フォールバック | URLを知る人全員が同じ課題を開く方式から、受信箱方式へ移行 |
| 課題作成画面 | 標準単元、上級・英語問題、オリジナル問題、CSV/TSV取込 | 下書き保存、予約配信、対象グループ選択、再配信を追加 |
| 回答履歴 | 正誤、再出題、回答時間、単元を端末内で記録 | サーバーへは必要最小限の集計値だけを同期 |
| 提出画面・PDF | 児童本人や対面での確認 | 自動提出、教員ポータルでの一覧確認を追加 |
| `StudentProfile` | 学年、組、番号、名前を端末内で保持 | サーバー上の児童IDとは分離し、本人確認なしに信用しない |
| 課題達成カード | 達成への動機付け | サーバー配信課題でも重複なく獲得できるようにする |
| オンラインランキングAPI | 認証トークン、端末連携、オフライン再送の実績 | 管理システムとはデータ・権限・画面を分離する |

## 3. 推奨する全体方針

### 3.1 管理ポータルは公開ランキングから分離する

保護者・教員用に、公開ランキングとは別の「学習ローグ 管理ポータル」を用意する。

- 公開ランキング: 公開名と集計済みランキングだけを扱う。
- 管理ポータル: 実名を含み得る所属情報、課題、非公開の学習進度を扱う。
- 学習ローグ: 児童向けゲーム画面、課題受信、進捗同期を担当する。

初期案では、管理ポータルを別のSitesプロジェクトと別D1データベースで構築する。公開サイトの不具合や設定ミスから児童の教育データを守り、管理者専用機能を公開ランキングへ混在させないためである。

```text
保護者・教員 ── 管理ポータル（認証必須・非公開データ）
                         │
                         ├─ グループ・所属・課題DB
                         ├─ 集計済み進捗DB
                         └─ 監査ログ
                                  ▲
                                  │ 安全なAPI
                                  ▼
児童・生徒 ───── 学習ローグ（課題受信・学習・進捗同期）

一般閲覧者 ───── 公開ランキングSites（公開名・公開記録のみ）
```

### 3.2 ランキング用プロフィールと学校名簿を結合して公開しない

- ランキングの公開コードを出席番号や学校内IDとして使わない。
- 管理ポータル上の児童IDから公開ランキング名を検索できないようにする。
- 教員画面にランキング順位を標準表示しない。
- 本人が希望した場合でも、学校・クラス名と公開ランキング名を同時に公開しない。
- ランキング参加を課題提出やクラス参加の条件にしない。

## 4. 利用者と権限

### 4.1 ロール

| ロール | 主な操作 |
|---|---|
| 保護者 | 自分と正式に関連付けられた子供の進度閲覧、家庭グループの課題作成・配信 |
| 教員 | 担当クラス・担当児童の進度閲覧、課題作成・配信、提出状況確認 |
| 補助教員 | 許可されたクラスの閲覧・支援。課題配信権限は学校設定で制御 |
| 学校管理者 | 教職員、学校、学年、クラス、年度更新、監査、データ出力の管理 |
| 組織閲覧者 | 校長・管理職等の集計閲覧。個別回答は原則閲覧不可 |
| 児童・生徒 | 自分宛ての課題受信、学習、自分の進度確認、所属解除申請 |
| 運営管理者 | 障害対応と不正利用対応。通常運用で教育内容を閲覧しない |

### 4.2 権限の原則

- 1人の児童は家庭グループと複数の学校グループに所属できる。
- 保護者は自分の子供だけを閲覧できる。
- 教員は現在担当するグループだけを閲覧できる。
- 学校管理者でも、必要性がなければ個別の問題・回答内容を閲覧できない。
- 年度替わりや異動時に教員の閲覧権限を自動終了する。
- グループから外れても過去データを無期限に閲覧可能にはしない。
- 全ての閲覧、出力、権限変更、課題配信を監査ログへ記録する。

## 5. グループ構造

### 5.1 グループ種別

| 種別 | 例 | 管理者 |
|---|---|---|
| 家庭 | 石田家、家庭学習グループ | 保護者 |
| クラス | 5年2組、中学1年A組 | 担任・学校管理者 |
| 学年 | 小学5年、2026年度中学2年 | 学年主任・学校管理者 |
| 学校 | ○○小学校 | 学校管理者 |
| 任意グループ | 算数補習、英語クラブ、夏休み講座 | 許可された教員 |

学校では「学校 → 年度 → 学年 → クラス・任意グループ」の階層を持たせる。家庭グループは学校組織から独立させ、学校側が家庭内の課題や活動を閲覧できないようにする。

### 5.2 児童の参加方法

#### 家庭グループ

1. 保護者が管理ポータルへ登録する。
2. 保護者が子供用スロットを作成する。
3. ポータルが10分間・1回限りの連携コードまたはQRコードを発行する。
4. 子供が学習ローグでコードを入力する。
5. 保護者画面と子供画面の双方に、関連付け対象を表示して確定する。

#### 学校・クラス

1. 学校管理者が年度、学年、クラスを作成する。
2. CSVまたは管理画面で名簿を登録する。初期版では学校内管理番号と表示名を分ける。
3. 児童ごとの1回限りコード、またはクラス参加コードと個別確認コードを発行する。
4. 児童が学習ローグから参加する。
5. 教員側で未確認・確認済み・重複疑いを確認する。

クラスコードだけで任意の児童情報を閲覧できる設計にはしない。共有クラスコードに加え、児童ごとの秘密または教員承認を必須とする。

## 6. 成人アカウントの認証

- 成人アカウントはメール確認を必須にする。
- 学校管理者と教員には多要素認証またはパスキーを推奨し、学校管理者では必須にする。
- 学校導入では、将来Microsoft 365またはGoogle Workspace等の学校SSOへ対応できる構造にする。
- 保護者と教員の役割を同じメールアドレスで併用できるようにするが、操作時には対象組織を明示する。
- 児童にメールアドレスの登録を要求しない。
- 成人アカウントの回復操作で児童データが第三者へ渡らないよう、重要操作は再認証する。

## 7. 課題配信

### 7.1 課題で設定できる項目

- タイトル、説明、対象教科、学年、単元
- 標準問題またはオリジナル問題
- 単元ごとの目標正答数
- 選択式、タイピング式などの回答方式
- 自由冒険内での達成、課題専用モード
- 配信日時、開始日時、期限、期限後の受付可否
- 対象グループ、対象児童、除外児童
- 再挑戦条件、合格条件、最大試行回数
- ご褒美カードの有無
- 児童へのメッセージ
- 下書き、予約、公開、終了、アーカイブの状態

### 7.2 配信単位

- グループ全員への一括配信
- 複数グループへの同時配信
- 児童ごとの個別配信
- 未達成者だけへの再配信
- 苦手単元に応じた提案から教員が確認して配信

自動配信は初期版では行わない。システムが候補を提示し、成人が内容と対象を確認してから配信する。

### 7.3 オリジナル問題

現在のCSV/TSV取込と手入力を継続利用する。追加で次を行う。

- 公開前のプレビューと解答確認
- 不適切表現・個人情報らしい記述の警告
- 問題セットの版管理
- 過去の配信内容を変更せず、修正版を新しい版として発行
- 他教員との共有範囲を「自分のみ・校内・組織内」から選択
- 著作権上問題のある教材転載を防ぐ注意表示と通報導線

## 8. 児童側の体験

タイトル画面に「課題受信箱」を追加する。

- 新着、今日まで、期限間近、達成済みを分けて表示する。
- 誰から届いた課題かを「家庭」「5年2組」など児童に分かる形で表示する。
- 課題を開始すると、現在の`AssignmentPayload`へ変換して既存の課題進行を利用する。
- オフライン中も取得済み課題を実行できる。
- オンライン復帰時に、送信済みイベントIDを用いて重複なく同期する。
- 課題を達成しても同期が失敗した場合、ご褒美カードと端末内達成状態は失わない。
- 自分がどのグループへ所属し、誰が進度を閲覧できるかを確認できる。
- 不明な所属について「保護者に確認」「先生に確認」「運営へ報告」を選べる。

## 9. 学習進度の集計

### 9.1 成人画面に表示する基本指標

| 指標 | 内容 |
|---|---|
| 課題状態 | 未着手、着手中、目標達成、期限超過、提出済み |
| 正答進度 | 目標正答数に対する達成数 |
| 正答率 | 最低回答数を満たした場合だけ表示 |
| 再挑戦 | 間違えた後に正解できた数・未克服数 |
| 学習時間 | 課題中の有効操作時間を上限付きで集計 |
| 単元進度 | 単元ごとの正答数、目標、達成率 |
| 最終同期 | 端末から最後に進捗が届いた日時 |
| 連続学習 | 日単位の学習日数。過度な競争表示はしない |

### 9.2 原則送信しないデータ

- 学習ローグ全体の操作ログ
- チャットや自由記述
- 児童の位置情報
- 生IPアドレスの長期保存
- 公開ランキング名
- 端末内のカード・画像・セーブデータ全体
- 標準問題の問題文、正解文、児童の選択回答文

標準問題では`problemKey`、正誤、再挑戦状態、経過時間だけを送る。教員作成問題でも、初期版は問題IDと正誤を基本とし、児童の入力内容を保存する機能は別途の明示設定と学校方針確認なしに有効化しない。

### 9.3 ダッシュボード

#### 保護者画面

- 子供ごとの今日・今週の学習状況
- 家庭課題と学校課題の状態
- 得意・苦手単元の傾向
- 再挑戦できた内容
- 子供への応援メッセージ

#### 教員画面

- クラス全体の課題達成率
- 未着手、進行中、達成済みの人数
- 児童ごとの単元進度
- 支援が必要そうな児童の候補
- 問題別の正答率。ただし少人数では個人推測を防ぐ
- 課題の再配信、期限延長、個別目標調整

#### 学校管理画面

- 学年・クラス別の利用状況
- 教員・グループ・児童数
- 同期エラー、長期間未利用端末
- 権限変更とデータ出力の監査履歴
- データ保持期限と削除予定

学校全体画面では原則として集計値を表示し、校長や学校管理者が常時個別回答を閲覧する設計にはしない。

## 10. 推奨データモデル

### 10.1 組織・認証

| テーブル | 主な内容 |
|---|---|
| `adult_accounts` | 成人アカウント、認証状態、MFA状態 |
| `organizations` | 家庭、学校、教育団体 |
| `organization_memberships` | 成人と組織の所属・ロール・有効期限 |
| `groups` | 年度、学年、クラス、家庭、任意グループ |
| `group_managers` | グループを管理できる成人と権限 |
| `learner_accounts` | 児童の内部ID、状態。公開名とは分離 |
| `learner_group_memberships` | 児童とグループの所属、開始・終了日 |
| `guardian_links` | 保護者と児童の関係、確認状態、根拠 |
| `learner_devices` | 児童端末の認証トークン、失効状態 |
| `link_codes` | ハッシュ化した1回限り連携コードと期限 |

### 10.2 課題・進捗

| テーブル | 主な内容 |
|---|---|
| `assignment_templates` | 再利用可能な課題原案 |
| `assignments` | 配信する課題本体、版、状態、期限 |
| `assignment_units` | 対象単元と目標 |
| `assignment_custom_problems` | 教員作成問題。権限と保存期間を厳格化 |
| `assignment_targets` | 対象グループまたは対象児童 |
| `assignment_deliveries` | 児童ごとの配信・受信・開始・達成状態 |
| `learning_progress_events` | 冪等な最小進捗イベント |
| `assignment_progress_summaries` | 成人画面用の集計済み進捗 |
| `learner_unit_summaries` | 児童・単元別の集計 |
| `reward_grants` | 課題達成カードの発行・受取状態 |
| `audit_logs` | 閲覧、出力、配信、権限変更、削除操作 |
| `data_deletion_jobs` | 退会、転校、年度終了時の削除処理 |

全ての教育データ行に`organizationId`または所属範囲を持たせる。APIはクライアントから渡された組織IDを信用せず、認証済み権限から許可範囲を再計算する。

### 11.3 進捗イベント例

```json
{
  "eventId": "device-id:assignment-id:local-sequence",
  "assignmentId": "asg_...",
  "assignmentVersion": 3,
  "problemKey": "MATH_G5_FRACTION_012",
  "unitId": "MATH_GRADES:FRACTION",
  "correct": true,
  "isRetry": false,
  "elapsedMs": 24000,
  "occurredAt": "2026-07-16T01:00:00.000Z",
  "platform": "web",
  "schemaVersion": 1
}
```

問題文、正解文、選択回答文、氏名、学校名は進捗イベントへ含めない。`eventId`で再送を冪等化し、端末時計だけで期限内達成を確定せず、サーバー受信時刻と許容範囲を併用する。

## 12. セキュリティとプライバシー

### 12.1 必須対策

- 成人用と児童用の認証トークンを分ける。
- 認証トークンと連携コードは平文保存せず、照合用ハッシュを保存する。
- 連携コードは短時間・1回限りとし、試行回数を制限する。
- 管理者操作には再認証を要求する。
- 学校・家庭・クラス間のデータ分離をAPIテストで保証する。
- 一覧CSV・PDFの出力を権限化し、出力者・対象・時刻を監査記録へ残す。
- 通信中と保存時の暗号化、バックアップ、復元手順を用意する。
- 保存期間、退会・転校・卒業時の削除または匿名化手順を決める。
- 誤所属、端末紛失、教員異動、保護者アカウント侵害の対応手順を用意する。
- エラーログや分析ログへ氏名、問題文、回答内容、認証情報を出力しない。
- 本番データを開発環境へコピーしない。
- セキュリティ事故時の連絡、遮断、調査、再発防止の責任者を決める。

### 12.2 同意・説明

- 何のために、誰が、どのデータを、いつまで閲覧するかを児童にも分かる文で表示する。
- 保護者利用と学校利用では、利用主体、根拠、必要な同意・通知が異なり得るため、同じ同意画面で一括処理しない。
- 学校導入前に、学校設置者の規程、委託契約、教育情報セキュリティポリシーとの適合を確認する。
- 同意撤回や所属終了後に何が削除され、何が法令・契約上保持されるかを明記する。
- 児童のデータを広告、販売、信用評価、公開ランキング強制参加へ利用しない。

## 13. 通知

- 課題配信、期限前、達成時だけを基本通知とする。
- 夜間や休日の通知抑制時間を設定できるようにする。
- 教員へ児童の細かな操作をリアルタイム通知しない。
- 「未達成」を責める文言ではなく、「未着手」「あと○問」など事実を表示する。
- 保護者と教員が児童へ自由な個別メッセージを送る機能は初期版に含めない。
- 将来メッセージ機能を追加する場合は、記録、通報、学校方針、送信可能時間を別途設計する。

## 14. 年度更新・異動

- 学校グループには年度を必須で持たせる。
- 新年度は過去クラスを複製せず、新しいクラスと所属を作成する。
- 旧年度の教員権限は自動終了する。
- 転校・退学・卒業時に、配信停止、閲覧停止、データ出力、削除予定を順番に処理する。
- 同じ児童が翌年度に再参加しても、学校間で履歴を自動共有しない。
- 引継ぎは学校設置者の方針と明示権限がある場合だけ行う。

## 15. 障害時の動作

- 管理ポータルが停止しても、学習ローグ本体と取得済み課題は利用できる。
- 進捗は端末内キューへ保存し、オンライン復帰時に自動再送する。
- サーバー障害中でも課題達成カードを失わない。
- 同じ進捗を複数回送っても回答数・正答数を重複加算しない。
- 成人画面には「最終同期日時」を表示し、未同期を未学習と誤認させない。
- 課題の削除や期限変更は端末の既取得版を壊さず、次回同期時の扱いを明示する。

## 17. 初回リリース範囲

最初から学校全体を対象にせず、家庭グループと小規模なクラス試験導入までに絞る。

含めるもの:

- 成人認証
- 家庭または1クラスのグループ管理
- 児童端末の1回限り連携
- 標準単元・オリジナル問題の課題配信
- 課題受信箱
- 着手、達成、正答数、正答率、再挑戦、時間、単元進度
- オフライン再送
- 権限監査ログ
- 所属解除とデータ削除

初回には含めないもの:

- 学校間の児童データ共有
- AIによる無確認の自動課題配信
- 教員と児童の自由チャット
- 児童同士の進度比較・順位表
- 通知表・成績評定の自動作成
- 顔写真、位置情報、音声、健康情報の収集
- 公開ランキングプロフィールとの名寄せ

## 18. 実装前に決める事項

## 19. 完了条件

- 保護者が自分の子供以外の進度へアクセスできない。
- 教員が担当外クラスや家庭グループへアクセスできない。
- 学校管理者の権限変更とデータ出力が監査記録に残る。
- 児童は自分が所属するグループと閲覧者を確認できる。
- 課題をグループ全体または個別児童へ配信できる。
- 児童はWeb、Steam、iOS、Androidで課題を受信・達成・同期できる。
- オフラインで学習しても、復帰後に重複なく進捗が反映される。
- 管理ポータル停止中でも学習ローグ本体と取得済み課題を利用できる。
- 公開ランキングと教育データが画面、API、データベース、権限上で分離されている。
- 問題文、選択回答、実名等を送らない基本構成が自動テストで保証される。
- 所属終了、端末紛失、年度更新、退会時の権限失効と削除手順が動作する。
- 児童データの利用目的、閲覧者、保存期間を児童と成人へ説明できる。
- 学校導入前に学校設置者の規程、契約、情報セキュリティ方針との適合確認が完了している。
